## 0) 一句话结论

* **必须改代码，2 处（都在 `dsh-codebuddy-credits`）**：
  1. `useAnchoredPosition` 从 `dsh-client-ui-primitives` **删除**（连文件一起删）⇒ 我方统计弹层定位编译失败；
  2. `new LlmError(msg, code)` 的 `code` 收窄为**内置码枚举**，我方 7 处 `'PROVIDER'` 编译失败。
* **必须改样式，1 处（`dsh-theme-tone`）**：官方悬停卡材质/字色从**组件内硬编码**改成新的
  `--dsw-alias-hovercard-*` token ⇒ 我方 `--dsw-hovercard-bg` 覆盖**静默失效**（编译与运行都不报错，
  浅色轴下会变成「深底 + 深字」）。这条同时带来**收缩私有 seam 的机会**（见 §2.4）。
* **必须跟版本门**：五个活跃插件的 peer 仍精确钉 `0.2.2-rc.1`，0.2.2 宿主会把它们判为不兼容并跳过
  （`packages/boot/app-boot/src/plugin-compatibility.ts` 该文件 rc.1→rc.2 **逐字节未变**，仅
  `index.ts` / `bundle-platform.ts` 有改动）。版本线对齐到 **`0.2.2-rc.2`**。
* **文档陈旧（需 owner 许可才改）**：`AGENTS.md:373` 的「任一 client entry 非 active = 致命」前提在
  rc.2 **已不成立**（官方改成「只有 7 个必需 entry 才致命」）。规则本身（client half 不抛错）仍该保留，
  但要换依据。
* **私有 seam 可收缩（本轮新发现，见 §8）**：有 **2 条能直接退**（`sessionPersistence.locate` → 公开
  `snapshot.location`；theme-tone 悬停卡的类名后缀 → 官方 4 个 `--dsw-alias-hovercard-*`），
  **1 条能退但要改行为**（WorkspaceRegistry 私有写通道）、**2 条只能部分收缩**、**1 条仍去不掉**（轮次导航 aria-label）。
* `dsh-archive-manage` / `dsh-chat-fim` / `dsh-desk-one` **无编译级改动**（行为面见 §3）。
* **Node 门槛不变**：`engines.node = ">=24.9.0"`；vendor 全套与 rc.1 一致（`cordis 4.1.0` 起）。

## 2) 真实差量（与插件作者相关）

方法：本机 `git fetch` 到不了 `github.com:443`（超时），故 rc.2 侧取 codeload tarball，
rc.1 侧取 checkout 的 `git ls-tree`，**逐 blob（git 对象哈希）比对**得出三态，再对命中点读源码。

### 2.1 破坏性 ①：`useAnchoredPosition` 被删除（编译级）

* rc.1：`packages/client/ui-primitives/src/index.ts:41-42` 导出 `useAnchoredPosition` 与
  `AnchoredPositionOptions`；rc.2 **两条导出消失**，`src/useAnchoredPosition.ts` 整个文件删除。
* 官方迁移路径：菜单与浮层改 **CSS Anchor Positioning**（`position-anchor` / `anchor()` /
  `position-try-fallbacks`）。指南 [`docs/upgrade-guide/v0.2.2-alpha.2/css-anchored-menus/guide.md`]，
  参考实现 `packages/client/ui-chat/src/client/chat/stat-dialog.ts`（`useId()` 生成 `anchorName`）
  与 `stat-dialog.module.css`（`position-area` / `anchor(top)` / `--dsh-stat-*` 兜底布局）。
* **命中**：`dsh-codebuddy-credits` 的统计弹层是**照官方旧实现复刻**的 ——
  `src/client/statDialog.ts:9` 直接 import `useAnchoredPosition`，派生 `pos ?? MEASURE_STYLE`
  给弹层 inline 定位，调用方 `CodeBuddyCreditsStats.tsx:113`、`CodeBuddyTurnCredit.tsx:107`、
  `CreditDialog.tsx` 的 `pos` 属性一起受影响。**改法就照官方 rc.2 的同一对文件抄**（官方改了什么，
  我方镜像同步改什么）。
* 同类但**不命中**：`Menu` 的 `getAnchorRect` → `anchorRef`/`anchorPoint`（我方未用 `Menu`，
  只用 `MenuSurface`，该组件文件 rc.1→rc.2 未变）；`useAnchoredMaxHeight` 仍导出（`chat-fim` 继续可用）。

### 2.2 破坏性 ②：`LlmError` 只接受内置失败码（编译级）

* rc.2 `packages/llm/llm/src/index.ts:109`：`constructor(message, code: BuiltinLlmFailureCode, ...)`，
  其中 `BuiltinLlmFailureCode = keyof typeof LLM_FAILURE_CODES | \`HTTP_${number}\``
  （`packages/llm/llm/src/error.ts:73`）；另新增 `LlmError.fromFailure(failure, options)`（`:142`）
  用于**原样重抛外部（非内置）码**。指南 [`docs/upgrade-guide/v0.2.2-alpha.2/llm-error-builtin-codes/guide.md`]。
* **`'PROVIDER'` 不在内置码表里**（`packages/llm/llm/src/error.ts:17-70` 逐条核对）。
* **命中 7 处，全在 `dsh-codebuddy-credits`**：
  `adapter/rejection.ts:34`、`adapter/stream.ts:152`、`adapter/stream.ts:232`、`adapter.ts:243`、
  `quota.ts:53`、`quota.ts:55`、`quota.ts:59`。其余码 `UNSUPPORTED_CONTENT` / `TRANSPORT` /
  `ABORTED` / `DISCOVERY_FAILED` 都是内置码，**不受影响**。
* 语义取舍（实施时定）：rc.2 把「可重试码」变成用户可配的 **`retryableCodes` 选择集**，只有内置码
  才能被选。上游 4xx/5xx 建议走 `HTTP_<status>`（可配、可读），无状态的分类失败走 `fromFailure()`
  保留原样；**不要**为了过编译把 `'PROVIDER'` 硬塞成别的内置码（会改变用户在重试设置里能看到的分类）。
* 我方**没有**任何按 `LlmError.code` 分支的逻辑（已 grep），故码值调整只影响持久化分类与设置项。

### 2.3 行为面 ③：插件失败不再让整个 Web 起不来（影响我方文档前提）

* rc.2 `packages/client/web/src/boot-client.ts:25-33` 新增 `requiredClientEntryNames`（7 项：
  `client-modules` / `api-session-controller` / `ui-renderer` / `ui-layout` / `ui-session` /
  `ui-chat` / `ui-sidebar`）；`assertEntriesActive`（`:96`）**只有必需项未激活才抛错**，
  其余非 active 的 entry 只 `warn`（`:133`），页面照常启动。
* 我方五个插件**都不在必需集**里 ⇒ 现在 client half 抛错/停在 pending **只影响自己**。
  `AGENTS.md:373`「任一 client entry 非 active = 致命」的实测依据（0.1.7-alpha.1 的 `boot-client.ts`）
  **已过期**；规则（client half 用 `warnMissingCapabilities` 惰性停用、不抛错）**仍然正确**，只是理由要换。
* 配套：`plugin-manager` 新增 `not-running` 状态（`packages/boot/plugin-manager/src/index.ts:1128-1133`）
  并由插件页渲染（`packages/client/ui-plugin-manager/src/client/PluginManagerPage.tsx`）⇒
  自停用、被版本门跳过的插件都会显式标「未运行及原因」，不再是「看起来在跑」。

### 2.4 行为面 ④：悬停卡改走官方 token ⇒ 我方覆盖静默失效（`dsh-theme-tone`）

* rc.2 把悬停卡的**面与字**从组件内硬编码改成官方 alias token：
  * `packages/client/ui-primitives/src/HoverCard.module.css:16` → `background: var(--dsw-alias-hovercard-bg)`
    （rc.1 是 `--dsw-hovercard-bg: #2C2C2E` 的组件级字面量，**该变量在 rc.2 已无任何消费者**）；
  * `packages/client/ui-workspace/src/client/rows/Rows.module.css:420-443` → `hoverTitle/hoverPath/
    hoverTime/hoverStatus` 由 `#FFFFFF`/`#CFD3D6`/`#ADB2B8` 改为
    `--dsw-alias-hovercard-label-primary/secondary/tertiary`；
  * 新 token 定义在 `packages/client/ui-theme/src/styles/design-platform.css:226-231`（默认轴）与
    `:378-383`（`body[data-ds-dark-theme]`）——**两轴同值**（`neutral-bluish-850` + `bluish-00`），
    即官方依旧是「固定深卡」。
* 我方现状（`src/surfaces.ts:41-58`）：在 portal 锚点上写 `--dsw-hovercard-bg`，再用 CSS-module
  类名后缀（`_hoverTitle` 等）改字色。**面色的那条现在是死代码**（变量没人读），字色的后缀选择器仍命中。
* 结果是浅色轴下「官方深卡 + 我方主题字色」混搭（浅色字压深底），**必须改**。最省事也最正确的改法：
  覆盖官方 4 个 `--dsw-alias-hovercard-*` token（`bg` + `label-primary/secondary/tertiary`），
  一次覆盖**同时**解决面色与字色，且**可删掉**类名后缀选择器与 portal 锚点
  ——正好是 [`docs/private-seams.md`](private-seams.md) §C 里登记的「跟随官方类名后缀 = 静默失效风险」，
  属于该文件要求的**收缩**方向。代价：`--…-bg` 目前只被 `HoverCard` 的 `.card` 消费，
  `label-*` 被 `.card` 里的 `.copied` 与左侧栏 Workspace 悬停卡（`Rows.tsx:350,765` 用的就是
  `HoverCard`）消费，所以**全局**覆盖会让**所有**悬停卡都跟主题走（这正是 §B1 的意图，
  但影响面比现在大）⇒ **需 owner 确认**。

### 2.5 行为面 ⑤：归档新增「后续动作」事件，我方私有写通道绕过了它

* rc.2 在 `packages/workspace/workspace/src/index.ts:156,163` 新增两个并行事件
  `workspace/session-archived` / `workspace/session-unarchiving`，分别由 `archiveSession()`（`:403`）
  与 `unarchiveSession()`（`:426`）派发。
* **rc.2 起 worktree 清理挂在这个钩子上**：归档一个由官方 worktree 服务创建的会话时，默认会
  `git worktree remove`（保留分支与提交；忽略文件不保留）。见指南
  [`docs/upgrade-guide/v0.2.2-rc.1/archive-worktrees/guide.md`]。
* 我方 `dsh-archive-manage` / `dsh-desk-one` 走的是 **WorkspaceRegistry 私有写通道**
  （`enqueueOperation` + `setState`，登记在 `docs/private-seams.md` §A），**不经过** `archiveSession()`
  ⇒ 官方后续动作（worktree 清理、`session-unarchiving` 的阻塞语义）**都不触发**。
* 判断：这不是缺陷，是**既有偏离的扩大**（此前只是「不派发 stop 请求」）。三个选项：
  ① 保持（我们的归档/还原更保守，不会删用户目录）并**在 README「已知限制」写清**；
  ② 归档时补发同名事件（等于替官方驱动别人的清理策略，风险高）；
  ③ 改走公开 `archiveSession({ stopActivity })`（行为变化大，需 owner 定）。
  本轮先记录，等 owner 定，**不擅自改**。

> 复核对象：`docs/private-seams.md` 现存条目（§A 四条 + §D 现存依赖）。结论分四档：

### 8.1 本轮可直接去掉（零行为变化）

1. **`sessionPersistence.locate`**（调用点：`archive-manage` 的 `host/routes.ts:167`、`host/session-files.ts:95`、
   `host/views.ts:50,101`；`desk-one` 的同名四处 `host/sessions/routes.ts:161`、`session-files.ts:106`、
