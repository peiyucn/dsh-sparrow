# 直查结论：`--dsw-mask-blur` 的官方变更史

> 用于回答：「弹窗背景模糊是不是被我们改坏了？0.1.5 是有的。」
> 结论：**不是我们改坏的，是官方在 0.1.7-rc.2 有意去掉的，并且写了测试钉住。**

## 证据链（全部来自官方源码，可复现）

### 1. 那个变量与它的消费点

`--dsw-mask-blur` 定义在 `packages/client/ui-theme/src/styles/gradient-shadow-text.css`，
消费点共 **4 处**（rc.2 全仓 grep）：

| 文件 | 用法 |
| :--- | :--- |
| `ui-primitives/src/Modal.module.css:21` | `.mask { backdrop-filter: var(--dsw-mask-blur) }` |
| `ui-primitives/src/ImageLightbox.module.css:15` | 同上 |
| `ui-settings-general/src/client/SettingsRoot.module.css:74` | 同上（设置面板自己的 mask） |
| `ui-settings-account/src/client/DesktopOnboarding.module.css:13` | `.blurred { filter: var(--dsw-mask-blur) }`（**filter**，非 backdrop） |

### 2. 逐版取值

| 官方 tag | `--dsw-mask-blur` |
| :--- | :--- |
| `dsh-v0.1.5-rc.3` | `blur(2px)` |
| `dsh-v0.1.6-alpha.2` | `blur(2px)` |
| `dsh-v0.1.7-alpha.1` | `blur(2px)` |
| `dsh-v0.1.7-rc.1` | `blur(2px)` |
| **`dsh-v0.1.7-rc.2`** | **`none`** |

### 3. 改动发生在哪一次提交

`dsh-v0.1.7-rc.1` → `dsh-v0.1.7-rc.2` 的 diff（该文件）：

```diff
-  /* Shared blur treatments for blocking masks and translucent menus. */
-  --dsw-mask-blur: blur(2px);
+  /* Blocking masks dim the page; menu backgrounds retain their blur. */
+  --dsw-mask-blur: none;
   --dsw-menu-backdrop-filter: blur(40px) saturate(150%);
```

**注释本身被改写了** —— 从「mask 与菜单共用模糊」改成「**mask 只负责压暗页面；
菜单背景保留模糊**」。这不是失误，是一次语义重划。

引入提交：`fdd14a0989 feat(web): unify UI materials and streamline file review`
（2026-09-23）。同提交新增了视觉夹具与 e2e：
`apps/web/tests/menu-material.e2e.ts`、`apps/web/tests/visual/expected/menu-material/*`。

### 4. 官方**写了断言**把新行为钉住

`apps/web/tests/menu-material.e2e.ts`（rc.2）里：

```js
const mask = await settings.locator('..').locator(':scope > [aria-hidden="true"]').evaluate((node) => {
  const style = getComputedStyle(node)
  return { fill: style.backgroundColor, blur: style.backdropFilter }
})
expect(mask).toEqual({ fill: dark ? 'rgba(0, 0, 0, 0.5)' : 'rgba(0, 0, 0, 0.24)', blur: 'none' })
```

⇒ **`blur: 'none'` 是官方有测试保护的既定行为**，不是回归。

### 5. 与本插件的关系：**无关**

* 本插件源码里 **从未出现** `mask-blur` / `dsw-mask`（`git grep` 零命中）。
* 而且这个变量与我们染的那些 token 不重叠 —— 官方通过 `body { --dsw-mask-blur: none }`
  声明，「官方默认档」与「插件开启档」读的是同一个值（实测两档 `backdropFilter` 逐字相同）。
* 所以：**模糊不是我们弄丢的**，也不是我们给改坏的。

## 那么「加回来」意味着什么（供决策）

官方把 mask 的职责收窄成「只压暗」。要恢复 0.1.5 的观感，只需把该变量重设为
`blur(2px)` —— 但这是**刻意改官方默认外观**，触及仓库硬规矩
（owner 原话「官方默认的都不要动，给个完全不动的参考」）。

### 影响面（4 个消费点，逐个列清）

| # | 消费点 | 重设后的效果 | 是否可接受 |
| :--- | :--- | :--- | :--- |
| 1 | `Modal` 的 `.mask` | 模态遮罩背后的页面**变模糊**（0.1.5 观感） | ✅ 这就是 owner 想要的 |
| 2 | `SettingsRoot` 的 `.mask` | 设置面板背后的页面变模糊 | ✅ 同 1（设置也是 Modal 系） |
| 3 | `ImageLightbox` 的 `.mask` | 看大图时的背景变模糊 | ⚠️ 需 owner 确认（看图时模糊背景可能是好事，也可能干扰） |
| 4 | `DesktopOnboarding` 的 `.blurred` | 用的是 `filter` 而不是 `backdrop-filter` ⇒ 会把**自身内容**整体模糊 | ❌ **必须排除**：那是「滤自己」不是「滤背后」，重设会让引导页糊掉 |

⇒ **不能简单地全局重设该变量**（第 4 点会坏）。正确做法是
**只对前 3 处的 `backdrop-filter` 生效，把第 4 处的 `filter` 排除**。

### 建议实现（待 §7 决策后落地）

在插件样式表里按**消费点**分别给值，而不是改全局变量：

```css
/* 只恢复「遮罩滤背后」这一族；不用 filter 的那处（DesktopOnboarding）不受影响 */
body:not([data-dsh-theme-tone-plain]) .mask,          /* 官方 mask 类名需按稳定后缀匹配 */
... {
  backdrop-filter: blur(2px);
}
```

要点：
1. **不改 `--dsw-mask-blur` 本体**（避免波及第 4 处的 `filter` 用法）；
2. 选择器只锚 `backdrop-filter` 的消费点；官方 mask 类名是哈希的，须按
   **稳定后缀**（`_mask`）或结构定位 —— 本仓库已有同类先例与守卫；
3. 与「官方默认档」的关系：本改动**属于刻意改官方默认**，须走 `HOVER_CARD_ANCHOR`
   那一类「破例」的记账方式（仓库现有唯一一处刻意改官方默认的先例），
   即 **不带 `PLAIN_ATTR` 门**，两档都生效 —— 还是只在插件档生效，**由 owner 定**（见 §7 Q6）。
