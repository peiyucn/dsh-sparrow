# 0.1.3 SessionHandle 变更 — 影响面预判

> 状态：预判（2026-09-04 记，基于官方 dsh-v0.1.3-alpha.1 release note 与
> 0.1.2-rc.1 源码形态）。0.1.3 适配任务开工时按官方 changelog 与源码逐条
> 核验，本文件只作起点，不替代临场查证（查证原则见根 AGENTS）。

## 官方变更（release note 摘录）

- **破坏性变更**：Session persistence API 改为由生命周期持有的
  `SessionHandle`；`agentLoop.create()` 变异步；新增 session 锁，同一 session
  至多被一个进程持有。
- Session format 升级 v2：v0/v1 日志经不可变相邻 generation 迁移；Assistant
  流按 attempt 聚合进持久化 settlement。
- 已知性能回退：部分历史 session 加载响应速度受影响（官方承诺下一版修复）。

## 本仓库受影响面（按 0.1.2-rc.1 形态预判）

### dsh-archive-manage（影响最大）

- 直触 `ctx.sessions.get`：live 判定、header 读取、`ensureSessionNotLive`、
  `subagentLabel` 第一档
- `ctx.agents.get(...).status` 的 live 判定
- `live?.header` 与 `storedHeaderFacts` 双形状分流
- `addedSummaryFor` 的 `api-session/added` 载荷形状
- `sessionPersistence.list()`（rc.1 返回裸 header、master 返回快照）与
  `locate`（rc.1 公开契约、master 私有化）——0.1.3 可能再变，list 或需第三
  形状
- 护栏已就位：WorkspaceRegistry 写通道（enqueueOperation/requireState/
  setState）与 locate 启动能力检查 fail-fast
- 已知性能回退若落在历史 session 加载，会影响归档面板的列表/备份路径，适配
  时一并验证

### dsh-chat-fim / dsh-vision-bridge

- 两者直读 `session.snapshotEvents()` 取主路由：session format v2 后事件流
  形态需重验
- dsh-vision-bridge 另包装 `ctx.llm.resolveModelInfo`：0.1.3 模型探测相关
  改动需重验包装点（签名/副作用面）

### 其他

- dsh-file-manage / dsh-nav-pin / dsh-codebuddy-credits 不直触 session
  persistence，按官方 changelog 确认无间接影响即可。
