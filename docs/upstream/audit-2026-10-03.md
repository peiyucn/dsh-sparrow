## 2. 真回归：`role='menu'` 在 rc.2 换了承载元素

### 2.1 是什么

rc.2 的官方 `ModelSelect` 把 `role='menu'` 从菜单**卡片**搬到了内层**滚动容器**上：

| 版本 | 渲染 | 谁带 `role='menu'` |
| :--- | :--- | :--- |
| ≤0.2.0-rc.1 | `MenuSurface role="menu"` → `div.groups` → `section[role=group]` | **卡片**（滚动容器是它的直接子） |
| **0.2.0-rc.2** | `MenuSurface role={pane==='model'?'group':'menu'}` → `div.groups role="menu"` → `section[role=group]` | **滚动容器自己**（卡片变成 `role='group'`） |

证据：官方 `ui-model-selection/src/client/ModelSelect.tsx:484`（卡片）
与 `:551-555`（`div.groups.scrollable` 自己带 `role="menu"`）。

### 2.2 为什么上一轮审计没抓到

上一轮是 **token 级**审计（`0.2.0-rc.2.md` §4.4 自己写明抓不到行为变化）。
`role="menu"` 这个名字**还在**、在官方源码里**还出现**，所以 grep 全绿 ——
**变的是"哪个元素带它"**，不是"它还在不在"。这正是 §4.4 承认的那一类。

**方法学教训（已写进 `docs/private-seams.md` §D 旁注）**：
下次官方再动这一带，要问的是「**哪个元素带这个 role**」，不是「这个 role 还在不在」。

### 2.3 后果与修法

后果：分组菜单的**内圈圆角**规则 `[role='menu'] > :has([role='group'])` 在 rc.2 结构下
**一条也命不中**（静默失效，不报错、不显形）。

修法：两条腿各出一条规则（不能合并进 `:is()`）——

* `GROUPED_MENU_SCROLLER_SELECTOR = "> :has([role='group'])"` —— 卡片是菜单锚点（rc.1 / codebuddy）
* `GROUPED_MENU_SELF_SCROLLER_SUFFIX = ":has(> [role='group'])"` —— **滚动容器自己就是锚点**（rc.2）

⚠️ **为什么不能合并进 `:is()`**（实测，不是推断）：相对选择器（以 `>` 开头）在 `:is()` 里按规范非法，
而浏览器**不报错、也不整条丢弃** —— 实测（Edge，读回 `document.styleSheets` 的 `selectorText`）
`:is(:has([role='group']), > :has([role='group']))` 被解析成 `:is(:has([role='group']))`，
**相对那一支被静默删掉**，rc.2 那一半照样丢。

### 2.4 验证（真机实测，两种 markup 同页对照）

| 形态 | 旧腿 `> :has(…)` | 新腿 `:has(> …)` |
| :--- | :--- | :--- |
| rc.2 官方 `ModelSelect` | **0** | **1**（`div.groups`）|
| rc.1 官方 `ModelSelect` | **1**（`div.groups`） | 0 |
| 本仓库 codebuddy `CodeBuddyModelSelect` | **1**（`div.ccb-model-groups`） | 0 |

真机计算值（读 `getComputedStyle(...).borderRadius`）：rc.2 滚动容器 `12px 17px 0 0`、
codebuddy 滚动容器 `16px 21px 0 0` —— 两条腿各吃到自己那份同心值。

**反向注入**（4 条，全部红 → 还原绿，工作树逐字节还原）：
删掉新腿的产出 / 改成 `:is()` 合并 / 退回「直接子」形态 / 改成非 `:has` 形态 —— 4/4 被新守卫抓住。

### 2.5 顺手查证：材质层**不会**滚走（不是缺陷，别照搬别处的结论）

直觉上会以为：`[role='menu']::after` 是 `position: absolute; inset: 0`，锚点既然成了滚动容器，
这层就该随内容滚掉。**实测否掉了**：官方 rc.2 的 `.menu`（卡片）是 **`position: fixed`**、
`overflow: hidden`，而 `.groups`（滚动容器）**没有 position**（static）⇒ `::after` 的包含块是
**卡片**、不是滚动容器，它**钉在卡片上**。

同构复刻实测（官方两条 CSS 逐字 + 一个与 `::after` 同属性的真实元素做镜像）：

| 采样 | 相对滚动容器的 top | 相对卡片的 top |
| :--- | ---: | ---: |
| `scrollTop = 0` | −4 | **0** |
| 滚到底 | −4（**完全没动**） | **0** |

⇒ 材质层照旧钉在菜单卡片上，**不需要为它加任何元素级兜底**。

## 3. 实测与静态推断相反的一条（诚实记录）

静态审计（读 `src/surface.ts` 的锚点表 + 官方 markup）推断：
归档页 / 云文件页从 `role='dialog'` 弹窗改成 `main` keyed 槽的**页面**之后，
`DIALOG_ANCHOR = "body [role='dialog']:not(:has(> img))"` 不再命中它们，
⇒ 颗粒 / 打光两张图层规则对这两页失去命中。

**真机像素实测否掉了这个推断**（暗色轴，两个采样区各 200×100）：

| 区 | 亮度 | 颗粒（亮度标准差） | 暖度 |
| :--- | ---: | ---: | ---: |
| 归档页空白区 | 19.67 | 2.246 | −5.53 |
| 对话区地面（对照） | 19.40 | 2.201 | −5.31 |
| 左栏（对照） | 28.83 | 2.173 | −7.79 |

归档页与对话区地面的**亮度 / 颗粒 / 暖度三项基本同值** ⇒ 这两页**照旧有质感与打光**。
机制：页面自己是**透明**的，本插件 `position: fixed` 的**地面层**在其后铺满视口
（单独隐藏地面层该区亮度 19.67 → 10.43 ⇒ 地面贡献 **9.24 亮度**）。

⚠️ **结论**：`0.2.0-rc.2.md` §「交给 owner / 另一路」那条「失去命中 ⇒ 退回官方纯色面」
**只在"页面自己不透明"的前提下成立**；本插件的地面层是整屏 `fixed` 的，所以实际没有退。
CHANGELOG 第 14 条（归档页 / 云文件页有纹理与打光）**与实测一致，不是错**。
静态审计提出的「高危 CHANGELOG 断言」**不成立**，此处如实记录以免下轮重查。
（待办：把这条实测补进归档 / 云文件那两个 spec 的《交给 owner / 另一路》小节。）

`plugins/dsh-nav-pin/README.md:3` 自己写着「⚠️ Retired (2026-09-29) — merged into `dsh-theme-tone`.
