# 00 · 共同面与验收（六个插件共用）

> 这一份是其余六份的前置：凡是「六个插件都要做」的事写在这里，插件文件里只写自己特有的。

## 1) 依赖升线（全部插件）

* 六个活跃插件的 `package.json` 里 `@deepseek-ai/dsh-*` 的 `peerDependencies` / `devDependencies` 全钉 `0.1.5-rc.2`，需整批升到 **`0.1.7-alpha.2`** 后重新 typecheck。
* 版本号策略：镜像官方线，插件版本走 `0.1.7-alpha.2`（自家迭代用预发布尾段递增，如 `0.1.7-alpha.2.1`）；通道 `next`。
* `dsh.client.platform` 在 alpha.2 是**必填且受校验**的 string（`packages/client/modules/src/client/manifest.ts:161-179`）；`inject` / `external` / `immediately` 语义未变。
* ⚠️ 待评估：升线后 `dsh.client.external` 白名单（我方 `scripts/bundle-client.mjs` 的种子词清单）与 peer 解析的联动。

## 2) 图标改名 —— 一招解四个 client half（最高优先）

**官方规则变了**：`Icon<字形><尺寸>`（如 `IconCloseOutline16`）→ `Icon<字形><字重>`（`…Regular` / `…Medium`），尺寸改由 `size?: number` prop 控制（alpha.2 `packages/client/ui-primitives/src/icons/index.tsx:1-4`、`icons/props.ts:2-8`）。**无兼容别名**，改名发生在 **alpha.1**（rc.2 / rc.3 / 0.1.6-alpha.* 仍是旧名）。

我方 8 个图标全部消失：

| 旧名（rc.2） | 新名（alpha.2） | 定义行 |
|---|---|---|
| `IconArchiveOutline20` | `IconArchiveOutlineRegular`（或 `…Medium`） | `icons/index.tsx:1304` |
| `IconCloseOutline16` | `IconCloseOutlineRegular` | `:255` |
| `IconFolderOpenOutline16` | `IconFolderOpenOutlineRegular` | `:894` |
| `IconSparkle16` | `IconSparkleRegular` | `:1178` |
| `IconChevronDownOutline14` | `IconChevronDownOutlineRegular` | `:174` |
| `IconChevronRightOutline14` | `IconChevronRightOutlineRegular` | `:206` |
| `IconCheckOutline16` | `IconCheckOutlineRegular` | `:139` |
| `IconWarningOutline16` | `IconWarningOutlineRegular` | `:598` |

* 落点四处：`dsh-file-manage/src/client/FileManageDock.tsx:7`、`dsh-archive-manage/src/client/ArchiveDock.tsx:7`、`dsh-chat-fim/src/client/ChatFimDock.tsx:6`、`dsh-codebuddy-credits/src/client/CodeBuddyModelSelect.tsx:22`。
* `Regular` = 1px 描边、`Medium` = 1.3px（`icons/index.tsx:253-262`）；旧名里的数字是**渲染尺寸**，迁移时显式传 `size` 保持观感。
* **为什么必须靠测试兜**：`ui-primitives` 是动态 bundle 的 external 基线（`packages/client/AGENTS.md:78`），缺命名导出**不报链接期错误**、`require` 只得到 `undefined`，首次渲染才抛 React #130，被 per-entry 边界接住（`ui-renderer/src/client/scoped-slots.tsx:404-420`）——页面整体不崩，只有那几格退化成 `<div data-slot-error="…">`。→ 每个受影响插件补一条「产物级」结构测试钉住新名。

## 3) client half 的三条硬约束（上一轮已写进 AGENTS，这里再确认一次）

1. **不许抛错**：客户端 boot 审计把任一非 active 的 client entry 当致命失败（`packages/client/web/src/boot-client.ts:66-89`），抛错 = 宿主整页停在 "Failed to load plugins"。
2. **`inject` 只放跨版本稳定存在的服务**；易变面走 `ctx.inject([...], cb)` 起的可选依赖 fork（缺服务 = entry 永久 pending = 同样致命）。
3. **host half 被自停用时，client half 也要跟着停**：否则会出现「界面还在、接口 404」的假活状态（chat-fim 在 alpha.2 实测就是 `/api/chat-fim/complete` 连打 404）。

## 4) 验收口径（每个插件都要过）

* **真机**：独立 `DSH_HOME` + 指向真实 profile 的 junction + `playwright-cli`，**不碰** owner 正在用的 3080 实例。
* **断言写行为级**（不做像素快照）：插件是否激活/停用、目标 UI 元素是否存在、console 有无 `#130` / `data-slot-error`、网络有无 404、关键交互（点选 / 开关 / Tab）是否生效。
* **两条线都要跑**：`0.1.7-alpha.2`（新线，主战场）与 `0.1.5-rc.2`（pkg 模式，防回归——双 fork 类改动必须两条线都验）。
* 插件目录 `npm run verify` 全绿 + `git diff --check` 干净。

## 5) 分支与发布

* 适配全部落 `dsh-0.1.7`；`dev` 继续发 `latest` 线的 rc.2 版本。
* 官方 0.1.7 进 **rc** 后再谈合流（届时 `dev` 切到新版本线）。
* push tag / npm publish 仍需 owner **当次点头**（不变）。

## 6) 结论（owner 拍板）

* 提交粒度：**待定** —— 建议「共同面一个 commit（升依赖 + 图标改名 + 测试），之后一个插件一个 commit」。
* 是否需要先发一版 `next` 预发布给 owner 本机验证：**待定**。
