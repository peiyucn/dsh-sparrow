## 讨论稿的统一结构

每个插件文件固定五段：

1. **定位与结论** —— 这个插件是什么、本版判定的档位（退役 / 部分退役 / 适配 / 重设计）
2. **现状（真机 + 源码双证）** —— host half / client half 各自的实际状态
3. **改动清单** —— 逐条带 `文件:行号` 落点
4. **结论（owner 拍板）** —— 留空，讨论后回写
5. **验收口径 / 未核实项**

## 纪律

* 讨论期间**不动代码**；结论回写后，按「一个插件一个 commit」推进。
* 证据标注沿用总评估口径：行号指 `dsh-v0.1.7-alpha.2` 工作树；真机结论来自独立 `DSH_HOME` + playwright（不碰 owner 正在用的 3080 实例）。
* 官方若继续出 alpha.3 / rc，本目录结论需按新版本重跑核验（尤其图标与 token 面）。
