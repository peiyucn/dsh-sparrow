## 官方变更（release note 摘录，0.1.2-rc.1 → 0.1.5-rc.1）

破坏性变更：

- **Session 数据格式升级至 V3**：受支持的旧日志通过不可变的相邻版本迁移生成新版日志**并保留原文件**；Assistant 流按 attempt 聚合进持久化 settlement；系统提示词纳入消息历史；旧 PTC 事件与 `code` 预设引用自动迁移。**自定义日志读取器需适配 V3，升级后的会话不支持降级读取。**
- **Session 生命周期变更**：persistence API 改为由生命周期持有的 `SessionHandle`；`agentLoop.create()` 改为异步；新增 session 锁，同一 session 至多被一个进程持有。
- **插件 Agent API 调整**：移除 `ctx.agent`，调用方需显式传递 Agent。
- **Inbox API 调整**：`Inbox` 改为类型接口，不再导出可构造的运行时类；插件通过 `agent.inbox` 读写待处理消息，`hasPending` 与 `claim` 不再属于公共接口。
- **Web 插件面板 API 调整**：插件可通过 `sidebar.panellist` 与 `main` 注册全局面板；原 `conversation` Slot 迁移为 `main` 的 `conversation` key。
- **默认工具调整**：SDK、Headless、ACP 默认使用 read/write/edit；Web `minimal` 与 Python `sdk-minimal` 默认仅提供持久 shell。
- 自定义 persona 配置拆分前缀/后缀；pi-ai 升至 0.85.1；可选子代理插件内置运行时升级（Codex 0.153.4 / Claude Code 2.1.263）。

体验与修复项与本仓库适配基本无交，从略（完整列表见官方 release 页）。

### 会话磁盘布局

```
27 × ~/.dsh/sessions/<workspace>/<id>/session.jsonl.zstd     旧代，原样保留
 7 × …/session.v3.jsonl.zstd                                 V3 新代（迁移产生）
 3 × …/dsh-archive-manage.json                               归档插件 sidecar 记账
```

- 文件是 zstd 帧（magic `28 b5 2f fd`）；本机 Node 24 的 `zlib.zstdDecompressSync` 对整份文件报
  `Unknown frame descriptor`，**不确定**是否多帧拼接，读取应走官方 persistence 而不是自解压。
- 会话 id 传入 `SessionId()` 时**带 `session-` 前缀**（如 `session-15defd87-…`），
  实测不带前缀会得到 `UNKNOWN_SESSION`；目录名新旧两种形态并存。

## 逐插件影响（2026-09-10 按 dsh-v0.1.5-rc.1 源码逐条核验）

### 结论一览

| 插件 | V3 后状态 | 唯一破坏点 | 本版改动 |
| :--- | :--- | :--- | :--- |
| dsh-archive-manage | 坏（`/trash`·`/delete` 报 501，文案指向 v3） | 格式门支持集合 `[0]` | 支持集合加 `3`；私有 `locate` 改结构化访问器（0.1.5 起不在公开类型上） |
| dsh-chat-fim | UI 整体隐藏（`supported:false`） | 同上 | 支持集合加 `3` |
| dsh-vision-bridge | `vision_read` 恒失败、状态图标照常（看起来「正常」） | 同上 + `assistant/chunk` 事件类型消失 | 支持集合加 `3`；改读 V3 `assistant/attempt.data.stream[]`，保留 V2 分支 |
| dsh-codebuddy-credits | 正常 | — | 无（仅依赖声明升级） |
| dsh-file-manage | 正常 | — | 无（仅依赖声明升级） |
| dsh-nav-pin | 正常 | — | 无（仅依赖声明升级） |

### dsh-archive-manage

根因不是 API 缺失，而是**格式门语义漂移**：0.1.5 的 `sessionPersistence.list()/stat()` 把 header
翻译成**当前逻辑版本**再返回（官方 `session-persistence-jsonl/src/index.ts:1064-1079` 的 `currentHeader`
强制 `=== SESSION_FORMAT_VERSION`；`format.ts:140-155`），所以 `header.version` **恒为 3**，不再代表磁盘
物理代；插件读到的就是 3 → 真值门在 `host.ts:718-722/736/1100` 抛 `BACKEND_UNSUPPORTED` 501。

除格式门外**全部不破**（逐条已核验）：

- `list()` 返回 `Snapshot{header,revision,sizeBytes}`，插件的双形状读命中；
- `locate` **仍在**但只在 jsonl 后端私有（`session-persistence/src/index.ts:293-295`），已不在公开
  `SessionPersistence` 类型上 → 插件改经 `assertSessionLocationApi` 返回结构化访问器；
- WorkspaceRegistry 的 `enqueueOperation`/`requireState`/`setState` 仍在、签名未变（`workspace/src/index.ts:653/643/648`）；
- `sessions`/`agents`/`sessionQuery`/`projections`/`storageDomain`/`webServer.register`/`sidebar.footer.action` 全在；
- 目录粒度 `<root>/--<cwd>--/<id>/` 与 0.1.2 相同，插件只用 `dirname(location.path)` 整目录移动 → 仍然正确。

**坑（已写进代码注释）**：别用 `header.version` 判断磁盘代（恒为当前版本）；别用 `location.path` 本体
（v0-only 会话会拿到不存在的 v3 路径）。

### dsh-chat-fim

根因链路：`host.ts:263` `hostFormatSupported(session.header)` → `header.version=3 ∉ [0]` →
`host.ts:264` 回 `{supported:false}` → client `ChatFimDock.tsx:662` `return null`（开关消失）、`:979` 菜单不渲染。
apply 期常量探针通过是因为它读的是插件自带的旧副本（值 0）——正是 `compat.ts:43-46` 注释预警的场景。

V3 事件形态**不影响**主路由读取（原 `mainRouteFromSession`，2026-09-10 已改为官方 `mainRouteFromHeader`）：`request/header` 仍带 `EpochHeader`
（官方 `types.ts:365-370`、`:232-239`）且 `header.config.provider/model` 仍在（`llm/src/call-config.ts:23-30`）——
该路径不读被移除的 `data.header.system`。`snapshotEvents()`（`core/session/src/index.ts:633`）、`session.header`（`:464`）都还在。

`conversation.input.dock` / `conversation.input.overlay` 两个 slot 仍在且 kind/scope 未变
（`client/ui-conversation/src/client/contract/slots.ts:166`/`:168`）→ slot 契约不是主因。

### dsh-vision-bridge

> **2026-09-10 决定退役**：能力已被官方原生多模态覆盖（`deepseek-flash`），本文件的适配改动仅作为退役前的最后一次修复记录。

除了同一道格式门，另有一处**真实的 V3 事件迁移**：`assistant/chunk` 不再是独立事件类型，
assistant 流按 attempt 聚合进 `assistant/attempt`（`types.ts:335`）与 `assistant/message`（`:326`）的
`data.stream[]`，原始记录为 `{ type: 'chunk', chunk }`（`llm/src/assistant-stream.ts:20-44`），
`block-end` 的 `chunk.block` 才带图片块。插件已改为优先读 `stream[]`，并保留 `assistant/chunk` 分支
（经 `string` 拓宽比较以免与 0.1.5 类型冲突）以继续支持旧宿主。

### dsh-codebuddy-credits / dsh-file-manage / dsh-nav-pin

三项 0.1.5 破坏性插件 API 变更**都没有打到这三个插件**（逐条核验）：

- `ctx.agent`：官方 packages 全树 0 命中，能力改走 `agent/request` 载荷；三插件也 0 使用；
- `Inbox`：已类型接口化（`core/agent/src/runtime-types.ts:48`），三插件 0 使用；
- 面板 API：新增 `sidebar.panellist` 与 `main`（`ui-layout/src/client/index.ts:66`），裸 `conversation` slot 消失，
  但三插件都不注册它们；codebuddy 用到的 6 个 slot 全在且 kind/scope/owner 一致。

唯一遗留（**非运行时问题**）：五个插件 client 端仍 `import type { ClientContext, SessionId } from
`@deepseek-ai/dsh-client-runtime/client``（官方 0.1.5 已不再发布该包）。**不能简单换成 `@deepseek-ai/cordis`**：
已实测——`ctx.slots` / `ctx.remote` / `ctx.sessions` 这些合并声明来自 `@deepseek-ai/dsh-client-ui-renderer/client`
（`ui-renderer/src/client/index.ts:33-48` 在 `declare module '@deepseek-ai/cordis'` 里声明 `slots`/`uiRenderer`）、
`@deepseek-ai/dsh-api-remotes/client`、`@deepseek-ai/dsh-api-session-controller/client` 等包，cordis 自带没有；
官方 0.1.5 的写法是 `import type { Context as ClientContext } from '@deepseek-ai/cordis'` + 一串 side-effect
type import（见 `client/ui-input-trigger/src/client/index.ts:7-12`、`client/ui-message-feedback/src/client/index.ts:10-14`）。
对齐需给各插件加 2–3 个官方 peer/dev 依赖（均已确认有 0.1.5-rc.1），属依赖面变更，**待 owner 决定是否单列一做**；
client 端 `SessionId` 类型的官方来源是 `@deepseek-ai/dsh-session/types`。
