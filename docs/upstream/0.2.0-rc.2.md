## 1. 结论

**直接原因仍是版本门**：peer 写的是精确 `0.2.0-rc.1`，运行时是 `0.2.0-rc.2`
⇒ 五个活跃插件在 profile 启动时被整批跳过（与 rc.1 那次的机制完全同型）。

**但与 rc.1 那次有一个关键区别：本版有 1 处真回归。** 官方在 `0.2.0-rc.2` 把分组菜单的
标题渲染抽成了新原语 `MenuGroup`，并在标题**前面**插入一个 1×1 隐形哨兵
（`<span data-menu-group-start>`）⇒ 标题不再是 `:first-child`，而 theme-tone 的分组标题
图层规则正是用 `[role='group'] > :first-child` 定位的。后果是规则打到哨兵上、真标题拿不到
图层，官方新的吸顶填充（`--dsw-alias-menu-group-header-fill`，浅深各 94% 不透明）会直接压在
我们染过色的菜单上 —— 即这条规则当初要治的「横带」回归。**已修**（`dc17491`，§5）。

其余 **13 类 seam 零回归**（§4）：官方 API 符号、会话格式常量、槽位名、`data-*` 锚点、
CSS 变量、hash 类名（除上述一处）、locale 字面量、平台种子词表、`container-type` 上下文、
宽度轴变量、`design-platform.css` 的 token **取值**全部保持兼容。

因此本次「适配」的实质是：

1. **依赖升线 + 重建 + 重验证**（机械工作，无代码改动）——`d955e9d` + `ac8d491`；
2. **一处契约修复**：分组标题锚点兼容 `MenuGroup`（`dc17491`）；
3. **一处 profile 纠正**：退役的 `dsh-nav-pin` 从挂载列表移除（§2）。

**`dsh-nav-pin` 又一次"活着"**：它的 `peerDependencies` 里没有任何 `@deepseek-ai/dsh-*`
（版本门只检查该前缀，`plugin-compatibility.ts:75` 直接 `continue`）⇒ 它**根本没参加考试**。
所以本次升级后 profile 里唯一还在跑的 sparrow 插件，恰好是那个**已经退役、功能已并入
theme-tone** 的插件，而接替它的 theme-tone 被跳过。这是漏考留下的第三种症状（前两种是
「白捡存活」与「与 rc.1 报告口径不符」），本次一并把它的挂载行删掉。

## 5. 本版唯一真回归：分组标题锚点与新原语 `MenuGroup`

### 5.1 现象与根因

theme-tone 的分组标题图层规则用结构锚点定位标题：

```ts
export const GROUPED_MENU_TITLE_SELECTOR = "[role='group'] > :first-child"   // rc.1 及以前
```

两个官方渲染形态在 rc.1 都是这个结构（`[role='group']` 的第一个子元素就是标题）：

| 版本 | 渲染 |
| :--- | :--- |
| rc.1 官方 `ModelSelect` + 本仓库 codebuddy 菜单 | `<section role="group"><div className="…groupTitle">标题</div>…` |
| **rc.2 官方 `MenuGroup`** | `<section role="group"><span data-menu-group-start/>`（**1×1、opacity 0 的哨兵**）`<div data-menu-group-heading>标题</div>…` |

rc.2 在标题**前面**插入哨兵是**有意的** —— `observeStickyMenuGroups` 用它与
`IntersectionObserver` 判断"这一组是否正压在视口顶部"，从而决定给标题加 `[data-stuck]`。

于是 `:first-child` 命中哨兵，**真标题条拿不到我们的图层**。而官方给吸顶标题的填充是
本版**新增**的 token：

```css
.heading[data-stuck] { background: var(--dsw-alias-menu-group-header-fill); }  /* 浅深各 94% 不透明 */
```

这层不透明的灰压在**已经被我们染过色**的菜单上，就是这条规则当初要治的「横带」
（`05-surfaces` §8.2 记过：标题必须与卡片**同一摞层**，否则同色的填充会在带光的面上显形）。

### 5.2 改法与为什么这么改

```ts
export const GROUPED_MENU_TITLE_SELECTOR =
  "[role='group'] > :is(:first-child, [data-menu-group-heading])"
```

三处刻意的选择：

1. **保留 `:first-child`**：本仓库自己的 codebuddy 菜单
   （`CodeBuddyModelSelect.tsx:475-476`）仍是旧结构，rc.1 的官方 `ModelSelect` 也是 ——
   删掉它会把自家菜单一起弄坏。
2. **用 `:is()` 合并，不用逗号列表**：本常量是**后代片段**，由 `groupTitleRule()`
   拼在 `GROUPED_MENU_UNGUARDED_SELECTOR` 之后。若写成顶层逗号列表，
   拼接处会把整条规则切开 —— `… A B, C` 的后半段 `C` **丢掉 body 前缀与色调门**，
   静默生效到全站。这是本文件反复记录的那类"规则静默走形"的坑。
3. **特异度不变**：`[data-menu-group-heading]` 与 `:first-child` 同为 (0,1,0)，
   `:is()` 取最具体参数 ⇒ 整体仍是 (0,1,0)，与本版之前**完全一致**，
   不改变与官方任何规则的胜负关系。

**为什么不去染那个新 token**（本版唯一需要判断的 token 问题）：不需要。
我们的标题规则本来就写 `background-color: var(--dsw-alias-bg-base) !important`
+ 六层 `background-image`（含不透明地面与染色后的菜单填充），
官方 `background:` 简写设的 `background-color` 被我们的 `!important` 逐元素盖掉 ⇒
该元素的填充**完全由我们决定**，`--dsw-alias-menu-group-header-fill` 不参与渲染。
（它只被官方 CSS 消费，而那些 CSS 正是我们覆盖掉的那条。）
按"不染我们已完全接管的面"的口径，**不加进 `POPUP_TOKENS` / 面 token 表**。

### 5.3 守卫与证据

新增两条回归守卫（都在 `test/surfaces.test.mjs`，与既有"标题不得出现本插件声明"那条并列）：

* 必须包含 `[data-menu-group-heading]`（否则 rc.2 上打错元素）；
* 必须是**单个复合选择器** —— **括号外不得有逗号**（`:is()` 内的逗号是嵌套的，不切分外层）。

两条都用**反向注入**验过有牙齿（本仓库纪律）：

| 注入 | 结果 |
| :--- | :--- |
| 选择器退回 `[role='group'] > :first-child` | **`pass 292 / fail 1`**，报「必须同时锚 … data-menu-group-heading」 |
| 改成顶层逗号列表 `A, B` | **`pass 292 / fail 1`**，报「必须是单个复合选择器（顶层逗号会切断后代拼接）」 |
| 还原 | `pass 293 / fail 0` |

另：既有用例「组合规则不得用带 `:has()` 的守卫锚点」会以该常量拼出期望选择器并断言
构建产物里确实有这一条 ⇒ **产出的 CSS 文本本身也被钉住了**（不是只测常量字符串）。
`pnpm run verify`（theme-tone）**exit 0**，`git diff --check` 干净。
