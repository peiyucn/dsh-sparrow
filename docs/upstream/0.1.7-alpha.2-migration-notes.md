## 3) theme-tone 设计哲学评估：**路子对，但一半该换**

**结论：官方仍把「三方色调」当扩展点，但本插件必须从「自铺静态样式表」改成官方 `ctx.theme` 的注册/覆盖 API；自绘背景层官方没覆盖，继续保留；官方外观行装不下色调，自建选择行与自己的持久化也必须留。**

* **原本的哲学仍成立**：官方明说「第三方主题可通过 `ctx.theme` 注册别名 token 覆盖」（`packages/client/ui-theme/README.zh.md:12`），并把已知限制写死为「第三方主题是扩展点，不是产品」（同文件 `:103`）。
* **官方 API 正好对着我们的需求**：`register({id, colorScheme, tokens})`（`ui-theme/src/client/index.ts:276`）= 同轴多套配色；`overrideTokens(source, tokens)`（`:309`）是可分层（`seq`）、可 dispose 还原的叠加层；`exportInspectTokens()`（`:211`）让插件先查再改；官方还给出 14 个受认可的覆盖 token 白名单（`:131-146`）。
* **官方在强制我们本来的口径**：覆盖值必须 `{light, dark}` 成对，裸字符串抛教学式错误（`index.ts:384-404`）—— 与 theme-tone「每轴一套」完全一致。
* **静态样式表这一半该退场（按官方分工，不是「官方禁止」）**：官方把全局主题的所有权划给 `ui-theme` —— `--dsw-*` 静态色阶、语义别名、排版、动效、渐变、阴影、滚动条样式与明暗偏好都归它，全局样式表也归 `ui-theme/src/styles/`（`docs/web-styling.zh.md:9,11`）；功能包只许消费语义别名、不得写颜色字面量、不得含主题选择器（`:17,18`）；第三方要走官方给的 `ctx.theme` 扩展点（`ui-theme/README.zh.md:12`）。
  ⚠️ **更正**：`docs/web-styling.zh.md:5` 写明它规定的是**浏览器客户端包**（仓库内功能包）的职责 —— 对第三方插件**不是禁令**。本文早先把这条读成「官方劝阻第三方自铺样式表」，措辞过强，以此处为准。
  换到官方 API 的真实收益仍在：静态表要自己处理明暗取值、层级顺序、卸载还原，`overrideTokens` 三者全包。另有一条我方当前**确实会违反的明文规则**：半透明 `--dsw-specific-menu` 填充的高层级表面必须在**同一规则中**配 `backdrop-filter: var(--dsw-menu-backdrop-filter)`（`:25`）—— 我方 opaque 覆盖该 token 且不配 filter，既破坏这个配对、又吃掉官方菜单玻璃。
* **官方没有、我方必须保留的两块**：① 色调预设与自定义 CSS —— 外观行硬编码 light/dark/system 三个 cube（`ui-theme/src/client/AppearanceRow.tsx:31-35`），全仓无 custom CSS 机制；② 自绘背景/质感 —— token 只有颜色，官方玻璃只到 `--dsw-menu-backdrop-filter`（`gradient-shadow-text.css:20`），消费面仅菜单/停靠面板三处（`ContextMeter.module.css:55`、`TodoPanel.module.css:26`、`QueueDock.module.css:45`），**顶栏与输入框不在内**；官方新 elevation 是描边 + 柔光投影（`:29-35`），不是玻璃。
* **两个必须知道的天花板**：三方主题 id 不跨内置 settings schema、**无法持久化**（`setTheme` 只在 `isThemePreference(id)` 时写 Host，`ui-theme/src/client/index.ts:232-240`；README 明说「仍是进程内扩展」`README.zh.md:36`）；注册的主题**不会出现在官方外观行**。→ 重设计后仍需自建色调行 + 自有持久化（本次事故同时说明：这条自建路径要按新线的 `configForms` / `Config` schema 走）。

### 3.1 theme-tone 改造清单（8 条，逐条带落点）

1. `src/client/index.ts:16` 类型 `SettingsScope` → `ConfigForm`（`SettingsScope*` 系列类型已随服务改名，`ui-settings/src/client/index.ts`）。
2. `index.ts:154` 的 `ctx.inject(['settingsScope'], …)` → 等 `'configForms'`；**跨版本要起两个 fork**（rc.2 线只有 `settingsScope`，0.1.7+ 只有 `configForms`），二者都**不能**写进模块级 `inject`（缺服务 = entry 永久 pending = 宿主整页失败，`boot-client.ts:79-81` 已确证）。
3. `index.ts:249-251` 的 `ctx.settingsScope.bind({namespace})` → `ctx.configForms.get<T>(entryId)`（`ui-settings/src/client/config-form.ts:293-302`）；差异：按 entryId **缓存共享**、**无 `decode` 钩子**（需自行校验 snapshot）、生命周期从调用方 fiber 改到 provider。
4. `index.ts:482` 的 `scope.set()` 现在返回 `Promise<boolean>`（`config-form-types.ts:58,68,76`；memory 模式恒 `false`）——可借 `false` 补「写入失败」的用户可见反馈。
5. 注释/文档同步：`index.ts:231` 引用的 `settings-scope.ts:71` 路径已不存在；`host.ts:4`、`compat.ts:69`、`index.ts:140-152` 里关于 `settingsScope` 的说明都要改。
6. **`--dsw-specific-menu` 前提失效**：`tones.ts:284,320` 的 `POPUP_TOKENS` 假设该 token = `var(--dsw-alias-bg-layer-3)`；alpha.2 官方已把它改成半透明玻璃色 + `backdrop-filter: var(--dsw-menu-backdrop-filter)`（`packages/client/web/src/base.css:44`）—— theme-tone 的不透明覆盖会**盖掉官方新玻璃**，`tones.ts` / `surface.ts:10-25` 的推理需按新事实重写。
7. `--dsw-static-deepseek-400` 值变更（`rgb(103,158,254)` → `rgb(122,170,255)`）：theme-tone 只用 `deepseek-100`，直接影响小，但按官方字面量比对同族色的地方要同步。
8. `[data-sidebar-right-float-host]` 锚点已删（见 §1 第 12 项），玻璃/缝挡板里引用它的规则要换锚点。
