## 0) 一句话结论

* **没有必须改的插件代码**：rc.4 的实质改动只有 ACP 诊断输出、MCP 资源列表短路和会话视图 tooltip；
  五个插件依赖的公开槽位、服务、导出与样式锚点均未变。
* **但版本门必须跟**：五个活跃插件的 peer 仍精确钉 `0.2.1-rc.3`，rc.4 宿主会把它们判为不兼容
  **静默跳过**（`profile.ts:760-766`；`plugin-compatibility.ts:62-71`）⇒ 用户升到 rc.4 后表现为
  「插件全没了」，不报错。故本轮仍需发新版。
* 版本线从 `0.2.1-rc.3` 对齐到 **`0.2.1-rc.4`**；codebuddy 仓库内的 `0.2.1-rc.3.1` 一并归到 rc.4 线。

## 2) rc.3 → rc.4 真实差量

release note 只写了 ACP 一条，但 tag 差量里还有两组未列出的修复：

1. **ACP stdout**
   * `packages/llm/llm-deepseek-account/src/index.ts:57`：账号模型目录的 `console.info` 改 `console.error`，
     成功加载时也不再向 stdout 写诊断。
   * `packages/mcp/mcp-client/src/connection.ts:371-389`：MCP 服务器未声明 `resources` 能力时，
     `resources/list` / `resources/templates/list` 直接返回空页，不再调用会向 stdout 打
     `console.debug` 的 SDK 路径。
   * 新增 `apps/cli/tests/profiles/acp/tests/stdout.expected.e2e.ts` 作为 stdout 回归护城河。
2. **会话视图 tooltip**
   * `packages/client/ui-conversation/src/client/skeleton/ConversationSession.tsx:46-67, 228-241`：
     视图标签按字形宽度估算，只有预计溢出 88px 时才启用 tooltip。
   * 同一文件 `:240` 附近将「更多会话视图」的 aria-label 恢复为固定文案；对应
     `session.moreViewsCurrent` 从 `locales.ts` 删除。
3. **版本号**：其余 360 余个文件均为 workspace 包 `package.json` 的版本号与相关 README 快照。

## 4) 命中与处置

### 4.1 🔴 P0：版本门（必改，否则插件静默消失）

* 五个活跃插件的 `peerDependencies` 精确钉 `0.2.1-rc.3`；rc.4 宿主逐个校验
  `@deepseek-ai/dsh*` peer，不满足即抛错并被 `loadProfileDirectory` 收进 `skippedBundles`
  （`packages/boot/app-boot/src/profile.ts:760-766`，注释明写 "nothing is printed"）。
* 处置：按 §5 全量改版本线，再验证。

### 4.2 无代码改动的项

* **archive-manage / file-manage**：rc.4 未触及会话侧栏、归档/文件面板、`dsh-llm-deepseek` 导出。
* **chat-fim**：视图标签 tooltip 是宿主内部显示逻辑；插件不使用该 label，也不消费该组件。
* **codebuddy-credits / theme-tone**：rc.4 未触及 LLM provider、主题 token、样式锚点或 DOM 结构。
* **ACP 修复**：对 Web GUI 与桌面端无直接行为变化；只有使用 ACP profile 的自动化调用方受益。
  本轮不额外做 ACP 实测，宿主已有 e2e 覆盖。
