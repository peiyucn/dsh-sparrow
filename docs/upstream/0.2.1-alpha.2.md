## 0) 一句话结论

* **官方仍在 alpha 线**：npm dist-tags `latest = next = 0.2.0-rc.2`，**只有 `alpha = 0.2.1-alpha.2`**。
  我方 pin 的 `0.2.0-rc.2` 是 `latest` ⇒ **现在没有任何东西逼我们动**，本次评估纯粹是提前备料。
* **契约面整体是干净的**：32 个 import 说明符、24 个值导入符号、10 个槽位、官方 `data-*` 锚点

     退到 fallback（§4.2）。
  3. 🟠 **`reasoning.efforts` 顺序契约**：官方 alpha.2 新增「取首个条目当最低强度」的消费点，
     我们的顺序以 `off` 开头 ⇒ 官方生成的会话标题会取到「关闭思考」（§4.3）。
  * ⚪ 第 4 条（§4.4，仅观感）：官方设置区把「字号」单行扩成整组，theme-tone 的色调行顺序不变、
    但位置被往下推。**无需改代码**。
* **另有一条机械项必须在 rc 时处理，且现有守卫抓不到**：`cordis` / `schemastery` **走独立版本线**
  （alpha 线起 `4.0.5-alpha.1` / `3.18.5-alpha.1`），而 `scripts/plugin-set.mjs` 的版本门只认
  `@deepseek-ai/dsh*` ⇒ **漏改也全绿**（§5.1）。

### 4.1 🔴 `webRuntime` 服务在 alpha.2 被删除（唯一功能性破坏）

**官方侧**（**alpha.2 引入**，alpha.1 仍在 —— 已用 provide 点定论）：

| tag | `packages/bundle/web-app/src/index.ts` |
| :--- | :--- |
| rc.2 | `:38` `const WEB_RUNTIME_SERVICE = 'webRuntime'` + `:231` `ctx.provide(WEB_RUNTIME_SERVICE, runtime)` |
| alpha.1 | `:40` 常量仍在 + `:250` `ctx.provide(...)` 仍在 |
| **alpha.2** | **全文无** `WEB_RUNTIME_SERVICE`、**无任何 `ctx.provide`** |

`packages/bundle/web-app/cordis.patch.yml` 的 `connection` 行同向：rc.2 `:218` / alpha.1 `:231` 都是
`inject: [webRuntime]`，alpha.2 `:231` 才换成 `[webStartup]`；`:236` 取信任面同步改为
`ctx.webStartup.trustedHosts`。删除 commit = **`cb9a590c86`「Support concrete Web listener bind addresses」**。

**我方命中**（4 个插件，各一处 `officialTrustedHosts`，全部**请求期**读、全部有 `try/catch` + 形状校验）：

| 插件 | 位置 |
| :--- | :--- |
| dsh-archive-manage | `src/trust.ts:63,69` |
| dsh-chat-fim | `src/trust.ts:74,80` |
| dsh-codebuddy-credits | `src/trust.ts:107,113` |
| dsh-file-manage | `src/trust.ts:92,98` |
| dsh-theme-tone | ✅ **不读，零影响** |

**后果（已核 cordis 语义，非推断）**：`ctx.get()` 是**可选探测**、缺服务返回 `undefined` 而不抛错
（官方 checkout 自带 `vendor/cordis/src/reflect.ts:231` 文档行逐字「returns the service value, or
`undefined` when not (yet) provided」、`:240` `if (!impl) return`；该文件**三 tag 逐字节相同**）。
四处又都有 `try/catch` 兜底 ⇒ **不崩、不抛、不触发自停用、不阻断启动**（四处的 `apply` 期能力门
**都没把 `webRuntime` 列为必需能力**，这正是「回归为何静默」的机制）。

⇒ **但额外信任面永久拿不到** ⇒ 栅栏 `allowedHosts` 恒为 `[]` ⇒ **非回环 authority 一律拒**。
栅栏在各自路由**最前面**（`archive-manage/src/host.ts:1080`、`chat-fim:283`、`file-manage:171`、
`codebuddy/web.ts:133`）⇒ **拒了就是该插件整个 HTTP 面不可达**（含面板的只读列表），
而 dsh 本体正常 ⇒ 用户症状是「**插件打不开，但 dsh 没事**」。

**命中面不是理论风险**：alpha.2 同时把 `Config.host` 从枚举改成「必须是具体 IP 字面量」、
**通配地址在加载期硬拒**（`packages/host/webserver/src/index.ts:263-270`），用户被迫改用具体 IP
（官方注释点名容器 Pod IP，`:77-86`）—— **那恰好就是最典型的非回环场景**。
默认 `127.0.0.1` / `localhost`（本机自用）**完全无感**。

**rc 时的修法方向（仅评估，未开工）**：改成 `ctx.get('webStartup')`（字段名同为 `trustedHosts`），
并**同时保留旧名兜底**（`ctx.get('webRuntime') ?? ctx.get('webStartup')`）以维持 rc.2 兼容；
四个插件的测试夹具都只 mock 了 `webRuntime`，须同步补 `webStartup` 用例。
⚠️ **不要**去注入 `webStartup` 服务本身（那是 profile 行名，插件拿不到，且 alpha.1 上不存在）。
另有一条**走公开路径的更优解**待评估：官方新信任语义是「所绑定的 IP 天然可信」
（`packages/client/connection/src/api-request-trust.ts:105` 新增 `isBindAddressAuthority`），
而 `ctx.webServer.host` 是公开 getter（`webserver/src/index.ts:315-317`）⇒
**读绑定地址并入 `allowedHosts`，与官方同口径**。
⚠️ 一个边界：官方 `publicUrl` 注释逐字写着「**grants no trust**」（`startup.ts:67`）⇒
**不能**靠让用户设 `--public-url` 绕过本回归。

### 4.2 🟠 `data-composer-stats` 在 alpha.1 被删除（codebuddy 胶囊落点退化）

* **事实**：`data-composer-stats` 在 rc.2 命中 2 个文件（`apps/web/tests/message-actions.e2e.ts`、
  `packages/client/ui-chat/src/client/chat/StatsPills.tsx`），**alpha.1 与 alpha.2 均 0 命中**。
* **官方同时改了结构**：`conversation.composer.dock` 由**单条** `stats` entry（rc.2 `apply.ts:284-288`）
  拆成**两条** —— `activity`（order 0）+ `usage`（order 1）（alpha.2 `apply.ts:324-331`），
  每颗胶囊改在 `StatsPills.tsx:175/197` 上带新属性 **`data-composer-stat={stat}`**；
  另新增 `data-composer-dock`（`InputBar.tsx:520`）。
* **我方命中**：`plugins/dsh-codebuddy-credits/src/client/CodeBuddyCreditsStats.tsx:22`
  `const ROW_SELECTOR = '[data-composer-stats]'` ⇒ alpha 线上**永久取不到**。
* **但有 fallback**：`:86-89` 在拿不到 `marked` 时退化到 `dock?.firstElementChild` ⇒
  **胶囊仍会渲染**，只是落点从「官方统计行」变成「dock 首个子节点」⇒ **间距 / 对齐大概率失真**，
  且我方 `order: 1` 现在与官方新的 `usage` 胶囊**同 order**（`src/client/index.ts:239-244`），
  同 order 下的渲染次序**不再确定**。

## 7) 方法论沉淀（供后续跟版复用）

1. **结构性锚点变化 ≠ 规则失效。** 本轮我把「官方 CSS 把锚点从 `[data-disclosure-row]` 换到新增的
   `[data-disclosure-header]`」判成回归，**只读源码就下了结论**；真浏览器实测证明**不成立**：
   `.row` 在无 accessory 时与 `.header` **同盒**（`flex:1 1 auto` + 固定 `height`）且自带
   `position: relative` ⇒ 绘制在父背景之上，我方涂层完整盖住官方纯色底，
   带上 `elementFromPoint` 命中的就是 `.row`。**该判定已撤回**（详见 §9）。
   ⇒ **这类判定必须真机 / 真 DOM 实测**，「官方换了锚点」只说明官方落点变了。
2. **官方 upgrade-guide 的目录名 ≠ 引入版本。** 实测：`docs/upgrade-guide/v0.2.1-alpha.1/` 下 19 份
   guide 在 **alpha.1 tag 上 0 份**、只在 alpha.2 上存在；而 `v0.2.0-rc.2/` 那 5 份里
   **alpha.1 上已有 4 份**（第 5 份 `bundled-python-tests` 是 alpha.2 才补的）。
   **反证**：`v0.2.0-rc.2/remove-runtime-invariants` 声称「v0.2.0-rc.2 提供 `dsh-invariants`、
   **下一版本**不再发布」，而实测 `dsh-invariants` 引用数 rc.1=177 / rc.2=177 / alpha.1=18 / alpha.2=18、
   `./invariant` 导出数 rc.1=38 / rc.2=38 / alpha.1=**0** / alpha.2=**0** ⇒ 若目录名 = 「已含此变更的版本」
   则原文自相矛盾。⇒ **目录名标的是「宣布变更的那个 release」，实际生效点是下一个 tag。**
3. **`SESSION_FORMAT_VERSION` 要连注释一起看。** 本轮值同行号同、**但文件 hash 三个 tag 各异**——
   差异全在常量上方的注释块（判定口径由「必须 bump」改成「老读取器能安全拒绝即可保留」）。
   只 grep 值会漏掉这条机制性改动：**官方今后可能更频繁地在不升版本号的前提下改会话结构**。
4. **同名命中要先分「服务」与「行 id」。** alpha.2 剩余的 `webRuntime` 命中共 6 个文件：2 个测试
   （`apps/web/tests/scaffold.ts`、`packages/bundle/web-app/tests/web-app.spec.ts` —— 指**行 id**
   `web-runtime` 而非服务）、2 份 `.agents` 笔记、2 份 guide 文本 ⇒ **无任何一处是 `provide` 点**。
5. **`git grep -F` 会前缀过匹配**（`data-side` 实测 359 vs 47）⇒ 一律加右边界断言。
6. **`git diff` 的上下文行号不是文件行号** —— 引用行号一律用 `git show <tag>:<path>` 重取。
7. **符号面判定用 TypeScript 编译器 API，不要用正则/grep。** 正则方案本轮误报 8 个假阴性

  `.header` 与 `.row` **盒完全重合**（同 1280×24 @ top 0）、吸顶带上 `elementFromPoint` 命中
