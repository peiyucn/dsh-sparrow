# 00 · 插件概览 — dsh-archive-manage

> 2026-10-28 重写为**单一现状描述**（旧版仍写「侧边栏 footer + 弹窗」「三档操作」「不实现取消归档」，
> 与实现相反）。详细机制见 07/12/16，迁移记录见 08/09/10/11/13/14/15。

## 定位

集中管理已归档的 DSH 会话：官方「轻归档」只负责把会话从列表收起，本插件提供**归档后的可见性与可回收性**
——列出归档会话、恢复归档、移入回收站、从回收站恢复、彻底删除。

## 入口

* 主面板页面（`main` 槽）+ 侧边栏面板列表中的一项（`sidebar.panellist`），经 `ctx.inject(['layout'])` 可选
  fork 注册（宿主没有 `layout` 时整体不挂）。
* **没有**侧边栏 footer 按钮，也没有弹窗：旧入口已随 spec 16 替换。

## 操作语义（现状）

* **查看**：列出归档会话（含 live / running 状态与子代理折叠标题）。
* **恢复（unarchive）**：把会话放回原工作区，已有路由（spec 12/16）。
* **移入回收站**：会话目录移入 `~/.dsh/.sessions-trash`，可整体/逐个恢复（spec 12 `trash-whole-subtree`）。
* **回收站恢复**：`/trash-restore-all` 等路由；旧格式（无 sidecar）按「只列出 / 可删除」收纳（spec 13/14）。
* **彻底删除**：强确认后删除回收站内容，不可恢复。

## 边界

* 只碰会话目录与回收站目录；附件 / 存储域 / 凭据一律走官方服务。
* 不 monkey-patch 核心、不替换会话模型。
* 写通道尽量复用官方：`WorkspaceRegistry` 私有写通道、`sessionPersistence.locate`、存储域（逐条登记在
  `docs/private-seams.md`）。
* 官方原生支持归档会话管理后退役。

## 已知限制

* 仍在 dsh 运行中驻留的会话无法移入回收站，需下次启动后操作。
* 服务端 7 个硬依赖若缺失，当前 `assertCapabilities` 未接入 apply（重构待办），失败会在首次调用时暴露。
