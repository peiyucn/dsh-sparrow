# 11 — 面板刷新不闪烁：首屏 loading 与静默刷新分离

> 状态：已实现（2026-09-08）。owner 实测反馈：移入回收站后面板「闪一下」，其它按钮同因。

## 现象

任何写操作（移入回收站 / 彻底删除 / 还原 / 取消归档 / 归档游离会话）完成后，
面板内容会闪一下——整块列表先消失、变成「加载中…」转圈，再重新出现。

## 根因

`refresh()` 无条件把 `loading` 置真，而渲染层用 `loading` 把整个内容区替换成整页 loading：

```tsx
const refresh = async () => {
  const seq = ++refreshSeqRef.current
  setLoading(true)          // ← 每次刷新都置真
  ...
}
// 渲染
{loading ? <整页 loading /> : <> 列表 … </>}
```

于是**任何**刷新（不只是首屏）都会让列表**卸载 → 重新挂载**：DOM 被丢弃重建，
视觉上就是闪烁。写操作后必然触发一次刷新，所以每个按钮都闪。

首屏确实需要整页 loading（四个请求都落定前没有数据可显示），但**已有数据时的刷新不需要**——
它只是把新数据换上去，React 本来就能增量协调。

## 设计

把「首屏加载」与「后台刷新」拆成两个状态：

| 状态 | 含义 | 渲染 |
| :--- | :--- | :--- |
| `loading` | 首屏（还没有任何数据） | 整页 loading（不变） |
| `refreshing` | 已有数据的刷新 | 列表**保持挂载**，静默换数据 |

- 判定依据 `loadedRef`（首屏是否成功落过数据）：成功一次后所有刷新都走 `refreshing`；
  首屏失败（如 host 未就绪）仍走整页 loading，重试语义不变。
- 面板关掉再打开同样不再转圈：数据已在，先显示旧内容再静默更新（感知更快）。
- **连点防护不变**：所有操作按钮的 `disabled` 与入口锁都从 `loading` 扩为
  `loading || refreshing`，刷新在途期间仍然禁点（AGENTS 审计⑨）。
- 无障碍：内容区加 `aria-busy={refreshing}`，屏幕阅读器仍能感知刷新在途。
- 不额外加可视指示器：确认框自身在操作期间显示「正在移入回收站…」等文案，
  刷新紧随其后完成，再加转圈反而制造第二个闪烁源。

## 涉及文件

- `src/client/ArchiveDock.tsx`：新增 `refreshing` 状态与 `loadedRef`；`refresh()` 分流；
  按钮禁用判据并入 `refreshing`。

## 验证

- `npm run verify` 全绿（122 tests）；客户端产物重新打包。
- 行为：写操作后列表不卸载（无闪烁），计数与行内容静默更新。

## 风险

- 若某次刷新失败，列表保留旧数据 + 顶部错误条（原有语义）；不会因为不卸载而丢数据。
- 首屏失败的判定仍是「没有成功数据」，与改动前一致。
