# 05 · 游离会话管理（stray sessions）

> 定案 2026-09-01（owner 拍板直接实现）。背景：官方 @ 候选 = 持久化全量清单，不过滤归档标记（见 AGENTS.md「设计依据」）；既不挂工作区、也不在归档集的会话（游离会话）侧边栏不显示、无法归档，会永久钉在 @ 列表里。

## 识别：三差集（全部公开 seam，无需新特例）

```
游离会话 := 持久化清单有（sessionPersistence.list()）
         ∧ 不在归档集（workspace 域 archivedSessionIds）
         ∧ 不挂任何工作区（workspaceRegistry.list() 每个 workspace.sessionIds 都不含）
```

三个清单插件全部已在读，识别是纯函数（`archive.ts / straySessionIds`，有单测）。

## 处置两级

1. **空白游离**（投影行 `sessionListMetadata.blank === true` 或 `sessionStats.turns === 0`）：
   - 面板里打「空白会话」角标、显示创建龄；
   - 删除确认**简化**：只需确认弹窗（不要求输入标题——空白会话无标题可输，0 轮无内容可保护）。
2. **非空白游离**：只列不自动处理，走与归档区相同的标题强确认；绝不自动删除任何会话。

> 硬约束：**不做启动自动删除**。所有动作都是用户在面板里手动触发的备份 / 删除。

## 动作复用

- 备份 / 删除直接复用现有链路（`POST /api/archive-manage/backup|delete`）：仅把入口校验从「必须已归档」放宽为「已归档 ∨ 游离」。链路其余部分对游离会话天然兼容：
  - `removeArchivedId`（不在归档集，no-op）、`detachWorkspaceAccounting`（不挂工作区，no-op）；
  - subagent 连带处理、投影失效、`api-session/removed` 事件照常执行。
- 备份后恢复：会话回到「游离」态，重新出现在游离区（行为自洽）。

## UI

- 归档面板新增「游离会话」区块（仅当存在游离会话时渲染），行内：标题（空白显示会话 id）/ 创建龄 / 空白角标 / 备份 / 删除。
- 空白删除的确认弹窗无输入框；非空白删除与归档区相同（输入完整标题）。

## 验收标准

- [ ] `straySessionIds` 三差集单测：持久化有∨无、归档∨未归档、挂工作区∨不挂，8 组合全覆盖；
- [ ] `parseBlankProjection` 单测：blank 标记、仅 turns=0、非空白、行缺失 / 形状异常（返回 undefined 按非空白对待）；
- [ ] 游离会话不出现在归档区，归档会话不出现在游离区（互斥）；
- [ ] 空白游离删除无需输入标题；非空白游离删除仍须输入标题；
- [ ] 非空白游离**绝不**被自动删除（无自动清扫路径）；
- [ ] 备份游离会话后 @ 列表即时移除、可从备份区恢复；
- [ ] `npm run verify` 全绿。
