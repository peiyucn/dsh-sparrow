# 08 · 事务性归档管理（父子树 + 只操作父会话）

> 草案 2026-09-02，待 owner 评审后开工。

## 背景（2026-09-02 实测发现）

1. **父子关系完全可识别**：会话 header 有 `parentSession` + `origin: 'subagent'`（+ `delegationDepth`），`sessionPersistence.list()` 即可重建整棵树（已实测扫描本机会话树）；插件 trash sidecar 也已记录父子副本。
2. **子会话物理上独立**：与父会话同 project 目录平级、独立目录；官方归档动作（`archiveSession`）只动父 id，不动子。
3. 已知问题：
   - **所有 subagent 子会话命中三差集「游离」判定**，全部混入 stray 区（实测唯一一条 stray 就是父还活着的子会话）。
   - restore 操作本身流畅、无 bug（owner 复核 2026-09-02 撤销该疑点）；真正的缺口是**父子无联动**——所有操作只管了父，子会话状态不随父变化。
   - 官方 @ 候选 / 工作区树对 `archivedSessionIds` 的消费行为需按当前 master 复核（决定「归档父时子随之隐藏」是否自动成立）。

## 目标

- 面板归档区改为**树形结构**：父会话为节点，子会话缩进挂在父下；子节点只读展示，不单独操作。
- **只操作父会话**：归档 / 取消归档 / 移入回收站 / 删除 / 还原全部以父为单位，子会话随父走（事务性归档管理）。
- 子会话永不单独出现在 stray 区与归档区根级。
- 建立父子联动（状态不变量：子镜像父）。

## 非目标

- 不支持单独操作某个子会话（无子会话独立归档/删除）。
- 不改动官方 UI 的归档入口与官方 children 展示。

## 核心设计

### 1. 树构建（host）

- 运行时由 `storedHeaders()` 全量 header 构建 parent → children 映射（`origin === 'subagent'` 且父在清单内）。
- `/list` 返回树形载荷（父条目 + children 数组），客户端直接渲染，不自行拼树。
- restore 复用 trash sidecar 的子会话清单。

### 2. 操作语义（事务性，逐项定义）

| 操作 | 父 | 子 |
| :--- | :--- | :--- |
| 归档（入口见开放问题 3） | 进归档集 | 一并进归档集（同一 enqueueOperation 链内原子） |
| 取消归档 | 出归档集 + `api-session/added`（已有 alpha.2 改动） | 一并出归档集 |
| 移入回收站 | 现状 | 现状（目录连带 + sidecar + 回滚） |
| 删除 | 现状 | 现状 |
| 还原 | 现状 | 现状 + 修复「拿不到」（实施第一步复现定位） |

**状态不变量**：归档状态以父为准，子永远镜像父——`archivedSessionIds` 同时含父子 id；清扫兜底对齐（官方只动父的操作也不会打破不变量）。

### 2.5 事件驱动一致性（对齐 + hold 实时化）

- **父子归档对齐**：监听官方 `domain/changed`（workspace 域 put）→ 比对归档集与全量 header 的父子关系 → 经官方写通道（现有 enqueueOperation/setState 特例）把子会话对齐进/出归档集（幂等）。官方 feed 层同款监听（workspace-controller/feed.ts，已查证）。兜底：启动清扫 + 面板打开惰性对齐。
- **hold 实时化（通知侧）**：监听官方 `session/created` / `session/disposed`（会话进入/离开 live store 时发出，core/session，已查证）→ 实时刷新面板条目 live 标记；用户关闭会话后「进回收站」即时解锁，无需刷新或重启。**主动释放仍无公开 API**（SessionStore 无 remove/close，卸载只有 fiber 销毁私有路径）——守卫保留，仅把报错文案从「请下次启动 dsh 后重试」改为「请先关闭该会话（或停止生成）再重试」。
- 两个监听均为公开事件，不新增私有 seam。

### 2.6 子会话标题（2026-09-02 实测问题）

- 现象：子会话在面板显示为父会话的委派指令文本（官方 UI 副行文本）。
- 根因：trash/delete 流程对每个子会话执行投影缓存失效；还原后 dsh 不重建（子未打开）→ `readTitleSnapshots` 冷读回退 = 首条用户消息 = 委派指令文本。
- 修复：**trash 不失效投影行**（移动期间会话身份未变，行依然有效）；delete 保持失效；树 UI 子行显示自身标题（投影可用时），无投影时以委派文本作副行展示（父标题为上下文）。

### 3. stray 区修正

- 三差集排除 `origin === 'subagent'` 且父在持久化中的会话（子会话不是游离）。
- 父不存在的孤儿子会话：不列 stray，由启动清扫处理（策略见开放问题 1）。

### 4. 启动清扫增强（幂等对齐）

- 「父已归档而子未归档」→ 子补进归档集；「父未归档而子已归档」→ 子移出归档集（历史脏数据）。
- 与官方 UI 归档动作互操作安全：官方只动父，清扫把子对齐。

### 5. UI

- 归档区树形：父行（标题/状态/操作按钮）+ 子行（缩进、只读、显示标题/深度）。
- live 分组保持现状：父或任一子被 dsh 占用 → 整组置灰并拦截操作（现状已按父拦截；子 live 也拦）。
- 双语 locale 补树形相关文案。
- stray 区与 trash 区结构不变（trash 条目可选展开子清单）。

## 开放问题

1. **官方 @ 候选过滤 archivedSessionIds 的行为**：查证后决定「归档父后子会话在官方列表的隐藏」是否自动成立。

> 已决议（2026-09-02）：归档入口保持官方菜单；面板「归档」按钮只补游离会话（官方菜单覆盖不到 stray）；父子归档对齐由 `domain/changed` 事件驱动，不做第二个归档入口、不包装官方函数；restore 无 bug（owner 复核撤销疑点），不设 restore 专项；**孤儿子会话删除启动自动删除，改为「树中按顶层会话对待 + 手动操作」**（零用户，无存量兼容包袱）。

## 验收标准

- [ ] `/list` 返回树形结构；归档区渲染父+子缩进树
- [ ] 子会话不出现在 stray 区（有父）与归档区根级（只挂父下）
- [ ] 取消归档：父子一并出归档集，父经 `api-session/added` 即时回列表、无需刷新
- [ ] trash / delete / restore 以父为单位，子随同（机制沿用现状，本次只补父子联动）
- [ ] 启动清扫对齐父→子归档状态（幂等，连续重启两次结果一致）
- [ ] 全部单测 + `npm run verify` 全绿 + 双语文案齐全
- [ ] 与官方 UI 归档动作互操作无冲突（官方归档父后，面板与清扫保持一致）
- [ ] 官方菜单归档父后，子会话**事件驱动**实时进归档集；官方取消归档同理
- [ ] 关闭会话（fiber 销毁）后面板 live 标记实时清除，无需刷新/重启
- [ ] hold 报错文案改为「请先关闭该会话（或停止生成）再重试」
