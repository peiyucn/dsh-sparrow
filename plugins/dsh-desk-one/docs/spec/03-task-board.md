# 03 · 任务板 — dsh-desk-one

> 状态：**已实施（S1，2026-11-07）**。数据层 / host 与客户端看板均已落地；实施记录见文末。配套：`01-object-model.md`（对象模型）、`02-modules.md`（模块需求）。
> 任务板与便签墙是同一套对象模型、两种组织形态：便签是自由坐标的墙面，任务是**列 + 列内顺序**的板。

## 已确认决策

| # | 决策 | 取值 |
| :-- | :--- | :--- |
| 1 | 泳道 | **固定三列**：待办 / 进行中 / 完成（绑定 `task.status`：`todo` / `doing` / `done`）；可自定义泳道后置 |
| 2 | 板数 | **单板**：v1 只有一个默认看板；数据层预留 `project` 与 `projectId`，多板只做 UI 切换 |
| 3 | 排序 | 列内**手动拖拽排序**（`order`）；另提供按**创建时间 / 截止日期**排序的视图切换 |
| 4 | 完成列 | 完成的卡片留在「完成」列，可折叠；卡片可**存档**，界面有**存档入口**（查看 / 恢复 / 彻底删除）。命名已定：统一用「存档」，避免与宿主「会话归档」撞词|

## 定位与边界

* 任务板是 Desk One 的第二个落地功能，也是「任务」对象的第一种视图；以后总览、日程都可能复用同一批任务。
* 与便签墙的差异：便签**位置自由**（x/y/尺寸/层级），任务**按列推进**（status + 列内 order）；不做自由摆放。
* 与总览的关系：S1 不联动（总览仍空白待设计）。

## 数据模型（在 01 基础上）

```ts
interface TaskPayload {
  status: 'todo' | 'doing' | 'done'          // 三列一一对应；cancelled 预留、不在板上出现
  due?: { date?: string; timezone?: string }  // 只到天，v1 不做时刻
  order: number                               // 未分组时 = 泳道块序号；分组内 = 组内顺序（与分组块共享泳道序列）
  groupId?: string                            // 所属分组 id；缺省未分组
  sessionIds: string[]                        // 关联的 DSH 会话 id（可多个；会话标题/状态实时解析）
  color?: NoteColor                           // 卡片颜色条，复用便签的 5 色板
  archived: boolean                           // 存档后从板上消失，进存档视图
  projectId?: string                          // 预留：多板后启用
  laneId?: string                             // 预留：自定义泳道后启用（v1 恒为空）
}
```

* 顶层字段沿用 Node 基础字段：`title`（必填）、`body`（描述，v1 不在卡片上展示）、`tags`、`createdAt`、`updatedAt`、`revision`、`source`。
* 关系：`belongsTo` 边（task → project）预留；v1 不写边。
* 存储：同一 `desk_one` 域的 `nodes` 表，按 `kind` 判别；组是独立记录：`{ kind: 'group', name, status, order, archived, revision }`。改名 / 排序是单条 group patch，删组时 host 把成员任务的 `groupId` 解绑。
* 一致性：任务只能属于**同一泳道**的分组；跨列移动卡片且未指定目标组时自动移出分组。

## 视图与交互

### 布局

* 三列等宽横向排列，**不出横向滚动条**；容器宽度低于阈值（720px）时三列收成「计数列」——只显示列名与各分组条数，避免把面板挤成横向滚动。
* 列内 / 存档列表可纵向滚动；内容超出时显示**细滚动条**（`scrollbar-width: thin` + 稳定 gutter），不再靠压缩卡片来容纳内容。
* 列头：列名 + 计数 + 该列「＋」；点击在**该列**新建卡片并直接进入标题编辑。
* 完成列支持**折叠**（折叠后只显示列头与计数）。

### 卡片

* 卡片分视图态 / 编辑态：视图态标题与描述是普通文本（自动换行），单击字段进入编辑、失焦保存；文本框只在编辑时存在，因此平时**整张卡片都是拖拽区**。颜色入口是**叠放色卡**（当前颜色在最上、其它颜色从后面露出），点开五色板直选（点外部 / Esc 关闭）。截止日期用**日历图标 + 日期**表达：未设置时只有日历图标（不再显示「设置截止」文字），设置后图标旁显示日期，再点可修改；图标让裸日期不会被误读成创建时间。
* 交互用 5px 位移阈值区分：未超过阈值 = 点击（进入编辑），超过 = 拖拽；拖拽结束后抑制紧随的 click，避免误进编辑。
* 截止日期只剩一天时卡片带**琥珀色描边**提醒；逾期日期标红。
* 整张卡片都是拖拽区（输入框 / 按钮除外），不再有单独的抓手。
* 悬停出现操作：**存档**（仅完成列卡片可见）、**删除**（二次确认，沿用便签的「再点一次」）。

### 拖拽

* 按住卡片任意位置开始拖：生成一张跟随鼠标的**幽灵卡**，原卡变淡；泳道 / 分组在指针下方高亮。
* 放下：跨列改 `status`，列内 / 分组内改 `order`，拖进分组改 `group`；本地先更新、抬手落库，失败提示并重拉。
* **统一块序列**：未分组卡片与分组块是同一条手动序列中的 block，分组可插到任意两张卡之间（卡片也可落到两个分组之间）；块的 `order` 就是序列下标，结构变化时整列重编号（旧数据在首次拖动前按「卡片在前、分组在后」兜底）。
* 拖动中目标泳道高亮、悬停的分组整体高亮，并在目标容器内画出蓝色**插入线**（块之间 / 末尾），明确松手后的落点。
* 整组拖动时插入序号**排除被拖分组自身**（否则向下拖会差一位）；插入线也按排除后的序号渲染。拖拽期间锁住文本选择，松手恢复。
* 拖到无效位置（泳道外 / Esc 取消）：幽灵卡**飞回原位置**，原卡恢复，不产生改动。
* 层级不需要（列布局没有叠放），复用的是「跟手 + 落库 + 写队列」这套。

### 分组（一层）

* 每个泳道内可建一层分组：列出「未分组」卡片，再按存储顺序列出分组；组卡片缩进并带分组名。
* 分组头两行：第一行六点拖动手柄 + 折叠箭头 + 名称（可双击改名、超长省略），第二行计数；右侧操作图标跨两行。操作统一为小图标：组内「＋新建」、完成列多一个**整组存档**、垃圾桶删除（二次确认，组内任务回未分组）。
* 分组容器有明确边框 / 底色 / 内边距，与未分组卡片区分；组内不再画缩进竖线 / 留空，卡片直接铺满。
* 深色 / 浅色主题都使用宿主 token；空分组显示「拖到这里或双击新建」的落点，并一直保留到显式删除。
* 成员关系以任务 `groupId` 为唯一真值；分组名 / 泳道 / 顺序存宿主，折叠状态是纯界面偏好。
* 整组拖动与卡片同一套指针手势：按住分组头（输入框 / 按钮除外）生成整组幽灵（头 + 卡片）跟手；同泳道放下调整分组顺序，拖到其它泳道直接连同卡片级联新状态，无确认条与撤销条；无效落点飞回原处。

### 会话关联（S1.5，多对多）

* 卡片可关联 0..N 个 DSH 会话；同一会话可服务多张卡。只存不透明 `sessionId`，标题 / 运行状态由客户端从宿主 `sessions` + `workspaces` 服务实时解析，**不落库**。
* 卡片会话行：每个 chip = 状态颜色 + 会话标题（点击打开会话）+ 移除；**`@` 入口单独占一行**（位于 chips 下方，不混在 chip 行里），打开多选选择器（搜索、运行中优先）。**会话范围与输入框 `@` 相同**（宿主 session 列表，含子代理会话）；已归档仍可关联，仅已从列表移除的不可用项禁用。
* 选择器通过 `react-dom` portal 挂到 `document.body`，按锚点 fixed 定位、视口内翻转/夹取（`useAnchoredPanel`），因此泳道滚动与卡片宽度都不会裁切列表。
* 状态表达：可用会话 = 绿色系（`data-state="running"` 追加一圈低对比旋转绿环，`idle` 为静态绿边；`prefers-reduced-motion` 下停转）；已归档 / 列表已移除 = 中性灰实线 + tooltip，不再用虚线。选择器行同样用绿色 / 灰色区分状态，不再绘制状态圆点。会话标题 / 描述**不覆盖**卡片自身文字。
* 三个客户端服务（`sessions` / `workspaces` / `uiWorkspace`）走可选依赖 fork：缺任一服务时整块功能隐藏，卡片仍正常可用。
* 边界：会话删除 / 归档后关联保留并以不可用态展示，不自动清空；宿主列表尚未就绪时显示 loading 态。

### 排序视图

* 页头排序下拉：**手动排序**（默认，拖拽顺序）/ **按创建时间** / **按截止日期**，当前项带勾选；外点或 Esc 关闭，上下键切换。
* 非手动排序只影响该视图的展示，不修改 `order`；切回手动排序恢复用户手排顺序。

### 存档

* 只有**完成列**的卡片 / 分组可以存档；存后从板上消失（`archived: true`），进任务板存档视图。
* 存档入口与便签墙同构：页头「存档（N）」动作，进入存档视图；任务条目可恢复（回到「完成」列）或彻底删除；**分组条目**显示组名 / 条数 / 泳道，恢复会把整组与卡片一起拉回，彻底删除则连卡片一起删除（二次确认）。
* `archived` 状态持久化，刷新 / 重启后保持。

### REST 与 Agent 工具

| 路由 | 方法 | 作用 |
| :--- | :--- | :--- |
| `/api/desk-one/tasks` | GET | 列任务（默认不含存档） |
| `/api/desk-one/tasks` | POST | 新建任务（status / 列内位置） |
| `/api/desk-one/tasks/update` | POST | 改标题 / 颜色 / 截止 / 状态 / order / archived（revision 乐观并发） |
| `/api/desk-one/tasks/delete` | POST | 彻底删除 |
| `/api/desk-one/groups` | GET | 列分组（含空分组） |
| `/api/desk-one/groups` | POST | 新建分组 |
| `/api/desk-one/groups/update` | POST | 改名 / 改组顺序 |
| `/api/desk-one/groups/move` | POST | 整组移动（跨泳道时级联成员状态） |
| `/api/desk-one/groups/archive` | POST | 整组存档 / 恢复（级联组内卡片） |
| `/api/desk-one/groups/delete` | POST | 删除分组（成员回未分组） |

工具：`desk_task_add`、`desk_task_list`、`desk_task_update`（含状态与排序）、`desk_task_complete`、`desk_task_archive`；分组：`desk_group_add`、`desk_group_list`、`desk_group_update`、`desk_group_move`、`desk_group_archive`、`desk_group_delete`。

## 验收标准

* 三列可见；列头「＋」或泳道空白处双击新建卡片，草稿可直接输入标题；列头计数正确。
* 整卡拖拽带**直立**跟手幽灵卡；跨列改状态、泳道块序列 / 分组内改顺序、拖入 / 拖出分组，刷新 / 重启后保持；无效落点飞回原位；失败有提示。
* **统一块序列**：分组块与未分组卡片可互相穿插排序（分组拖到两张卡之间、卡片落到两个分组之间），刷新后保持；旧数据在首次拖动前按「卡片在前、分组在后」显示。
* 窄窗口（< 720px）下三列收成计数列，不出现横向滚动条；分组可拖动手柄调整顺序且刷新后保持。
* 标题 / 描述自动换行，卡片随内容变高；只剩一天截止的卡片有琥珀色描边。
* 分组可新建 / 改名 / 折叠 / 拖动排序 / 删除；空分组刷新后仍存在；删除分组后组内卡片回到未分组；整组拖动跟手、跨列直接移动；完成列分组可整组存档，存档视图出现分组条目，恢复 / 彻底删除均按组级联卡片。
* 按创建时间 / 截止日期排序视图正确；切回手动排序恢复手排顺序。
* 完成列可折叠；只有完成列卡片有存档入口；存档后从板上消失、出现在存档视图，恢复后回到完成列。
* 颜色、截止日期（含逾期标记）正确显示与保存。
* 会话关联支持多对多；chip 颜色随会话运行状态实时变化，running 有旋转绿环（减弱动态效果下静止）；点击 chip 打开对应会话；已归档 / 不可用会话以中性灰实线降级；宿主缺会话服务时不报错、不显示 @ 入口。
* agent 工具与界面读写同一批任务（工具建的任务出现在板上）。
* `npm run verify` 全绿；文档与守卫同步。

## 非目标（v1 不做）

* 多板 / 项目切换、自定义泳道、WIP 限制、优先级、标签、子任务、详情抽屉、任务耗时统计、与总览 / 日程的联动。
* 拖拽的键盘替代操作（v1 仅指针拖拽，卡片操作按钮均可键盘聚焦）。

## 实施顺序

1. **spec 评审通过**（本文）。
2. 数据层：schema task 分支 + 模型纯函数（创建 / 补丁 / 顺序重排）+ 单测。
3. host：REST 路由 + 工具 + 写队列复用。
4. client：三列板 + 卡片 + 拖拽 + 排序视图 + 存档视图。
5. 文档 / 测试 / 守卫；宿主侧改动攒一批后请 owner 重启验收。
