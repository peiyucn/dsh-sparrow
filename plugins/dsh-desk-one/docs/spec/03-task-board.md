# 03 · 任务板 — dsh-desk-one

> 状态：**设计稿**（2026-11-06），评审通过后开工。配套：`01-object-model.md`（对象模型）、`02-modules.md`（模块需求）。
> 任务板与便签墙是同一套对象模型、两种组织形态：便签是自由坐标的墙面，任务是**列 + 列内顺序**的板。

## 已确认决策

| # | 决策 | 取值 |
| :-- | :--- | :--- |
| 1 | 泳道 | **固定三列**：待办 / 进行中 / 完成（绑定 `task.status`：`todo` / `doing` / `done`）；可自定义泳道后置 |
| 2 | 板数 | **单板**：v1 只有一个默认看板；数据层预留 `project` 与 `projectId`，多板只做 UI 切换 |
| 3 | 排序 | 列内**手动拖拽排序**（`order`）；另提供按**创建时间 / 截止日期**排序的视图切换 |
| 4 | 完成列 | 完成的卡片留在「完成」列，可折叠；卡片可**归档**，界面有**归档入口**（查看 / 恢复 / 彻底删除）。命名待定：为与宿主「会话归档」区分，候选改为「存档」，实现时再定 |

## 定位与边界

* 任务板是办公桌的第二个落地功能，也是「任务」对象的第一种视图；以后总览、日程都可能复用同一批任务。
* 与便签墙的差异：便签**位置自由**（x/y/尺寸/层级），任务**按列推进**（status + 列内 order）；不做自由摆放。
* 与总览的关系：S1 不联动（总览仍空白待设计）。

## 数据模型（在 01 基础上）

```ts
interface TaskPayload {
  status: 'todo' | 'doing' | 'done'          // 三列一一对应；cancelled 预留、不在板上出现
  due?: { date?: string; timezone?: string }  // 只到天，v1 不做时刻
  order: number                               // 列内手动顺序（拖拽即改，重排后写回）
  color?: NoteColor                           // 卡片颜色条，复用便签的 5 色板
  archived: boolean                           // 归档后从板上消失，进归档视图
  projectId?: string                          // 预留：多板后启用
  laneId?: string                             // 预留：自定义泳道后启用（v1 恒为空）
}
```

* 顶层字段沿用 Node 基础字段：`title`（必填）、`body`（描述，v1 不在卡片上展示）、`tags`、`createdAt`、`updatedAt`、`revision`、`source`。
* 关系：`belongsTo` 边（task → project）预留；v1 不写边。
* 存储：同一 `desk_one` 域的 `nodes` 表，按 `kind: 'task'` 判别；zod schema 增加 task 分支（旧便签记录不受影响）。

## 视图与交互

### 布局

* 三列等宽横向排列；窄屏横向滚动（列布局的标准行为，与便签墙「不出屏」不同）。
* 列头：列名 + 计数 + 该列「＋」；点击在**该列**新建卡片并直接进入标题编辑。
* 完成列支持**折叠**（折叠后只显示列头与计数）。

### 卡片

* 卡片面：标题（行内编辑，失焦保存）+ 颜色条 + 截止日期（有则显示，逾期标红点）。
* 点卡片空白处不打开详情（v1 无详情抽屉）；标题、颜色、截止日期都在卡片上直接改。
* 卡片右侧悬停出现操作：**归档**、**删除**（删除二次确认沿用便签的「再点一次」模式）。

### 拖拽

* 跨列拖动 = 改状态（`status` 随落点列变化）；列内拖动 = 改顺序（重排 `order`）。
* 拖到空列：显示整列落点高亮；放下后卡片进该列。
* 与便签墙一致：本地先移动、抬手落库；失败提示并重拉。
* 层级不需要（列布局没有叠放），复用的是「跟手 + 落库 + 写队列」这套。

### 排序视图

* 列头右侧菜单：**手动排序**（默认，拖拽顺序）/ **按创建时间** / **按截止日期**。
* 非手动排序只影响该视图的展示，不修改 `order`；切回手动排序恢复用户手排顺序。

### 归档

* 卡片「归档」后从板上消失（`archived: true`），进任务板归档视图。
* 归档入口与便签墙同构：板顶部右侧「归档（N）」按钮，进入归档视图；列表显示标题、颜色点、归档日期，可**恢复**（回到「完成」列）或**彻底删除**。
* `archived` 状态持久化，刷新 / 重启后保持。

### REST 与 Agent 工具

| 路由 | 方法 | 作用 |
| :--- | :--- | :--- |
| `/api/desk-one/tasks` | GET | 列任务（默认不含归档） |
| `/api/desk-one/tasks` | POST | 新建任务（status / 列内位置） |
| `/api/desk-one/tasks/update` | POST | 改标题 / 颜色 / 截止 / 状态 / order / archived（revision 乐观并发） |
| `/api/desk-one/tasks/delete` | POST | 彻底删除 |

工具：`desk_task_add`、`desk_task_list`、`desk_task_update`（含状态与排序）、`desk_task_complete`、`desk_task_archive`。

## 验收标准

* 三列可见；新建卡片落在对应列并可直接输入标题；列头计数正确。
* 跨列拖动改状态、列内拖动改顺序，刷新 / 重启后保持；失败有提示。
* 按创建时间 / 截止日期排序视图正确；切回手动排序恢复手排顺序。
* 完成列可折叠；归档后卡片从板上消失、出现在归档视图，恢复后回到完成列。
* 颜色、截止日期（含逾期标记）正确显示与保存。
* agent 工具与界面读写同一批任务（工具建的任务出现在板上）。
* `npm run verify` 全绿；文档与守卫同步。

## 非目标（v1 不做）

* 多板 / 项目切换、自定义泳道、WIP 限制、优先级、标签、子任务、详情抽屉、任务耗时统计、与总览 / 日程的联动。
* 拖拽的键盘替代操作（v1 仅指针拖拽，卡片操作按钮均可键盘聚焦）。

## 实施顺序

1. **spec 评审通过**（本文）。
2. 数据层：schema task 分支 + 模型纯函数（创建 / 补丁 / 顺序重排）+ 单测。
3. host：REST 路由 + 工具 + 写队列复用。
4. client：三列板 + 卡片 + 拖拽 + 排序视图 + 归档视图。
5. 文档 / 测试 / 守卫；宿主侧改动攒一批后请 owner 重启验收。
