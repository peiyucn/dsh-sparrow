# 07 · 笔记（最小版）：AI 主写 + 人审阅

> 状态（2026-11-13）：**已实现**。取代此前被撤销的「笔记库 + 审阅会话」完整版。
>
> 定位：新建/维护笔记的入口与审阅视图；**AI 主写、人审阅**；不做编辑器、不依赖 git、
> 不与官方 diff 审阅桥接。

## 1. 为什么是这个形态

官方「变更请求 → 本地变更」只在 **git 检出 + 有变更** 时可用，定位是「有改动后的评论」；
笔记场景多为：① 目录由网盘同步、没有 git；② 文档相对检出没有变化时官方视图无从开始；
③ 需要「AI 主写、人发起第一轮审阅」。因此保留笔记入口与审阅视图，但不重建状态体系。

## 2. 实体与存储

| 实体 | 存哪 | 说明 |
|:--|:--|:--|
| 笔记库根 | `notebook-config` | 单个记录；指向一个已注册的 DSH 工作区目录 |
| 笔记索引 | **派生** | 扫描根的 `.md/.markdown/.txt`；标题/类型/日期/标签由 frontmatter 解析 |
| 文件身份 | `note-file` | **惰性分配**（首次审阅时）；路径 + 内容哈希；改名后按哈希重新关联 |
| 草稿箱 | `note-draft` | 每个文件身份一条；存未提交批注 |
| 审阅历史 | `review-record` | 每次提交一条：会话 id + 文件快照元信息 + 批注；不存正文快照 |

审阅状态本身不落库：提交后的批注就是对话消息，另外按「独立审阅对象」留一份历史。

## 3. 入口页（管理面，不是浏览器）

浏览与阅读交给官方右侧栏文件浏览，但**进入笔记页不会自动切走**：只有用户显式点「打开文件浏览」
（或点某一篇进入审阅）才会切到 DSH 会话页。官方目录树与官方预览我们不复制、不改动。入口页本身只做四件事：

- **新建**：hero 主按钮；note2md 工作区走 note2md，否则「创建空笔记」或「让 AI 起草」；
- **搜索**：居中搜索引擎式输入框，跨库搜索；结果行标出缺元数据 / 草稿数，点一行直接开审阅；
- **未提交**：有草稿的文件列表（点一行开审阅继续写）；
- **历史**：已提交审阅记录（批注数、关联状态、时间、可删除；占用超 2MB 红框提示）；

另提供「打开文件浏览」按钮（显式切到官方文件页）与「断开链接」；未链接时画面中央引导
「链接已有工作区 / 新建工作区…」，并注明链接/创建的是 DSH 工作区、只索引目录内 md/文本文件。

### 3.1 官方预览头部的「审阅视图」入口

- 官方文件浏览与文档预览**一行不改**；通过公开槽 `sidebar.right.tab.document.actions`
  在官方预览头部为笔记库内 md/markdown/txt 增加一个**文件+笔图标、官方 Button primary 规格（28px 方形、品牌色）**的按钮；
- 点击 = 在笔记库工作区新建审阅会话并打开审阅视图（默认源码视图）；官方预览不切模式、不注入 DOM；
- 库外文件不出现该按钮；其它工作区不受影响。
## 4. 审阅视图与入口

- **官方预览入口**（推荐路径）：官方文件浏览/文档预览完全不动；笔记库内的 md / markdown / txt
  在官方预览头部多一个「审阅视图」按钮（公开槽 `sidebar.right.tab.document.actions`，
  `canOpen` 以「文件在笔记库根内」为界）。点击 = 在笔记库工作区**新建审阅会话**并在其中打开
  我们的审阅 tab（默认源码视图）；官方预览本身不切模式、不注入 DOM，与官方行为互不影响；
- 面板入口：笔记页点一篇 → **在笔记库所属工作区新建会话**（官方 `startSession`）→ 右侧栏打开审阅 tab；
  不借用用户当前会话；
- **视图切换**：「源码」（默认）/「渲染」；
  - 源码视图：每行行号 + 源文本；选中行后浮出小按钮「批注」（沿用面板按钮样式），点击才弹
    输入框；输入框**就地渲染在选中行下方**并自动聚焦；保存的批注锚定**精确行号区间 + 引用文本**，
    高亮对应行并在行下就地显示卡片；
  - 取消联动：Esc、点输入框外、点「取消」都会关闭输入框并同时清掉选中高亮与浏览器原生选区，
    不会留下“选中了但退不出去”的灰色状态；
  - 输入框**必须留在选中行下方**（静态文档流），不得绝对定位到面板底部；结构测试有守卫；
  - 渲染视图：只读阅读；批注请在源码视图操作；
- 顶部「整篇批注」：范围为整篇，引用用标题；
- 底部固定菜单：**官方 composer 胶囊风格**——透明底、14px 图标 + 11px 文字、小圆角，hover/展开时浅底，
  两枚胶囊：`批注 N` 与 `本轮改动 +A −D`（无改动显示「持平」），点开为浮层；
- 视觉规范：入口页、审阅 tab、官方预览按钮统一用官方主题 token（品牌色 / 语义色 / 圆角 / 0.5px 边框），
  按钮尺寸与面板既有 action / mini 两档对齐，不自创第三套按钮样式。
- 「本轮改动」= tab 打开时正文 vs 当前正文（官方 DiffBlock，默认收起）；可见时静默刷新；
- 「全部提交」：按编号插入新会话输入框（不自动发送），格式：

```
【批注 1】文件：Diary/x.md
行号：42-44
> 引用原文
意见：…
```

同时写入一条 `review-record` 历史并清空草稿箱。

## 5. 官方文件浏览的复用边界

- **不动**官方文件页与文档预览：不注册地址接管、不替换渲染器、不注入 DOM；
- 复用公开槽给官方预览头部加一个按钮；文件导航继续用官方目录树（预览头部的目录树按钮）；
- 页内目录树（左树+右列表）属于本插件入口页的自身导航，不触碰官方右侧栏；

## 6. 非目标

- 不做编辑器（0→1 在对话里完成）；不依赖 git、不桥接官方 diff；
- 不做轮次快照/历史 diff/接受状态/失效锚点/随包 skill；
- 不做笔记同步/备份/加密；渲染视图不承载批注交互。

## 7. 验收标准

1. 未链接时画面中央有「链接已有工作区 / 新建工作区…」及说明；链接后能浏览与搜索；
2. 缺元数据行有徽标；目录树可展开、切换目录；列表默认 50 条且可加载更多；
3. 笔记库内 md 在官方预览头部出现「审阅视图」按钮，点击后新开审阅会话并显示源码视图；
   笔记库外的文件不出现该按钮；官方预览行为不变；
4. 点笔记 → 在库工作区新开会话并打开审阅；无工作区时给出明确提示；
5. 源码视图行号精确；选中 → 小按钮 → 行下输入框（自动聚焦）；批注高亮+就地展示；
   可切「渲染」只读视图；
6. 草稿关 tab / 重启后仍在；全部提交后输入框出现编号批注（含精确行号），历史出现记录；
7. 改文件后「本轮改动」可见；历史可删除、占用超限红框提示；
8. `npm run verify` 与根 `check` 全绿。
