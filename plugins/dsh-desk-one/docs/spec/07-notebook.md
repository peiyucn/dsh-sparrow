## 1. 定位

**笔记 = AI 写 + 人审阅，不做 markdown 编辑器。**
0→1 在对话里完成（用户只出摘要/提纲/要求），之后通过「审阅会话」（见 `09-review-session.md`）无限迭代修改。
笔记页负责库浏览、索引、搜索、行动性统计与 0→1 入口；审阅状态全部由会话承载。


**笔记页不是文件管理器，是本地笔记库的「入口 + 检索 + 审阅工作台」。**

产品姿态是 **AI 写、人审阅**：模型产出 markdown，人在右侧栏审阅并留批注，AI 按批注改。
因此"插件不提供编辑能力"不是缺陷，而是定位——审阅者本来就不该直接改稿。

与其它页的边界：

| 页 | 职责 |
| :--- | :--- |
| 便签 | 快速捕获（可编辑的轻量卡片，Desk One 自有对象） |
| 任务 | 推进与完成（看板） |
| 笔记 | 长文档：浏览 + 检索 + 批注审阅（**只读**） |
| 日程 | 时间 |
| 会话 | AI 执行记录与归档管理 |

## 2. 数据边界与工作区约束

- **只负责本地文件夹 + `.md`**：不做同步、云端、备份、加密、版本历史，也不检测用户自己把目录放进云盘的行为。
- 不自动 `git commit` / `git push`（沿用 note2md 原则）。
- **不提供编辑能力**：一切写入经 agent + skill + 用户确认。
- 笔记正文 = 唯一真值（磁盘）；索引 = 纯派生、可重建、正文不入 `nodes` 表。
- **笔记库必须落在 DSH 工作区之下**（工作区根本身，或工作区内的子目录）。

理由：沙箱的 `workspace-write` 只授权会话工作区内的写入。把笔记库放进工作区，AI 就能用
**官方文件工具**直接写，不需要插件自带写 API、不需要 `additionalWritableRoots`、不依赖
`danger-full-access`。

**只读降级**：笔记库不在当前会话工作区内时，不禁止进入，但——

- 笔记页顶部提示：「当前会话不在笔记库所在工作区，AI 无法修改文件；切换到笔记库工作区的会话即可。」
- 浏览 / 搜索 / 批注 / 查看全部正常（这些不碰 md 文件）；
- 「交给 AI」仍可点（引用能进输入框），但**提示必须提前给**，不能等写失败才发现。

**建库 = 建工作区**：新建笔记库直接复用 DSH 自己的流程——`uiWorkspace.pickDirectory()`（系统文件夹选择器）+ `IWorkspaces.create({ path })`（注册工作区），随后把笔记库根指向该工作区。
这样「必须落在工作区之下」是**构造上成立**的，不需要用户理解沙箱或自己判断工作区边界。
用户既可以把空文件夹建成库，也可以直接指向已有的 markdown 笔记目录（DSH 工作区注册对已存在目录是幂等的）。

## 3. 层级与来源兼容

- 数据层统一为「**路径 + md**」，层数 = 路径段数，**N 级任意深度，不预设**。
- 「笔记本 / 分区 / 页面」只是视图说法与描述性语义，**不是数据结构**：
  - 恰好两层容器时（OneNote 导出、规范库）自然对上；
  - N≠2 时由视图原样渲染或经首次体验协商归位，不强制改造用户目录。
- **容器不建索引节点、无目录用户态**（无颜色 / 别名 / 排序），与 Obsidian 行为一致。
- 只索引 `.md` / `.markdown`；过滤内部目录（`.note2md/`、`.obsidian/`、`.trash/` 等）。
- 纯文本 / 代码 / PDF / Excel 不索引、不批注（浏览可走官方右侧栏预览）。

| 来源 | 接入方式 |
| :--- | :--- |
| Obsidian（文件夹 + md + YAML） | 天然接入；wikilink / 嵌入 / callout **降级显示**（原样文本），v1 不解析 |
| Trilium | 通过其 Markdown 导出接入（**不做原生连接器**，它是 DB + blob） |
| OneNote | 导出 XML → 确定性脚本转 md；**自动导出仅 Windows**（COM 上游限制） |
| 任意含 md 的文件夹 | skill 探查结构 → 对齐 / 归位协商 |

## 4. 索引（纯派生）

host 侧内存视图，**不落库**（与 `01-object-model.md` 的 View 一致：视图不落库）。

```ts
interface NoteIndexEntry {
  path: string          // 相对笔记库根，可移植
  title: string         // frontmatter.title，缺省取文件名
  type?: string         // frontmatter.type：note / meeting / daily / task …
  date?: string         // frontmatter.date
  tags: readonly string[]
  mtimeMs: number       // 用于「最近修改」与「长期未动」
  bytes: number
}
```

- 刷新：打开笔记标签 / 显式刷新 / 文件变更后重扫；有 TTL 与并发上限，重扫可被新一轮取消。
- **不夹带用户态**（折叠、排序、收藏、阅读进度都不许进索引），保证可丢弃重建。
- 笔记库根 = 用户配置项（profile 级，不写进仓库、不用绝对路径常量）。

## 5. 书架（入口页）

```
┌──────────────────────────────────────────────┐
│ 🔍 搜索全库（标题 · 正文 · 标签）             │
├──────────────────────────────────────────────┤
│ 最近修改                          [列表 | 树] │
│  · 昨天   AI五层蛋糕框架          笔记本/AI   │
│  · 3 天前 某次讨论记录            工作/会议   │
├──────────────────────────────────────────────┤
│ 待整理（有才显示）                            │
│  ⚠ 12 篇缺 frontmatter        [让 AI 补齐]    │
│  ⚠ 3 篇空笔记                 [清理]          │
└──────────────────────────────────────────────┘
```

- **搜索常驻**：输入即筛，结果按标题 / 路径 / 日期展示；正文匹配走 host 侧子串扫描（有上限）。
- **统计只做行动性的**（缺 frontmatter、空笔记），不做装饰性数字；**统计即筛选**：点数字 → 筛出列表。
- **无任何直接落盘按钮**。空库态见第 8 节。
- 点一篇笔记 → **先切回对话（`layout.selectPanel(null)`），再打开审阅 tab**；**左栏不自动收起**（官方在窄屏打开右栏时本就会收）。
  顺序不能反：`openTab` 在无 on-screen Session 时抛错（见 §11 探针结论）。

### 5.0 版式与点击语义

```
┌──────────────────────────────────────────────────┐
│ 🔍 搜索标题·路径·正文              [+ 新建笔记]   │
├──────────────────────────────────────────────────┤
│ 全部 N · 缺 frontmatter N · 空笔记 N（统计即筛选）│
├──────────────────────────────────────────────────┤
│ 最近修改                                          │
│  标题                 路径           日期  [审阅] │
└──────────────────────────────────────────────────┘
```

- 「新建笔记」= 去对话起草（0→1），不创建空文件；对话预填「帮我写一篇笔记：主题是…」，可给模板选项；
- 统计入口保留（缺 frontmatter / 空笔记），点击即筛选；
- **点击行 = 继续该文件最近一个未归档的审阅会话**；没有则新建审阅会话；
- 行尾 hover 的「审阅」旁提供 `＋`：显式新开一轮审阅；
- 会话页对审阅会话显示 `审阅` 徽标（trailing 槽位，hover 显示文件标题）。

### 5.1 空库态两级

**A. 尚未配置笔记库**

```
📓 还没有笔记库
把 DSH 工作区当成笔记库
            [ 创建 / 链接笔记库 ]
会链接一个 DSH 工作区：可以指向空文件夹，也可以指向你已有的 markdown 笔记目录。
```

「创建 / 链接笔记库」= **配置动作**（不写笔记内容）：打开 DSH 的文件夹选择器，注册为工作区，再把笔记库根指向它。
「断开链接」= 清除这条配置，回到首启状态；笔记文件本身不受影响，可反复链接/断开。

**B. 已配置目录但无 md**

```
📓 这个文件夹还没有笔记
在对话里说一句就能开始：
「把刚才的讨论整理成第一篇笔记」
「帮我写一篇今天的日记」
                [ 去对话 ]  ← 预填上述句子，不落盘
```

## 6. 审阅视图与批注

### 6.1 位置与布局

审阅是**右侧栏的自定义 tab 类型**（`ctx.sidebarRightTabs.register`），与对话并排：

```
┌────────┬───────────────────────┬──────────────────────────┐
│ 左栏   │ 对话（main）           │ 右侧栏：笔记审阅 tab      │
│        │  …                    │ ┌───────────┬──────────┐ │
│        │  > 批注1  > 批注2      │ │ 元数据/正文│ 批注列表 │ │
│        │  [输入框]              │ └───────────┴──────────┘ │
└────────┴───────────────────────┴──────────────────────────┘
```

宽度自适应：

| tab 宽度 | 布局 |
| :--- | :--- |
| ≥720px | 文档 60% / 批注 40% 并排 |
| 480–720px | 批注折叠为右侧抽屉 |
| <480px | 单栏 + 底部抽屉 |

- 官方右栏的调宽 / 全屏 / 浮动 / tab 切换全部沿用。
- 正文用公开 `MarkdownText` 渲染（官方 `MarkdownBody` 不暴露锚点），frontmatter 由我们解析后渲染成字段区。
- **本轮改动 diff**：批注创建时快照页面正文作为基线，AI 改动后审阅页用官方 `DiffBlock` 展示「基线 → 现在」；
  **默认收起**，标题行只显示 `+N -M`，点击才展开（与对话里的改动卡一致）；
  接受时把当前正文写回基线，下一轮 diff 从接受点开始（每次接受 = 一次修订的闭环）。
- 交互流：**批注 → 点「交给 AI」→ 引用出现在对话输入框 → 发送 → AI 回复 → 人继续批注 / 接受**。全程不切面板。

### 6.2 两套锚点

| 区域 | 锚点类型 | 存什么 |
| :--- | :--- | :--- |
| frontmatter | **字段锚** | 字段名（如 `title`）+ 当时原值 |
| 正文 | **引用锚** | 引文原文 + 前文约 32 字 + 后文约 32 字 + 近似位置 |

- frontmatter **可批注**（AI 写的内容都要能审），只是用字段锚，与正文分区、不串选。
- 字段锚更稳：字段名通常不变；值变了显示「原值 / 现值」对照；字段被删才 `orphaned`。
- 正文锚按**渲染后文本**定位（用户选中什么就存什么），不依赖源码偏移。
- 失效检测：打开审阅页时由 host 比对当前页面——引用锚字面匹配失败、字段被删、或页面已不存在 → 标 `orphaned`；
  顶部提示「有 N 条批注已失效」，因为它们通常是 DSH 之外的编辑造成的批量失效。
- **自动定位（不打扰用户）**：检测时先尝试自动恢复锚点——① 忽略空白差异重新匹配；
  ② 用存下来的前文/后文夹出新引文（两侧上下文都必须唯一）。成功则静默更新锚点，状态不变；
  ③ 任何不确定都放弃，宁失效不错位。
- 自动定位失败时，只有**「待处理且 AI 从未参与」**（纯人工批注、被外部改动）才标 `orphaned`：
  AI 回复后改掉锚定原文正是这条批注的答案，属正常闭环，不能判失效；`answered` / `resolved` 一律不动。
- 被误判的线程（`orphaned` 但有 AI 回复）在下次检测时自动恢复：最后发言者是 AI → `answered`，是 人 → `open`。
- 真失效的线程：顶部提示「有 N 条批注已失效」，**建议删除**（可保留作记录，不参与待处理统计）。

### 6.3 批注对象（统一对象）

```ts
kind: 'annotation'
  id / schema / createdAt / updatedAt / revision   // 统一核心字段
  path: string          // 相对笔记库根
  anchor: FieldAnchor | QuoteAnchor
  comments: { author: 'human' | 'ai'; body: string; at: string }[]
  status: 'open' | 'answered' | 'resolved' | 'orphaned'
  linkedSessionId?: string   // 产出 / 处理它的会话
```

- **不写回 md 文件**（不污染用户笔记；Obsidian 里看不到批注是预期行为）。
- 归属：Desk One 自有数据 → 第四阶段 `desk_export` 必须带上；笔记索引则不需要导出。

### 6.4 状态机与批量接受

```
open ──(交给 AI / 人补充回复)──> open ──(AI 处理并回复)──> answered ──(人点【接受】)──> resolved
  └─(自动定位失败)──> orphaned（建议删除）                              │
                                                                       │
resolved ──(人回复)──> open ──(交给 AI)──> answered ──(接受)（循环）─────┘
```

- **状态由最后一条消息决定**：AI 回复 → `answered`（等人接受）；人回复 → `open`（等工作 / 等 AI）。
  所以**没有单独的「重新打开」按钮**——回复本身就是重新打开讨论。
- **AI 只能标 `answered`；`resolved` 只能人点**（REST 路由给界面；agent 工具不暴露 `resolved`）。
- **接受 = 关闭当前这一轮 AI 反馈**：只有 `answered` 能接受；`resolved` 是终态，再回复才回到 `open`。
  这样「接受」不会对旧答复反复反悔，也不需要回滚已经落地的文件改动。
- **「全部接受」**：只作用于**当前这篇笔记**的 `answered`，绝不碰 `open`；执行后 toast「已接受 N 条 [撤销]」。
- 当前文件没有 `answered` 时按钮禁用（不隐藏，避免布局跳动）。

### 6.5 视觉语言

沿用 Desk One 现有：行级操作 = 图标按钮；整体操作 = 白色 primary 文字按钮；
状态点 open 灰 / answered 蓝 / resolved 绿 / orphaned 黄 + ⚠；批注卡 = 浅色底 + 圆角。

## 7. 首次体验（契约协商，不是固定导入）

1. **L0 入口**：已配置笔记库 → 直接进；未配置 → 首次体验。
2. **L1 分叉**：接入旧笔记，还是空库开始（空库见第 8 节）。
3. **L2 探查**（LLM 探查后复述确认，不问「你是什么格式」）：源是笔记应用导出还是文件夹 + 文件？
   文件类型分布？层级几层？有无 frontmatter？
4. **L3 契约协商**（真正要拍板的）：
   - 能否接受统一 `.md`？
   - 归位与否：要不要整理成「笔记本 / 分区」？还是原样接入？
   - 处理方式：**原地规整 / 复制成新库 / 只建索引不动原件**（决定不可逆程度）
   - 非 md / 无法无损转换的内容：只索引 / 转写摘要 / 跳过 / 保留原件
   - 同名与非法字符：沿用 `(2)` 后缀，不单独问
   - **工作区归属**：把笔记根添加为 DSH 工作区，或移进现有工作区
5. **L4 落契约**：写入 `AGENTS.md` 的 Init recap（复用 note2md `agentsmd` 机制）。
6. **L5 执行**：dry-run 计划 → 用户确认 → 分批 → 抽样验证 → 汇报失败清单。

**硬约束**：

- 不为每种新源写适配器；
- **大批量、规则固定的转换仍优先确定性脚本**（note2md 实测：agent 长流程会漂移）；
- LLM 负责形态识别、契约协商、无确定规则的逐文件规整，且必须带 dry-run + 幂等 + 可回滚。

## 8. 冷启动：第一篇笔记

**没有「新建空白笔记」**：在无编辑器模型下，空文件是死文件。第一篇一律 **AI 起草 → 人审阅批注**。

| 方式 | 用户说什么 | AI 做什么 |
| :--- | :--- | :--- |
| 从对话整理（推荐） | 「把刚才的讨论整理成笔记」 | 读当前会话上下文 → 起草 md → 落盘 → 回审阅视图 |
| 主题起草 | 「帮我写一篇关于 X 的笔记」 | 选模板（note2md daily / meeting / quick-note）→ 起草 → 落盘 |
| 导入已有 | 「接入我的 Obsidian 库」 | 走第 7 节契约协商 |

- agent 改不了插件配置，因此建库后需用户在本页选一次目录（一次性摩擦，接受）。
- 选完目录若已有 md 立即建索引；若为空则显示 5.1-B 空态。

## 9. 非目标

- 不做编辑器、不做文件树重造（复用官方右侧栏与 tree factory）。
- 不做同步 / 备份 / 加密 / 版本历史。
- 不解析 wikilink / 嵌入 / callout / Dataview。
- 不做目录用户态；v1 不做文件级用户态（收藏 / 最近打开），回避「path 即身份」。
- 不做 Trilium / Notion 原生连接器。
- 不重复官方文件工具、官方 session 搜索、官方代码 diff 评审（forge 地盘）。

## 10. 验收

- 配置笔记库后，书架能列出 md（含任意深度），过滤 `.note2md/` / `.obsidian/`；
- 搜索可按标题 / 路径 / 标签命中，正文匹配有明确上限；
- 点笔记能在右侧栏打开审阅 tab，对话保持可见；批注 →「交给 AI」→ 输入框出现引用；
- AI 标 `answered` 后，单条 ✓ 与「全部接受」都只作用于 `answered`，可撤销；
- 锚点失效显示 `orphaned` 且不静默错位；
- 笔记库不在当前工作区时显示只读提示，浏览 / 搜索 / 批注仍可用；
- `npm run verify` 全绿（含结构测试）；纯逻辑（索引扫描、锚点匹配、状态机）有测试。

| 1 | 右侧栏注册自定义审阅 tab | ✅ 可行 | `ctx.sidebarRightTabs.register({ id, kind, title, patterns? })` + 槽位 `sidebar.right.pane.tab` / `.title`（官方 `ui-sidebar-right` 公开面）。官方 `ui-plan`（builtin）与 `client-ui-forge`（extension）都用这一套；页面型 tab 可省略 `patterns`，用 `openTab(kind)` 打开 |
| 2 | `insertQuote` 从插件 client 半可达 | ✅ 可行 | `ctx.sessions.scope(sessionId)?.get('conversation')` → `conversation.input.for(scope)` → `insertQuote(text)`。`ISessions.scope` 与 `IConversation.input`（`SessionInputResolver`）都是公开契约，forge 即用此链路 |
| 3 | host 枚举工作区目录 | ✅ 可行 | 插件 host 半已有 `node:fs/promises` 先例（`host/sessions/session-files.ts`、`trash.ts`）；工作区根经 `ctx.workspaceRegistry.list()` 的 `path` 取得，无需 `workspaceFiles.list` |
| 4 | 笔记库配置界面 | ✅ 可行（复用 DSH 工作区创建流程） | **实测：本机宿主编排的是 native 后端**——`pick()`（系统文件夹对话框）可用，`list()` 被拒（「needs the browse capability」）。因此建库直接走官方链路：`ctx.get('uiWorkspace').pickDirectory()`（打开系统选择器）+ `ctx.get('workspaces').create({ path })`（注册工作区，已存在目录幂等），随后 `setRoot(workspace.path)`。宿主只提供 browse 后端时，官方 `pickDirectory()` 本身不可用，属于该部署的既有约束，不在本插件内另行兜底 |
| 5 | frontmatter 解析 | ✅ 可行（需加依赖） | 插件当前无 YAML 解析。实测 `yaml@2.9.1` 能正确解析本项目的 `title/date/type/tags`、带冒号的引号值、嵌套未知字段。**只在 host 半引入**，解析结果经 REST 把「字段名 + 值 + 原文」发给 client，客户端不打包 YAML |

### 探针带出的两条实施约束

1. **`ctx.sidebarRightTabs` / `ctx.sidebarRight` / `ctx.sessions` 按可选依赖 fork 接入**：宿主缺任一项时不注册审阅 tab、隐藏「打开审阅」入口，**不抛错**（client boot 审计把非 active entry 当致命失败）。
2. **`openTab` 需要已挂载的 session surface**：`SidebarRightController.require()` 在无 on-screen Session 时抛错。所以顺序必须是「先 `layout.selectPanel(null)` 回对话 → 再 `openTab`」，不能反过来。
3. **附带发现**：官方右栏 tab 定义可选 `priority`（`extension` / `builtin` / `fallback`）；我们用 `extension` 默认带即可，不覆盖任何官方 kind。
