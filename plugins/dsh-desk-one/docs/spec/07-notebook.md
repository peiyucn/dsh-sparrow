# 07 · 笔记（最小版）：AI 主写 + 人审阅

> 状态（2026-11-12）：**已实现**。取代此前被撤销的「笔记库 + 审阅会话」完整版（设计稿在 git 历史里）。
>
> 定位：Desk One 提供**新建/维护笔记**的入口与审阅视图；**AI 主写、人审阅**；不做编辑器、
> 不依赖 git、不新建会话、不与官方 diff 审阅桥接。

## 1. 为什么重做最小版

官方「变更请求 → 本地变更」只在 **git 检出 + 有变更** 时可用，定位是「有改动后的评论 + AI 处理」；
而笔记场景多为：① 笔记目录由网盘同步、没有 git；② 文档相对检出没有变化时官方视图无从开始；
③ 需要「AI 主写、人发起第一轮审阅」。因此保留笔记入口与审阅视图，但不重建状态体系。

## 2. 实体与存储

| 实体 | 存哪 | 说明 |
|:--|:--|:--|
| 笔记库根 | `notebook-config` 记录 | 单个记录；指向一个已注册的 DSH 工作区目录 |
| 笔记索引 | **派生**（不落库） | 扫描根目录下的 `.md/.markdown/.txt`；标题/类型/日期/标签由 frontmatter 解析 |
| 草稿箱 | `note-draft` 记录 | 每个文件一条（id 由 cwd+path 派生），存「未提交的批注」；审阅状态本身不落库 |
| 审阅状态 | 会话 | 提交后的批注就是对话消息；无锚点、无状态机、无接受步骤 |

## 3. 笔记页

- 顶部：搜索（标题/路径）＋「断开链接」；
- 统计（可点即筛选）：全部 / 缺元数据 / 空笔记；
- 列表：标题、相对路径、日期、标签；点行 = 打开该页的审阅视图；
- 未配置根时：引导「选择笔记库」——列出已注册工作区，或经官方文件夹选择器新建工作区。

## 4. 审阅视图（当前会话内）

- 入口：笔记页点一行 → 若屏幕上有会话，直接打开右侧栏「笔记审阅」tab；没有会话则提示先去开会话
  （**不创建会话、不导航**）；
- 渲染：markdown 用官方 `MarkdownText`，其余文本按纯文本；元数据单独小卡；
- 选中正文 → 弹窗写意见；引用会按原文文本大致定位行号（渲染层无源行号，故为近似值）；
- 「加到待提交」→ 立即写入草稿箱（关 tab / 重启 DSH 不丢）；
- 「全部提交」→ 按编号插入当前会话输入框（**不自动发送**）：

```
【审阅 1】文件：Diary/快速笔记/示例.md
行号：42-44
> 引用原文
意见：把这段改成…
```

- 底部条：`待提交 N 处` / `本轮改动 +N -M`；点开为浮层（不挤压正文）；
- 「本轮改动」= **tab 打开时**的正文 vs 当前正文（官方 `DisclosureRow + DiffBlock`，默认收起）；
  tab 可见时每 60s 静默刷新，隐藏时零请求；不自带 git 信息。

## 5. 非目标

- 不做编辑器（0→1 在对话里完成）；
- 不依赖 git、不读 git 状态、不桥接官方 diff 审阅；
- 不做轮次历史/接受状态/失效锚点/随包 skill；
- 不做笔记同步/备份/加密。

## 6. 验收标准

1. 未配置根时有引导，选目录后能列出 `.md/.txt`；
2. 点行能打开审阅 tab 并渲染正文；无会话时给出明确提示；
3. 选中正文能写意见并进入待提交；草稿关 tab / 重启后仍在；
4. 全部提交后输入框出现编号批注（带文件与近似行号），列表清空；
5. AI 改文件后，可见「本轮改动」diff；test / check 全绿。
