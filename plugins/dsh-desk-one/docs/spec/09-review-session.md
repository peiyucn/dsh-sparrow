# 09 · 审阅会话（Review Session）— 以会话为状态载体

> 状态（2026-11-11）：**设计稿，待评审**。评审通过后替换 `07-notebook.md` 的批注章节，
> 并按「删改清单」重构实现。
>
> 前置结论：Word 的批注/修订是**自持格式**（状态内嵌在文档里）；markdown 天然**无状态**。
> 把状态外挂到 markdown 上，必然产生锚点失效、文件改名即丢、部分接受等无解问题。
> 因此状态挂在**会话**上，文档与审阅会话是两个独立实体。

## 1. 定位

**审阅是会话的一种，不是文档的附属能力。**

```
文档（无状态）                审阅会话（有状态、有历史）
 .md 文件                    一次评审的全部上下文
 ├─ 内容真值                  ├─ 当时审的是哪篇（标题 + 路径快照）
 ├─ 历史：git                 ├─ 对话：人提了什么、AI 改了什么、人怎么回
 └─ 不承载任何审阅状态         └─ 改动：文件编辑工具卡里的逐次 diff（天然留档）
```

两者之间只有一条**指向**。指向失效（文章改名/删除）只影响「现在还能不能打开那篇」，
不影响审阅会话存在，也不需要任何锚点修复。

## 2. 实体模型

### 2.1 审阅会话本体 = DSH 会话

不新造「审阅对象」：审阅会话就是一个**新建的 DSH 会话**，因此天然拥有：

- 持久化与历史（官方会话存储）；
- 可搜索（官方 session 工具）；
- 归档 / 回收站管理（复用会话页能力）；
- 文件改动的 diff 记录（`edit`/`write` 工具卡）。

### 2.2 关联记录 `review`

Desk One 只存一条轻量关联（统一对象模型里的新 kind）：

```ts
kind: 'review'
  id: 'review_<uuid>'
  sessionId: string            // 审阅会话（外键，指向真实 DSH 会话）
  doc: {
    path: string               // 创建时的笔记库相对路径
    title: string              // 创建时的标题（路径失效时用于提示）
    hash: string               // 创建时内容指纹（用于「可能改成了哪篇」的候选提示，v1 只记录不猜）
  }
  createdAt: string
  updatedAt: string
  revision: number
```

- 一篇文档可有多次审阅 → 多条 review 指向不同会话；
- 一条会话至多一条 review（同一会话不重复挂文章，v1 约束）。

## 3. 创建审阅（发起新会话）

入口：笔记页某篇 → 「审阅」。

```
点击审阅
  → 若已有该篇的进行中审阅？不判断，直接新建（历史可查）
  → sessions.create({ cwd: 笔记库所在工作区 })   // 不依赖「当前会话」，无会话也能用
  → 写入 review 记录（doc 快照：path/title/hash）
  → 切到该会话（layout.selectPanel(null) + 官方会话导航）
  → 右侧栏打开「笔记审阅」tab，参数 { reviewId } 或 { path }
```

要点：

- **不要求用户先有会话**——上来就能从笔记库发起审阅；
- 审阅会话的 cwd 必须是笔记库所在工作区（写权限 + 索引可见）；
- 主面板仍在时先回对话（`openTab` 需要 on-screen Session）。

## 4. 打开历史审阅

两个入口，同一份数据：

| 入口 | 展示 |
|:--|:--|
| 笔记页「这篇的审阅记录」（按 doc.path 聚合） | N 次审阅 + 时间；点击打开对应会话 |
| 会话页的审阅标记（官方会话行槽位） | 该会话是审阅会话；点击进入即恢复审阅视图 |

打开某条历史审阅时：

1. 读取 review → 拿到 `sessionId`、`doc.path`；
2. 找文档：按 path 查索引；
   - **找到** → 审阅 tab 打开该文档；
   - **找不到** → 提示「找不到当时的文章（标题：X），可能已移动或改名」+ **[重新挂载]**；
3. 会话本身照常可读（历史不受影响）。

## 5. 审阅交互（无持久批注）

- 文档只读渲染（官方 `MarkdownText`）；frontmatter 字段区；
- 选中正文 → 「引用到对话」→ `SessionInput.insertQuote()`，插入输入框，**不落任何批注对象**；
- 可以连续引用多处，最后一次发送 = 一条消息（一次审阅请求）；
- AI 按消息内容改文件并回复；改动通过会话里的工具卡 diff 与人审阅；
- 侧栏可选显示「本轮改动」汇总（会话内基线，见 §6），不做接受/待接受状态。

## 6. 本轮 diff（会话内、不持久）

- 审阅 tab 打开时快照当前页面正文作为基线（仅 tab 组件状态）；
- AI 改动后，用官方 `DiffBlock` 展示「基线 → 当前」，默认收起只显示 `+N -M`；
- 用户点「刷新/完成一轮」时基线前移；关闭 tab 即丢（历史 diff 已经在会话记录里，不依赖它）；
- **不写库**，不存在基线迁移问题。

## 7. 找不到文章：提示 + 手动挂载

v1：

- 只提示 + 提供 [重新挂载]；
- 重新挂载 = 在笔记库索引里选一篇（搜索/列表），更新 `review.doc`（path/title/hash），
  `updatedAt` 前移；后续 diff 基线以新文档为准；
- **不做**自动猜测（同 hash/同标题只作展示信息，不自动改指向）。

## 8. 删除与归档

- 归档/删除审阅会话 → 复用官方会话管理，**review 记录跟随**：
  - 会话归档 → 审阅记录仍可展示（标记已归档），也可从笔记页历史里看到；
  - 会话被彻底删除 → 打开该 review 时提示「对应的审阅会话已不存在」；
- 明确「删除 review 记录」≠「删除会话」：v1 不提供单独删 review 的入口，避免两套生命周期。

## 11. 边界场景

| 场景 | 行为 |
|:--|:--|
| 用户还没有任何会话 | 从笔记页直接发起审阅（`sessions.create`） |
| 文档被改名（内容同） | 历史审阅打开时找不到 → 提示 + 手动重新挂载（不自动猜） |
| 文档被删除 | 同上提示 |
| 文档被外部改内容 | 不影响审阅会话；打开时按当前内容显示，diff 基线从本次打开起算 |
| 同一文档多次审阅 | 多条 review，各自独立会话与历史 |
| 审阅会话被归档/删除 | 见 §8 |
| 浏览器关闭时尚未发送的引用 | 与普通输入框草稿一致（DSH 输入框草稿机制）；不额外承诺 |
| 插件升级/重载 | 审阅记录在存储里；本地未发送引用可能丢（同普通草稿） |

## 12. 验收标准

- 无会话状态下，从笔记页点「审阅」能创建会话、写入 review、切到会话并打开审阅 tab；
- 笔记页能看到某篇的 N 次审阅记录，点击打开对应会话；
- 会话页能识别审阅会话（有标记）；
- 文档改名/删除后打开历史审阅：提示找不到 + 手动重新挂载可用，会话历史完整；
- 审阅过程中选中文字 → 引用进输入框；不产生任何批注对象；
- 「本轮改动」diff 默认收起显示 `+N -M`，展开为官方 DiffBlock；
- 代码中不再存在 annotation 对象/状态机/锚点/失效检测；
- `npm run verify` 全绿，根 `check` 通过。
