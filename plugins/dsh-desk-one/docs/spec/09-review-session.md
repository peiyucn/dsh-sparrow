# 09 · 文件审阅会话（Review Session）— 以会话为状态载体

> 状态（2026-11-11）：**设计稿 v3（定位已确认）**。属于「笔记」功能的工作机制：笔记 = AI 写 + 人审阅，
> 不做 markdown 编辑器；审阅会话是审阅状态的唯一载体。
>
> 根因（v1 已验证）：Word 的批注/修订是**自持格式**（状态内嵌文档）；markdown 与一般纯文本**无状态**。
> 把状态外挂到文件上必然产生锚点失效、改名即丢、部分接受等无解问题。
> 结论：**状态挂在会话上，文件与审阅会话相互独立，只保留一条指向。**
>
> 进一步结论：既然读取/编辑/历史/归档都走官方能力，审阅与**文件格式无关**——
> 只要在工作区内、可编辑，任何文本文件都能发起审阅。笔记只是其中一个入口。

## 0. 与「笔记」的关系

| 模块 | 职责 |
| :-- | :-- |
| 笔记 Notebook | 产品名与入口：库浏览、索引、搜索、行动性统计（缺 frontmatter / 空笔记）、0→1 去对话 |
| 审阅会话 Review Session | 笔记的工作机制：关联文件、对话历史、本轮 diff、历史入口、重新挂载 |
| 编辑器 | **不做**。0→1 在对话里完成；后续修改全部经审阅会话 |

用户已有 Obsidian / OneNote / VSCode 时，把笔记库指向原目录即可只使用审阅能力；
没有笔记系统时，用「对话起草 → 审阅迭代」这套新形式。两种情况下都不冲突。

## 1. 定位

**审阅是会话的一种能力，不是文档的附属功能。**

```
被审文件（无状态）            审阅会话（有状态、有历史）
 工作区内任意文本文件          一次评审的全部上下文
 ├─ 内容真值                  ├─ 当时审的是哪个文件（路径 + 标题 + 指纹快照）
 ├─ 历史：git / 外部版本      ├─ 对话：人提了什么、AI 改了什么、人怎么回
 └─ 不承载任何审阅状态         └─ 改动：文件编辑工具卡里的逐次 diff（天然留档）
```

审阅会话 = **新建的 DSH 会话**；Desk One 只存一条 `review` 关联记录。
两者之间只有一条指向，指向失效只影响「现在还能不能打开那个文件」，不影响会话。

## 2. 实体模型

### 2.1 审阅会话本体 = DSH 会话

复用官方会话系统：持久化、历史、搜索、归档/回收站、文件编辑工具卡的 diff。

### 2.2 关联记录 `review`

```ts
kind: 'review'
  id: 'review_<uuid>'
  sessionId: string            // 审阅会话外键
  target: {
    cwd: string                // 发起时的工作区根（相对路径的基准）
    path: string               // 相对 cwd 的文件路径
    title: string              // 显示用（文件名或 md 的 frontmatter title）
    kind: 'markdown' | 'text'  // 渲染分派依据
    hash: string               // 创建时内容指纹（只记录，v1 不据此自动猜测）
  }
  createdAt: string
  updatedAt: string
  revision: number
```

- 同一文件可多次审阅 → 多条 review 指向不同会话；
- 一条会话至多一条 review（v1 约束）。

## 3. 适用范围

| 可审 | 不可审 |
|:--|:--|
| 工作区内 UTF-8 文本文件 | 二进制（按扩展名 + 内容探测拒绝） |
| `.md`（markdown 渲染） | 超大文件（v1 上限，如 1MB，超出提示） |
| 其他文本/代码（按扩展名渲染为代码块或纯文本） | 工作区外文件（沙箱写不了，AI 无法改） |

## 4. 发起审阅

入口两条：

1. **笔记页**（md 库内）：某篇 → 「审阅」；
2. **官方文件预览 tab 菜单**（任意文本文件）：菜单项「发起审阅」。
   槽位 `sidebar.right.tab.menu.item` 源码确认存在（给任意 tab 追加菜单项），运行时待探针。

流程：

```
发起审阅
  → 解析目标：cwd（工作区根）+ 相对路径 + 渲染类型 + 内容指纹
  → sessions.create({ cwd: 该工作区 })      // 不依赖「当前会话」，无会话也能用
  → 写入 review 记录
  → 切到该会话（layout.selectPanel(null) + 官方会话导航）
  → 右侧栏打开「审阅」tab，参数 { reviewId }
```

## 5. 打开历史审阅

两个入口，同一份数据：

| 入口 | 展示 |
|:--|:--|
| 笔记页（md）：这篇的审阅记录 | N 次审阅 + 时间；点击打开对应会话 |
| 会话页：审阅标记（官方会话行槽位） | 该会话是审阅会话；进入即恢复审阅视图 |

打开时读 review → 按 `cwd + path` 找文件：

- **找到** → 审阅 tab 显示文件；
- **找不到** → 提示「找不到当时的文件（标题：X），可能已移动或改名」+ **[重新挂载]**；
- 会话本身照常可读。

## 6. 审阅交互（无持久批注）

### 6.1 布局（不挤压正文）

```
┌──────────────────────────────────────┐
│ 📄 文件标题                     [⛶]  │  顶栏：标题 + 专注（官方右栏全屏）
├──────────────────────────────────────┤
│                                      │
│  正文（唯一主内容，唯一滚动区）       │
│                                      │
├──────────────────────────────────────┤
│ 待提交 3 处      │   本轮改动 +3 -1   │  底部浮层条（折叠，常驻）
└──────────────────────────────────────┘
```

- 正文是唯一主内容；元数据（frontmatter）收进顶栏弹层，不常驻；
- 底部条折叠时不占正文高度；
- **展开为浮层**（绝对定位覆盖在正文之上，最高约 60% 高度，带背景与阴影），
  **不重排/压缩正文**；点击条外或 Esc 收起；
- 浮层内两个页签：**待提交** / **本轮改动**；
- 宽度越宽浮层越宽；窄栏下仍覆盖在正文上，不改变布局。

### 6.2 写批注（弹窗）

- 选中正文 → 浮出 `[写批注]`；
- 点击后就地弹窗：引用原文（只读）+ 意见输入框 + `[取消] [加到待提交]`；
- 弹窗覆盖在正文之上，**不改变正文尺寸**；保存后进入待提交清单（tab 内存，不落库）。

### 6.3 待提交清单（浮层）

- 每条：序号、引用原文、意见（可编辑）、删除；点击条目可滚动定位到原文；
- `[全部提交]`：按编号拼成一段（`【批注 N】引用原文` + 意见）插入输入框，**不自动发送**；
- 插入成功后清空清单、计数归零（单一真值回到输入框）。

### 6.4 生命周期

| 事件 | 行为 |
| :-- | :-- |
| 切 tab / 切会话 / 收起右栏 | 不丢（tab 定义 `keepMounted`） |
| 有未提交时关闭 tab | 官方 closeHandler 拦截 + tab 内确认「有 N 处未提交，关闭即丢失」 |
| 关闭浏览器 | `beforeunload` 提示 |
| 提交给 AI | 清单清空，此后属于会话记录 |
| 崩溃 | 丢（同未保存文档，可接受） |

**不落库** → 文件改名、外部改动、跨会话身份问题均不存在。


- 按 `target.kind` 渲染：markdown 用官方 `MarkdownText`；其他文本用官方 `CodeBlock`/纯文本块；
- 选中文本 → 「引用到对话」→ `SessionInput.insertQuote()`，插入输入框，**不落任何批注对象**；
- 可连续引用多处，一次发送 = 一条审阅请求；
- AI 按消息改文件并回复；改动通过会话里工具卡 diff 与人审阅；
- 侧栏可选「本轮改动」汇总（会话内基线，见 §7），无接受/待接受状态。

## 7. 本轮 diff（会话内、不持久）

- 审阅 tab 打开时快照文件内容作为基线（仅 tab 状态）；
- AI 改动后，用官方 `DiffBlock` 展示「基线 → 当前」，默认收起只显示 `+N -M`；
- 用户点「刷新/完成一轮」时基线前移；关闭 tab 即丢（历史 diff 已在会话记录里）；
- 不写库，无迁移问题。

## 8. 找不到文件：提示 + 手动挂载

v1 只提示 + [重新挂载]：

- 重新挂载 = 在工作区里选一个文本文件（搜索/列表），更新 `target`（cwd/path/title/kind/hash）；
- 不自动猜测（同 hash/同标题只展示，不改指向）；
- 重新挂载后 diff 基线以新文件为准。

## 9. 删除与归档

- 归档/删除审阅会话 → 复用官方会话管理；
- review 记录跟随会话：会话被彻底删除 → 打开该 review 时提示「对应审阅会话已不存在」；
- v1 不提供单独删 review 的入口（避免两套生命周期）。

## 13. 边界场景

| 场景 | 行为 |
|:--|:--|
| 用户还没有任何会话 | 从文件发起审阅（`sessions.create`） |
| 文件被改名（内容同） | 历史审阅提示找不到 + 手动重新挂载 |
| 文件被删除 | 同上 |
| 文件被外部改内容 | 不影响审阅会话；打开时按当前内容显示 |
| 同一文件多次审阅 | 多条 review，各自独立会话 |
| 审阅会话归档/删除 | 见 §9 |
| 二进制/超大文件 | 拒绝发起并说明原因 |
| 浏览器关闭时未发送的引用 | 与普通输入框草稿一致；不额外承诺 |
| 插件升级/重载 | review 记录在存储里；本地未发送引用可能丢 |

## 14. 验收标准

- 无会话状态下，从笔记页或预览 tab 菜单能发起审阅：创建会话、写 review、切到会话、打开审阅 tab；
- md 用 markdown 渲染，其他文本用代码/纯文本渲染，选中均可引用；
- 笔记页看到某文件的 N 次审阅记录并可打开；
- 会话页能识别审阅会话；
- 文件改名/删除后打开历史审阅：提示找不到 + 手动重新挂载可用，会话历史完整；
- 「本轮改动」diff 默认收起显示 `+N -M`，展开为官方 DiffBlock；
- 代码中不再存在 annotation 对象/状态机/锚点/失效检测；
- `npm run verify` 全绿，根 `check` 通过。
