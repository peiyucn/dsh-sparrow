# 10 · 新会话任务捕获

> 状态：**Phase 1 + Phase 2 已实现（2026-11-19）；2026-11-22 起放宽触发语义，并补 `desk_task_delete`。** host 半改动需要重启 DSH 后生效；真实新会话验收待重启后补。Phase 2 的完整规则见 `12-auto-task-capture-prompt.md`。

## 背景

Desk One 的任务板已经能挂会话（任务卡显示会话 chip，可跳回会话），但用户要自己想起来去建任务。目标是在**新会话第一条实质性请求**有任务性质时，主动问一次是否建待办并挂上本会话，把真正要落地的事接到任务板。任务性质不是“出现任务二字”，而是请求要求产出 / 修改 / 验证 / 协调 / 接手一个有落地结果的工作；包括代码、文件、配置、数据、文档、交付物和多步跟进。

Phase 1 不加常驻提示词，`desk-one` skill 只在被模型加载时生效。Phase 2 已加常驻 system prompt 作为稳定触发层，skill 保留为详细操作指南。

## 触发规则

- 只看新会话的**第一条实质性请求**；如果第一句只是打招呼 / 上下文，顺延到第一条真正开始做事的请求。
- 每个会话最多问一次；会话后来明显进入多步工作且尚未捕获时，允许补问一次。
- 只在面向用户的主会话问，**不在 subagent 会话**问。
- 任务性质：要求产出 / 修改 / 验证 / 协调 / 接手一个有落地结果的工作，结果超出一次解释；代码 / 文件 / 配置 / 数据 / 文档修改、交付物、验收、多步跟进都算。
- 不因出现「任务」二字就触发；纯问答、解释、只读且没有后续的请求、Desk One 自身用法提问、本会话已有任务关联，都不问。
- 用户拒绝后本会话不再问；**先问再做**，不先建任务再补问。

## 交互

1. 助手用一句话提议：「要不要在任务板建个「XXX」待办，并把本会话挂上？」
2. 用户同意 → 调用 `desk_task_add`：
   - 标题：从用户原话提炼；用户改名用新名。
   - 状态：默认 `todo`。
   - body：只写一句来源 / 目标，不复述整段对话。
   - `link_current_session: true`：工具从 `exec.agent.id` 取当前会话 id 写入 `sessionIds`，模型不需要猜 id。
3. 用户拒绝或没回应 → 不建任务，本会话不再提。
4. 用户明确要求建任务 → 直接建，不再问一遍。

## 数据与边界

- 不新增存储字段；复用任务已有的 `sessionIds`。
- 会话关联仍受单任务最多 `MAX_TASK_SESSIONS`（当前 10）的约束；已有任务的补挂见 `11-task-session-link.md`。
- 任务状态不会随会话 running / idle 自动变化；会话 chip 只是关联与跳转。
- 每个新会话独立判断一次；每个会话最多问一次。
- Phase 2 已加常驻提示词；skill 仍保留为详细操作指南，两者规则一致。
- 删除卡片只删除任务卡本身，不删关联会话、不删分组。

## 验收

- 新会话第一次实质性请求「帮我改一下这个页面」→ 只问一次；同意后建 `todo`，任务卡出现本会话 chip。
- 第一次请求「解释一下这个报错」、只读查询、Desk One 用法提问 → 不问。
- 第一句只是上下文，随后「把 A 和 B 都改掉」→ 在第一条实质性请求时问一次。
- 会话后来明显进入多步工作且尚未捕获 → 允许补问一次。
- 用户拒绝后，本会话后续不再问。
- `desk_task_add` 不传 `link_current_session` 时行为不变；传了但无 agent 上下文时明确报错，不假装关联。
- host 半不注册常驻 system prompt（Phase 1 边界）。

## 非目标

- 不做“会话每轮自动更新任务状态 / 进度”。
- 不自动建任务、不自动补截止日期、不自动分组。
- 不做跨会话去重（是否已有同主题任务由用户判断）。
