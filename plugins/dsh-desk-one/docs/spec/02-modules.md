# 02 · 模块需求 — dsh-desk-one

> 每个模块一节：目标、用户故事、交互、涉及对象、边界、验收、工具。对象字段与状态机见 `01-object-model.md`。
> 阶段标记：v1 = 第一版（壳 + 总览 + 待办 + 日程只读 + 设置），v2 = 第二版（专注、便签、看板、搜索、写回）。

## 1. 面板外壳 Shell（v1）

**目标**：一个侧栏入口，一块面板，内部路由七个模块；统一加载态、错误态与空态。

**用户故事**

* 我从侧栏点「办公桌」打开面板，默认落在「总览」。
* 我切到别的标签再切回来，当前标签与滚动位置不丢（面板生命周期内）。
* 面板出问题时我能看到一条错误带和「重试」，而不是一片空白。

**交互**

* 侧栏入口带未完成数量角标（今天到期 + 逾期，上限显示 `99+`）。
* 顶部标签：总览 / 便签墙 / 任务板 / 日程 / 专注；设置放标签右侧齿轮。
* 模块懒挂载：首次进入才初始化，离开不销毁状态（内存有界）。
* 统一空态文案与「添加」入口。

**边界与异常**

* 数据未就绪时显示骨架屏；Store 读取失败显示错误带 + 重试。
* client 能力门缺失时整体不注册、不抛错（宿主 boot 审计要求）。

**验收标准**

* 断网点开面板可用，本地模块正常渲染。
* 任一模块渲染异常不导致整页白屏（错误边界）。
* 切模块不重复拉全量数据；首次打开 < 300ms（个人规模）。

**Agent 工具**：无（壳不直接产生工具）。

## 2. 总览 Overview（内容未设计，S0 空白占位）

**长期定位**：办公桌的汇总页——跨模块摘要与联动入口，不是「某一天」的页面。

**S0 现状**：打开只有空白区域，不放统计 / 最近项 / 引导文案；默认标签是便签墙，避免首屏空白。

**待设计的问题**（先记录，不实现）

* 汇总哪些模块、以什么形式呈现（时间轴 / 卡片 / 列表）？
* 与便签墙、任务板、日程的联动入口是什么？
* 是否需要「今天 / 本周」这类时间切面，还是纯模块摘要？
* agent 工具面是否需要 `desk_overview`（S1 起再说）。

**验收标准**：S0 不出现任何未经验证的内容区块；内容与联动规则评审通过后再实现，并在此补验收标准。

## 3. 待办 Tasks（v1）

**目标**：快速收集、清晰推进、可靠完成。

**用户故事**

* 我把想法丢进收集箱，之后再整理。
* 我给任务设优先级、估算和到期时间。
* 我完成或取消任务，状态一致地反映到今天和看板。

**交互**

* 列表分组：收集箱 / 今天 / 未来 / 已完成；支持标签过滤与关键词过滤。
* 行内操作：完成勾选、优先级、到期时间、打开详情。
* 详情：标题、描述、标签、估算、关联便签、专注记录、排期按钮（v2 生成事件）。
* 状态流转按状态机，禁止非法跳转（界面隐藏非法动作）。

**涉及对象/查询**：`task`；`derivedFrom`（便签来源）、`workedOn`（专注记录）、`scheduledAs`（排期）。

**边界与异常**

* 并发修改：保存时 revision 不匹配提示「内容已被修改，请刷新」。
* 到期时间跨时区显示正确；逾期计算按用户时区。
* 删除任务软删，可从回收站恢复（v2 提供界面）。

**验收标准**

* 增删改与状态流转在列表、今天、看板三处一致。
* 到期/逾期计算在夏令时与跨日边界正确（单测覆盖）。
* 连续点击完成不会重复写入或状态错乱（防连点 + revision）。

**Agent 工具**：`desk_task_add`、`desk_task_list`、`desk_task_update`、`desk_task_complete`。

## 4. 日程 Calendar（v1 读 / v2 写）

**目标**：本地事件可管；外部日程可看、可合并、可辨认来源。

**用户故事**

* 我在月/周视图里看本周安排，外部事件与本地事件同屏。
* 我新建一个本地事件，不写回任何外部日历。
* 我点开外部事件能看详情（时间、地点、来源），但默认不能改。

**交互**

* 视图：月 / 周 / 议程；今天高亮；点空白新建（本地事件）。
* 事件详情面板：来源徽标、只读提示、复制、跳转原始客户端（可选）。
* 刷新按钮 + 最后同步时间；同步失败显示原因。
* v2：本地事件可「写回」到指定 provider（需确认），外部事件在 provider 可写时允许编辑。

**涉及对象/查询**：`event`；`source.provider` 区分本地/镜像；`scheduledAs` 关联任务。

**边界与异常**

* 外部事件重复拉取不重复创建（唯一键 upsert）。
* 外部事件被删除：本地软删并在界面消失，恢复时重新拉取。
* 写回失败：事件保留本地改动，标 `syncState: 'error'` 并给重试。

**验收标准**

* 月/周/议程切换正确，跨月事件显示完整。
* 外部事件只读的按钮禁用态明确，不会误以为能改。
* 同一事件不会同时出现「本地」与「镜像」两份。

**Agent 工具**：`desk_calendar_list`；v2 加 `desk_calendar_add`（写回需确认）。

## 5. 同步 Sync（v1 只读）

**目标**：两条外部线路各管各的连接、拉取、状态与错误。

**用户故事**

* 我用微软账号登录，授权后看到我的个人 Outlook 日历事件。
* 我在设置里填入企业微信 CalDAV 的地址、邮箱和密码，点「测试连接」通过后保存。
* 同步失败时我知道是哪条线路、什么原因、怎么重试。

**交互**

* 设置页两张连接卡：Outlook（Graph 设备码流程 / 重新授权 / 断开）、企业微信 CalDAV（地址、账号、密码、测试连接、保存、断开）。
* 每张卡显示：状态（未连接 / 正常 / 失败）、最后同步时间、错误摘要、手动同步按钮。
* 自动同步：打开面板时增量拉取，间隔可配（默认 15 分钟），失败退避。
* 凭据只经官方凭据服务读取，不写日志、不进 HTML。

**边界与异常**

* Graph 令牌过期：提示重新授权，不清空本地镜像。
* CalDAV 密码失效：提示「请在手机端重新获取密码」，保存失败态，不无限重试。
* 网络断开：保留本地数据，显示离线状态；恢复后自动补拉。
* 同步并发：同一 provider 串行，重复点击合并为一次。

**验收标准**

* 连接、测试、断开全流程可用；错误提示可操作。
* 拉取事件数与远端一致（抽样核对），重复同步不产生重复对象。
* 凭据不出现在日志、HTML 或导出文件中。

**Agent 工具**：`desk_sync`（手动触发，返回每线路报告）。

## 6. 专注 Focus（v2）

**目标**：番茄计时绑定任务，累计实际用时。

**用户故事**

* 我选一个任务点「开始专注」，25 分钟后提醒我。
* 我中途暂停/继续，记录中断次数。
* 我结束专注后任务的实际用时更新。

**交互**

* 计时卡：剩余时间、开始/暂停/结束、关联任务选择、可配时长（默认 25/5）。
* 结束原因：完成 / 中断 / 取消，分别记录。
* 侧栏入口显示运行中状态（可选）。
* 提醒走站内提示 + 可选系统通知。

**涉及对象/查询**：`focus`；`workedOn` 边；task 实际用时 = 所有 focus 时长汇总。

**边界与异常**

* 同一时刻只允许一个运行中专注；开始新的先提示结束旧的。
* 页面刷新/重启：运行中的专注从持久化恢复（时间戳计算，不靠内存计时器）。
* 计时器在 `ctx.effect` 中清理，不泄漏。

**验收标准**

* 暂停期间不累计；刷新后剩余时间正确。
* 实际用时汇总与专注记录一致；取消的专注不计入。
* 提醒准时，关闭面板后仍触发（宿主侧计时）。

**Agent 工具**：`desk_focus_start`、`desk_focus_stop`、`desk_focus_status`。

## 7. 便签墙 Notes（v2 → 已提前落地在 S0）

**目标**：一面随手记的便签墙——点「＋」就贴一张，直接在贴纸上写，拖着摆、拖角改大小；墙面不出滚动条。

**用户故事**

* 我点右下角的「＋」，墙上立刻出现一张空便签并拿到输入焦点，不用填表单。
* 我直接在贴纸上打字，点别处就保存；写空了就走开，它自己消失。
* 我按住贴纸拖到墙面的任意位置；贴纸永远不出屏，也不会出现滚动条。
* 点过或拖过哪张，哪张就显示在最上层，不被别的贴纸压住。
* 我拖右下角改大小，贴纸变成方角纸片；下次进来位置和尺寸都还在。
* 我悬停贴纸就能换颜色、把它丢进垃圾桶；垃圾桶里还能恢复。

**交互**

* 墙面正好占满面板剩余高度、`overflow: hidden`；贴纸绝对定位（x/y/width/height，px），坐标与尺寸一律夹在可见墙面内。
* 「＋」是悬浮在右下角的圆形按钮；新便签落在视口中心并级联错位，自动聚焦。
* 贴纸正文失焦即保存；内容清空后失焦 = 删除该便签。
* 拖动在正文之外的区域开始；本地跟手移动，抬手落库。改大小从右下角手柄开始，抬手落库；两者失败都提示并重拉对齐。
* 点 / 拖 / 改大小都会把该贴纸的 z-index 抬到最高，层级同时写回便签（可选 `z` 字段）：刷新 / 重启后压叠顺序不丢。
* 贴纸形状：方角（2px）纸片、纸面阴影，不做大圆角卡片。
* 悬停显示颜色圆点（默认 / 黄 / 绿 / 蓝 / 粉）、删除按钮与右下角改大小手柄。
* 标签页记忆：切走再回到办公桌停在上次标签页（`localStorage: dsh-desk-one:tab`，纯界面偏好，不含用户内容）。
* 空墙提示：不加背板（显脏且缩小操作面积），沿用页面干净底；加载时中央显示加载提示，空墙中央有很淡的两层提示（主提示「双击空白处新建便签」13px/500/0.04em + 次提示「或点右下角＋」11px/400）。
* 新建：右下角 **＋** 或双击背板空白处新建；新贴纸落在双击点附近、默认置顶（`z` = 当前最大 + 1，随记录持久化）并立刻聚焦正文。
* 垃圾桶：卡片悬停的小垃圾桶图标即丢进垃圾桶；右下角「＋」旁的垃圾桶入口（带计数）进入垃圾桶视图，可恢复或永久删除；「清空垃圾桶」须二次确认、**绝不自动清空**；`trashed` 状态持久化，重启后垃圾桶仍生效。
* agent 工具创建的便签若没有坐标 / 尺寸，界面按网格兜底摆放与默认尺寸，用户操作后才写回。

**涉及对象/查询**：`note`（`body` 是唯一内容，`title` 由正文首行派生）；`x`/`y` 位置、`width`/`height` 尺寸与 `z` 层级均为可选字段，`trashed` 标记垃圾桶状态。

**边界与异常**

* 并发修改：沿用 revision 乐观并发，409 时提示并重拉。
* 兼容旧记录：没有 x/y/width/height 也能通过 schema 校验（字段可选，无需迁移）。
* 窗口缩放：渲染时把坐标 / 尺寸临时夹进可见区，保存值不丢；空间恢复后回到原位置（README 已注明）。
* 大量便签：墙面不滚动，贴纸数量增长后按需做可视区裁剪 / 虚拟化（> 300 张）。

**验收标准**

* 「＋」→ 立即出现空贴纸可输入；失焦后文字持久化，刷新仍在。
* 拖动 / 改大小都夹在可见墙面内，不出现滚动条；落库后刷新位置与尺寸不变。
* 点或拖任意贴纸，它显示在最上层，且刷新后层级保持。
* 贴纸是方角纸片；清空正文失焦后自动消失，不产生空记录。
* 切到别的侧栏入口再回来，停在上次标签页。
* 新便签出现即置顶并聚焦正文，双击墙面空白处能新建；空墙提示在浅色 / 深色主题下都只是很淡的引导，不抢贴纸。
* 丢进垃圾桶后贴纸从墙面消失、出现在垃圾桶；恢复后回墙面；刷新 / 重启后垃圾桶状态保持。
* 「清空垃圾桶」需二次确认后才永久删除，未确认时垃圾桶内容不变。
* agent 工具建的便签出现在墙上（兜底位置 + 默认尺寸），且能被拖动 / 改大小落位。

**Agent 工具**：`desk_note_add`、`desk_note_list`、`desk_note_update`、`desk_note_delete`（位置 / 尺寸字段暂不进工具面）。

## 8. 看板 Board（v2）

**目标**：按项目看任务流转，拖拽改状态。

**用户故事**

* 我为一个项目建看板，任务按状态排在泳道里。
* 我拖一张卡从「进行中」到「完成」，待办列表里也变成完成。

**交互**

* 项目选择器（新建/重命名/归档）；泳道默认 收集箱/待办/进行中/完成（可配列）。
* 卡片显示标题、优先级、到期、标签；拖拽改状态并乐观更新。
* 每列计数；空列显示占位。

**涉及对象/查询**：`project`、`task`（`belongsTo` 边）；泳道 = status 分组。

**边界与异常**

* 拖拽失败回滚并提示；并发修改提示刷新。
* 归档项目只读展示；删除项目需迁移任务归属（v2 内定位为归档，不删数据）。

**验收标准**

* 拖拽改状态与待办列表双向一致；刷新后保持。
* 100 张卡以内拖拽流畅；无重复卡片。

**Agent 工具**：`desk_board_list`、`desk_board_move`。

## 9. 搜索 Search（v2）

**目标**：一个框搜所有对象。

**用户故事**

* 我搜关键词，能同时看到任务、便签、日程。
* 结果按类型分组，点进去定位到对象。

**交互**

* 顶部搜索框；结果分组 + 数量；空结果给建议。
* 匹配 title / body / tags；大小写不敏感；中文按子串。

**边界与异常**

* 结果上限 200，超出提示缩小范围。
* 搜索不阻塞输入（防抖 200ms）。

**验收标准**

* 三类对象都能被搜到；无结果不报错。
* 大对象库（5k）下搜索响应 < 200ms。

**Agent 工具**：复用各模块 list 工具，v2 再加 `desk_search`。

## 10. 设置 Settings（v1）

**目标**：连接、同步状态、数据管理、关于。

**用户故事**

* 我在设置里完成两条线路的连接与测试。
* 我导出全部数据备份，或从备份导入到新机器。

**交互**

* 分区：连接（两张卡）/ 同步（间隔、立即同步）/ 数据（导出 JSONL、导入、清空需二次确认）/ 关于（版本、许可证、隐私说明）。
* 危险操作二次确认并展示影响范围。

**边界与异常**

* 导入格式错误逐行报告，不中断已导入部分。
* 清空数据需输入确认词（不可逆，界面明示）。

**验收标准**

* 导出文件可被导入还原（对象数、关键字段一致）。
* 清空操作有确认且不可误触。

**Agent 工具**：`desk_export`（只读导出）。

## 11. Agent 工具层（v1 起随模块）

**目标**：模型能用同一套对象做事，工具行为与界面一致。

**约定**

* 只读工具默认可调用；写工具返回结构化结果和一句摘要。
* 写外部日历（v2）必须带确认；失败的写入不静默。
* 工具名统一 `desk_*`，参数与 Store API 对齐，不直接操作文件。
* 每个工具的错误带 `code` 与可操作提示（如「先连接 Outlook」）。

**验收标准**

* 工具调用结果与界面看到的数据一致（同一查询）。
* 工具写操作触发界面刷新（订阅广播），不出现两份真相。
