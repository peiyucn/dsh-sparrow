# 02 · 模块需求 — dsh-desk-one

> 每个模块一节：目标、用户故事、交互、涉及对象、边界、验收、工具。对象字段与状态机见 `01-object-model.md`。
> 阶段标记：v1 = 第一版（壳 + 总览 + 待办 + 日程只读 + 设置），v2 = 第二版（专注、便签、看板、搜索、写回）。

## 0. UI 设计基准

> 不为 DeskOne 另建视觉语言：位置、尺寸、材质优先复用官方同位置组件，DeskOne 只负责功能组合。

| 区域 | 官方参考 | 落地约束 |
|---|---|---|
| 品牌 lockup | 官方 `BrandWordmark` 的反色徽章 | 中文 **同桌**、英文 **Desk One**（与官方 HARNESS wordmark 一样，英文徽章视觉全大写 DESK ONE；中文标题不受影响）；页头用**一个**反色徽章：墨色底 + inverted 字，内部合并 14px 圆角矩形 + 小星星与标题（不拆成两个方块）；小字后接官方插件页同款 20px infoButton + 纯 hover/focus Tooltip（无点击行为、宽度上限 240px；文案走碳硅协同 slogan：两种生命、一张桌子，你出灵感、harness 出算力，便签/任务/会话/日程/时间一起完成）；左栏图标与页头共用同一字形 |
| 整体面板 | 对话区 `ui-conversation`（ConversationRoot / ConversationSession） | 76px 页头浮层；第一行品牌标题 + 小字说明 + 当前功能动作，第二行官方纯文字 tab；内容首屏用 `--dsh-desk-header-h` 下移，滚动时内容从页头下经过 |
| 页头 tab | ConversationRoot 的 `.tabs` / `.viewTabs` / `.tab` | 两层 flex：外层 gap 20px（viewTabs ↔ More），内层 gap 32px（文字间）；tab 本体 35px 高、上抬 10px、padding 10/9、10px 命中内边距；当前项 2px 下划线压在页头 rule 上；More 22×22，menu 以三点为锚点左对齐浮出 |
| 功能动作按钮 | 插件页 `ui-plugin-manager` 的 PluginManagerPage（`.addPrimary` / `.addMore` 覆盖值） | **32px 高 / 13px 文案 / 20px 行高 / 0 12px padding / 12px 圆角**；primary fill 或 0.5px 描边；保留图标 + 文字；不采用通用 Button sm 的 28px/8px |
| 材质 | theme-tone 的官方对话区顶栏 | 默认 `bg-base` 实色、无模糊；theme-tone 激活且非 plain 时，header 自身透明，由 `::before` 套其 barGlass（54% 底色 + `blur(24px) saturate(170%) brightness(1.04)` + 同相位打光）；DeskOne 不另定玻璃配方 |
| 滚动条 | `ui-theme` 的 scrollbar skin + 对话区滚动契约 | 不声明 `scrollbar-width`（会关闭 Chromium 的 ::-webkit-scrollbar 规则）；track margin 只错开顶部（header + 2px），底部保留 2px，thumb 和内容都能滚到底 |
| 内容区 | 各功能自身语义 | 与页头间距统一 14px；便签墙固定宽度、纵向无限、横向不滚动、全宽动态；任务板三泳道；Sessions 只读目录；页头靠 theme-tone 决定是否玻璃 |

**页头尺寸推导**：76px = 8px 顶 inset + 32px 标题行（容纳插件页 32px 按钮，故比对话区的 10px inset 少 2px） + 10px 间距 + 25px tab 行。

**不照抄的部分**：只复用控件形状、尺寸、材质与交互，不照抄官方页面的信息层级或位置；DeskOne 的一级导航是页头 tab，不把功能动作塞进 tab 行。

## 1. 面板外壳 Shell（v1）

**目标**：一个侧栏入口，一块面板，内部路由七个模块；统一加载态、错误态与空态。

**用户故事**

* 我从侧栏点「同桌」打开面板，默认落在「便签墙」。
* 我切到别的标签再切回来，当前标签与滚动位置不丢（面板生命周期内）。
* 面板出问题时我能看到一条错误带和「重试」，而不是一片空白。

**交互**

* 侧栏入口带未完成数量角标（今天到期 + 逾期，上限显示 `99+`）。
* 顶部标签：总览 / 便签墙 / 任务板 / 会话（日程、专注后续扩展）；末尾 More 收起溢出页面。会话标签 Phase 1 为只读目录（活跃会话按工作区分组 + 归档树），详见 `04-sessions.md`。
* 模块懒挂载：首次进入才初始化，离开不销毁状态（内存有界）。
* 统一空态文案与「添加」入口。

**边界与异常**

* 数据未就绪时显示骨架屏；Store 读取失败显示错误带 + 重试。
* client 能力门缺失时整体不注册、不抛错（宿主 boot 审计要求）。

**验收标准**

* 断网点开面板可用，本地模块正常渲染。
* 任一模块渲染异常不导致整页白屏（错误边界）。
* 切模块不重复拉全量数据；首次打开 < 300ms（个人规模）。

**Agent 工具**：无（壳不直接产生工具）。

## 2. 总览 Overview（内容未设计，S0 空白占位）

**长期定位**：同桌的汇总页——跨模块摘要与联动入口，不是「某一天」的页面。

**S0 现状**：打开只有空白区域，不放统计 / 最近项 / 引导文案；默认标签是便签墙，避免首屏空白。

**待设计的问题**（先记录，不实现）

* 汇总哪些模块、以什么形式呈现（时间轴 / 卡片 / 列表）？
* 与便签墙、任务板、日程的联动入口是什么？
* 是否需要「今天 / 本周」这类时间切面，还是纯模块摘要？
* agent 工具面是否需要 `desk_overview`（S1 起再说）。

**验收标准**：S0 不出现任何未经验证的内容区块；内容与联动规则评审通过后再实现，并在此补验收标准。

## 3. 待办 Tasks（S1：固定三泳道看板）

**目标**：快速收集、清晰推进、可靠完成。S1 用固定三泳道看板承载；收集箱 / 今天 / 列表等视图后置。

**用户故事**

* 我把要做的事按泳道记下来，一眼看清哪些在待办、哪些在做、哪些完成了。
* 我用拖拽推进状态、调整顺序，不需要先打开表单。
* 我给卡片标颜色、设截止日期，逾期能一眼看出来。
* 完成的事可以折叠，或存档留底、需要时恢复。

**交互**

* 三泳道固定：待办 / 进行中 / 完成（`TASK_STATUSES`，与 `task.status` 一一对应）；窄屏横向滚动。
* 列头：列名 + 计数 + 「＋」新建、新建分组（草稿卡提交标题；空标题取消）；泳道空白处双击也可新建；完成列可折叠。
* 卡片：视图态展示自动换行的标题与描述，单击字段进入编辑（文本框只在编辑时存在）；平时整卡可拖，5px 位移阈值区分点击 / 拖动。叠放色卡（当前色在上、其它颜色露在后，点开五色板直选）、按天截止日期（日历图标 + 日期；未设置时仅日历图标，逾期红字，只剩一天时琥珀色描边）；悬停显示存档（仅完成列）/ 删除（二次确认）。
* 拖拽：泳道是**统一块序列**（未分组卡片与分组块共享手动顺序，可互相穿插）。按住卡片任意位置生成跟手幽灵卡，跨列改 `status`、泳道块序列 / 分组内改 `order`、拖入 / 拖出分组改 `group`；落点泳道与目标分组高亮，容器内画精确插入线，无效落点飞回原位。
* 会话关联：任务卡可挂 0..N 个 DSH 会话（一个会话也可服务多张卡）；卡片只存 `sessionIds`，会话标题 / 运行状态由客户端从宿主会话服务实时解析。chip 用颜色表达状态（可用=绿色，运行中额外加一圈缓慢旋转的绿环；已归档/不可用=中性灰实线，不再用虚线），点 chip 跳转会话；`@` 打开多选选择器（搜索、运行中优先；会话范围与输入框 `@` 一致，即宿主 session 列表含子代理会话；已归档仍可关联，仅列表已移除的不可用项禁用）。选择器渲染为 body portal 浮层，不受泳道滚动裁切。**标题口径与输入框 `@` 对齐**：普通会话取持久化 `title`；子代理会话优先取 subagent label（composer 的 `displayTitle` 就是这么来的），再回退 `title` → id；不把 cwd 目录名当标题。同时订阅会话列表与工作区归档集，归档 / 还原后状态即时刷新。会话是可选依赖，宿主缺服务时整块隐藏。关联不覆盖卡片标题 / 描述。
* 分组：每个泳道支持一层**持久化分组实体**（可为空 / 就地改名 / 折叠 / 拖手柄排序 / 删除后卡片回未分组），成员以任务 `groupId` 为准；折叠是视图偏好。整组拖动与卡片同一套指针拖拽：整块跟手，拖到其它泳道直接级联成员状态（无确认步骤，移回来成本相同）。完成列分组可**整组存档**：组与卡片一起进存档视图（一条分组条目），恢复一起回来，删除存档分组连卡片一起删除。组头操作统一为小图标：加卡 / 完成列多一个存档 / 垃圾桶删除（二次确认）；组内不再画缩进竖线。组头采用两行布局（第一行名称、第二行计数，左侧手柄/折叠与右侧操作跨两行），窄泳道下不换行挤压。
* 排序视图：手动（默认）/ 创建时间 / 截止日期；视图切换不写回 `order`，偏好存 localStorage。
* 存档：工具栏「存档 (N)」进入存档视图，可恢复回原泳道或永久删除；命名统一「存档」，避免与宿主会话归档撞词。
* 加载 / 保存失败可见；revision 冲突时重新拉取。

**涉及对象/查询**：`task`（`status` / `due` / `order` / `color` / `archived`）。

**边界与异常**

* 并发修改 revision 不匹配 → 提示并重拉。
* 日期只到天（YYYY-MM-DD），校验真实日历日；逾期按本地日历日判断。
* 空标题不创建（草稿取消）；删除卡片与存档永久删除均为二次确认。

**验收标准**

* 三列可见；列头计数正确；列头＋ / 双击泳道都可草稿新建；标题 / 描述自动换行、颜色、截止日期可用。
* 整卡拖拽带幽灵卡，无效落点飞回原位；分组可新建 / 改名 / 折叠 / 删除，组内拖拽生效。
* 只剩一天截止的卡片有琥珀色描边；只有完成列卡片可存档。
* 跨列拖拽改状态、列内拖拽改顺序，刷新 / 重启后保持；失败有提示。
* 手动 / 创建时间 / 截止日期三种视图正确，切回手动恢复手排顺序。
* 完成列可折叠；存档后从板上消失，存档视图可恢复 / 永久删除。
* agent 工具与界面读写同一批任务（工具建的任务出现在板上）。
* 会话关联支持多对多；chip 的实时颜色随宿主会话状态变化；已归档 / 不可用会话以中性灰实线和提示降级，不丢失关联；宿主缺会话服务时卡片照常可用；旋转动画在 `prefers-reduced-motion: reduce` 下静止。

**Agent 工具**：`desk_task_add`、`desk_task_list`、`desk_task_update`、`desk_task_complete`、`desk_task_archive`；分组：`desk_group_add`、`desk_group_list`、`desk_group_update`、`desk_group_move`、`desk_group_archive`、`desk_group_delete`。

## 4. 日程 Schedule（S2 只读）

**目标**：把企业微信 / iCloud / Outlook 个人三条线路的日程聚合到一个视图里，只读展示、来源可辨；v1 不创建本地事件，也不写回外部。

**用户故事**

* 我在月/周视图里看本周安排，三个来源的日程同屏，颜色与来源可辨。
* 我点开一条外部日程能看详情（时间、地点、来源、描述），但改不了；可以复制或跳到原始客户端。
* 刷新/同步失败时我知道是哪条线路、什么原因、怎么重试。

**交互**

* 视图：月 / 周 / 议程；今天高亮；外部事件只读（没有编辑入口，来源徽标 + 只读提示）。
* 事件详情：来源、日历名、时间、地点、描述、复制、跳转原始客户端（有链接时）。
* 页头动作：刷新（手动同步）/ 上次同步时间；同步中不可重复点击。
* 冲突提示：时间重叠的事件在周视图/清单里标记；`busy: false` 不参与冲突。
* 多日历：连接卡里逐个勾选（iCloud 多日历默认可能只同步其中一部分）。
* 空态/降级：未连接任何线路时给连接引导；某线路失败时只有该线路顶部错误条，其它线路照常显示。

**涉及对象/查询**：`event`（镜像，只读）+ `calendar`（远端日历源）；`SourceRef.provider/channel` 区分 wecom / icloud / outlook（ics）。

**边界与异常**

* 外部事件按 `(provider, calendarId, externalId)` upsert，不重复创建；重复事件按镜像窗口展开成实例。
* 远端删除：本地软删并从视图消失；窗口滚动后按远端重新拉取。
* 凭据/链接失效：连接卡与日程页各给一次性提示，不自动重试到死循环（企微密码重取、iCloud App 专用密码重生成、Outlook ICS 链接重新发布）。
* 只读：外部事件在界面上不出现可编辑入口；v1 不提供本地事件新建（见 `00-overview.md` 决策 7）。

**验收标准**

* 月/周/议程切换正确，跨天/跨月事件显示完整。
* 三源事件合并展示、来源可辨、同一事件不出现两份。
* 外部事件只读的按钮/编辑态明确禁用，不会误以为能改。
* 任一源失效时其它源照常显示，错误提示可操作。
* 同一时间重叠事件有冲突标记；`busy:false` 不计入。

**Agent 工具**：`desk_schedule_list`、`desk_schedule_sync`、`desk_schedule_connections`（只读；本地事件与写回在 S3）。

## 5. 同步 Sync（S2 只读）

**目标**：三条外部线路各自管理连接、拉取、状态与错误，互不阻塞。

**用户故事**

* 我在设置里粘贴企业微信同步密码，点「测试连接」通过后保存，看到公司日程。
* 我用 Apple ID + App 专用密码连接 iCloud，勾选要展示的日历。
* 我在 Outlook 网页版发布日历得到 ICS 链接，粘贴进设置后看到个人日程。
* 同步失败时我知道是哪条线路、什么原因、怎么重试。

**交互**

* 设置页三张连接卡：
  * 企业微信 CalDAV：账号（邮箱）、密码（手机端「日程 → 日程设置 → 同步至其他日历」获取，**每次重取会作废旧密码**）、测试连接、保存、断开、最后同步时间。
  * iCloud CalDAV：Apple ID、App 专用密码（account.apple.com 生成；改 Apple 主密码会全部失效）、测试连接、保存、断开、日历勾选。
  * Outlook 个人 ICS：发布链接（Outlook 网页版「设置 → 日历 → 共享日历 → 发布日历」复制 ICS 链接）、测试连接、保存、断开；界面标明「只读，刷新通常 3–24 小时」。
* 每张卡显示：未连接 / 正常 / 同步中 / 失败（错误摘要 + 重试）；手动同步按钮；自动同步间隔可配（默认 15 分钟）。
* 凭据只经官方 `ctx.credentials`：密码类走 ref，令牌类（S3 Graph）走 grant 记录；不写日志、不进 HTML、不进导出。

**边界与异常**

* 企业微信 401：提示「请在手机端重新获取同步密码」，保存失败态，不自动无限重试。
* iCloud 401：提示「请重新生成 App 专用密码」；改 Apple 主密码后需重新配置。
* Outlook ICS 403/404：提示「发布链接失效或已被关闭，请在网页版重新发布」。
* 网络断开：保留本地镜像并显示离线；恢复后补拉。
* 同步并发：同一 provider 串行，重复点击合并为一次；跨 provider 总并发 ≤ 2。
* 限流：iCloud 窗口按 366 天 / 400 条切分、读取 ≤ 60 次/分钟；企业微信额度**未查到**，按保守退避。
* 宿主没运行时不同步（无后台守护进程），UI 明示上次同步时间。

**验收标准**

* 连接、测试、断开全流程可用；错误提示可操作。
* 拉取事件数与远端抽样一致，重复同步不产生重复对象。
* 凭据不出现在日志、HTML 或导出文件中。
* 任一线路失败不影响其它线路与本地便签/任务/会话。

**Agent 工具**：`desk_schedule_sync`（手动触发，返回每线路报告）；连接管理走设置界面。

## 6. 专注 Focus（v2）

**目标**：番茄计时绑定任务，累计实际用时。

**用户故事**

* 我选一个任务点「开始专注」，25 分钟后提醒我。
* 我中途暂停/继续，记录中断次数。
* 我结束专注后任务的实际用时更新。

**交互**

* 计时卡：剩余时间、开始/暂停/结束、关联任务选择、可配时长（默认 25/5）。
* 结束原因：完成 / 中断 / 取消，分别记录。
* 侧栏入口显示运行中状态（可选）。
* 提醒走站内提示 + 可选系统通知。

**涉及对象/查询**：`focus`；`workedOn` 边；task 实际用时 = 所有 focus 时长汇总。

**边界与异常**

* 同一时刻只允许一个运行中专注；开始新的先提示结束旧的。
* 页面刷新/重启：运行中的专注从持久化恢复（时间戳计算，不靠内存计时器）。
* 计时器在 `ctx.effect` 中清理，不泄漏。

**验收标准**

* 暂停期间不累计；刷新后剩余时间正确。
* 实际用时汇总与专注记录一致；取消的专注不计入。
* 提醒准时，关闭面板后仍触发（宿主侧计时）。

**Agent 工具**：`desk_focus_start`、`desk_focus_stop`、`desk_focus_status`。

## 7. 便签墙 Notes（v2 → 已提前落地在 S0）

**目标**：一面随手记的便签墙——点「＋」就贴一张，直接在贴纸上写，拖着摆、拖角改大小；墙面不出滚动条。

**用户故事**

* 我点页头标题行的「随手记」，墙上立刻出现一张空便签并拿到输入焦点，不用填表单。
* 我直接在贴纸上打字，点别处就保存；写空了就走开，它自己消失。
* 我按住贴纸拖到墙面的任意位置；贴纸可以超出当前屏幕，墙面纵向滚动，横向不出滚动条。
* 点过或拖过哪张，哪张就显示在最上层，不被别的贴纸压住。
* 我拖右下角改大小，贴纸变成方角纸片；下次进来位置和尺寸都还在。
* 我悬停贴纸就能换颜色、把它丢进垃圾桶；垃圾桶里还能恢复。
* 事情堆太多时，我可以用 **Smash!** 把整墙清进垃圾桶再慢慢收拾；但墙上永远不会超过 100 张。

**交互**

* 墙面正好占满面板剩余高度、`overflow: hidden`；贴纸绝对定位（x/y/width/height，px），坐标与尺寸一律夹在可见墙面内。
* 新建入口是页头标题行的「＋ 随手记」主按钮；新便签落在视口中心并级联错位，自动聚焦。
* 贴纸正文失焦即保存；内容清空后失焦 = 删除该便签。
* 拖动在正文之外的区域开始；本地跟手移动，抬手落库。改大小从右下角手柄开始，抬手落库；两者失败都提示并重拉对齐。
* 点 / 拖 / 改大小都会把该贴纸的 z-index 抬到最高，层级同时写回便签（可选 `z` 字段）：刷新 / 重启后压叠顺序不丢。
* 贴纸形状：方角（2px）纸片、纸面阴影，不做大圆角卡片；纸面底部用 10px 低对比度日期（`createdAt`，本地 YYYY-MM-DD，hover title 带完整时间）显示创建时间，不抢正文。
* 尺寸下限：**152×100**（`NOTE_MIN_WIDTH` / `NOTE_MIN_HEIGHT`），保证五点颜色 + 垃圾桶的顶栏完整落在便签内；旧记录里小于下限的尺寸在渲染时同样夹到下限。
* 悬停显示颜色圆点（默认 / 黄 / 绿 / 蓝 / 粉）、删除按钮与右下角改大小手柄。
* 标签页记忆：切走再回到同桌停在上次标签页（`localStorage: dsh-desk-one:tab`，纯界面偏好，不含用户内容）。
* 空墙提示：不加背板（显脏且缩小操作面积），沿用页面干净底；加载时中央显示加载提示，空墙中央有很淡的两层提示（主提示「双击空白处新建便签」+ 次提示「或点页头「随手记」」）。
* 新建：页头 **随手记** 或双击墙面空白处新建；双击热区覆盖整个滚动墙面（包括动态扩展出来的空白），不局限首屏 canvas；新贴纸落在双击点附近、默认置顶（`z` = 当前最大 + 1，随记录持久化）并立刻聚焦正文。
* 页头、动作按钮、材质与滚动契约统一见 **第 0 节 UI 设计基准**，本节只列便签功能自身动作。便签视图动作为「随手记（主）/ Smash / 垃圾桶」，垃圾桶视图为「返回便签墙 / 清空垃圾桶」。
* 对象级图标按钮（贴纸垃圾桶、任务卡/分组/垃圾桶行）统一为同一套 24/20px 尺寸与 hover 规则。
* 容量：墙上最多 **100** 张（`MAX_ACTIVE_NOTES`），达到后新建入口提示「便签太多了，请先清理一下吧。」、不再创建；垃圾桶最多 **200** 张（`MAX_TRASH_NOTES`），满了先提示清空。host 侧同样校验，agent 工具也绕不过。
* 垃圾桶分页：一次渲染 **10** 行（`TRASH_PAGE_SIZE`），顶部显示「共 N 个便签」，点「加载更多」继续；垃圾桶按钮**不挂角标**（角标只留给未读）。
* **Smash!**：页头标题行里的危险色动作按钮，常驻显示（空墙点击无反应）；二次确认后把墙上全部便签丢进垃圾桶（先播 260ms 飞散动画，再乐观清墙并落库）；单张贴纸丢垃圾桶也播同一段动画。
* 页头动作顺序：随手记（主）、Smash、垃圾桶；进入垃圾桶后变为「返回便签墙」「清空垃圾桶」，避免把导航误读成墙面操作。
* Smash 确认态：点击按钮以外任何位置或按 `Esc` 均取消，回到未确认态（不会一直红着）。
* 垃圾桶：卡片悬停的小垃圾桶图标即丢进垃圾桶；页头垃圾桶入口进入垃圾桶视图，可恢复或永久删除；「清空垃圾桶」在页头且须二次确认、**绝不自动清空**；`trashed` 状态持久化，重启后垃圾桶仍生效。
* agent 工具创建的便签若没有坐标 / 尺寸，界面按网格兜底摆放与默认尺寸，用户操作后才写回。

**涉及对象/查询**：`note`（`body` 是唯一内容，`title` 由正文首行派生）；`x`/`y` 位置、`width`/`height` 尺寸与 `z` 层级均为可选字段，`trashed` 标记垃圾桶状态。

**边界与异常**

* 并发修改：沿用 revision 乐观并发，409 时提示并重拉。
* 兼容旧记录：没有 x/y/width/height 也能通过 schema 校验（字段可选，无需迁移）。
* 窗口缩放：渲染时把坐标 / 尺寸临时夹进可见区，保存值不丢；空间恢复后回到原位置（README 已注明）。
* 墙面是**固定宽度、纵向无限**的画布：X 夹在墙宽内，Y 只设安全上限（`NOTE_MAX_POSITION`）；墙面纵向滚动由滚轮 / 滚动条控制，拖动便签期间**不做自动滚动**；大量便签仍按需做可视区裁剪 / 虚拟化（> 300 张）。

**验收标准**

* 「＋」→ 立即出现空贴纸可输入；失焦后文字持久化，刷新仍在。
* 拖动 / 改大小横向夹在墙宽内，纵向可超出屏幕并滚动；**拖动期间墙面不滚动**，便签严格跟手，位置按当前滚动偏移换算成画布坐标；需要换到别的滚动位置时先滚墙再拖；落库后刷新位置与尺寸不变。
* 点或拖任意贴纸，它显示在最上层，且刷新后层级保持。
* 贴纸是方角纸片；清空正文失焦后自动消失，不产生空记录。
* 切到别的侧栏入口再回来，停在上次标签页。
* 新便签出现即置顶并聚焦正文，双击墙面空白处能新建；空墙提示在浅色 / 深色主题下都只是很淡的引导，不抢贴纸。
* 丢进垃圾桶后贴纸从墙面消失、出现在垃圾桶；恢复后回墙面；刷新 / 重启后垃圾桶状态保持。
* 「清空垃圾桶」需二次确认后才永久删除，未确认时垃圾桶内容不变。
* 第 101 张被拦下并提示；垃圾桶满 200 时丢入被拦下并提示先清空；垃圾桶每页 10、加载更多可用；垃圾桶按钮无角标；Smash 二次确认后整墙清空且有动画，确认态点击旁边 / Esc 可取消；垃圾桶入口提示为「打开垃圾桶」。
* agent 工具建的便签出现在墙上（兜底位置 + 默认尺寸），且能被拖动 / 改大小落位。

**Agent 工具**：`desk_note_add`、`desk_note_list`、`desk_note_update`、`desk_note_delete`（位置 / 尺寸字段暂不进工具面）。

## 8. 看板 Board（v2）

**目标**：按项目看任务流转，拖拽改状态。

**用户故事**

* 我为一个项目建看板，任务按状态排在泳道里。
* 我拖一张卡从「进行中」到「完成」，待办列表里也变成完成。

**交互**

* 项目选择器（新建/重命名/归档）；泳道默认 收集箱/待办/进行中/完成（可配列）。
* 卡片显示标题、优先级、到期、标签；拖拽改状态并乐观更新。
* 每列计数；空列显示占位。

**涉及对象/查询**：`project`、`task`（`belongsTo` 边）；泳道 = status 分组。

**边界与异常**

* 拖拽失败回滚并提示；并发修改提示刷新。
* 归档项目只读展示；删除项目需迁移任务归属（v2 内定位为归档，不删数据）。

**验收标准**

* 拖拽改状态与待办列表双向一致；刷新后保持。
* 100 张卡以内拖拽流畅；无重复卡片。

**Agent 工具**：`desk_board_list`、`desk_board_move`。

## 9. 搜索 Search（v2）

**目标**：一个框搜所有对象。

**用户故事**

* 我搜关键词，能同时看到任务、便签、日程。
* 结果按类型分组，点进去定位到对象。

**交互**

* 顶部搜索框；结果分组 + 数量；空结果给建议。
* 匹配 title / body / tags；大小写不敏感；中文按子串。

**边界与异常**

**Agent 工具**：复用各模块 list 工具，v2 再加 `desk_search`。

## 10. 设置 Settings（v1）

**目标**：连接、同步状态、数据管理、关于。

**用户故事**

* 我在设置里完成三条线路（企业微信 / iCloud / Outlook ICS）的连接与测试。
* 我导出全部数据备份，或从备份导入到新机器。

**交互**

* 分区：连接（三张卡，见第 5 节）/ 同步（间隔、立即同步）/ 数据（导出 JSONL、导入、清空需二次确认）/ 关于（版本、许可证、隐私说明）。
* 连接卡的状态与错误文案见第 5 节；保存前必须先「测试连接」通过，失败不落库。
* 危险操作二次确认并展示影响范围。

**边界与异常**

* 导入格式错误逐行报告，不中断已导入部分。
* 导出文件**不含凭据与订阅链接**（`credentialRef` 只存名字，导出时剔除连接配置）。
* 清空数据需输入确认词（不可逆，界面明示）；清空不触碰外部日历。

**验收标准**

* 导出文件可被导入还原（对象数、关键字段一致）。
* 清空操作有确认且不可误触。

**Agent 工具**：`desk_export`（只读导出）。

## 11. Agent 工具层（v1 起随模块）

**目标**：模型能用同一套对象做事，工具行为与界面一致。

**约定**

* 只读工具默认可调用；写工具返回结构化结果和一句摘要。
* 写外部日历（S3）必须带确认；失败的写入不静默。
* 日程 v1 只读：不提供新建/修改外部日程的工具；本地事件与订阅能力同批设计（S3）。
* 工具名统一 `desk_*`，参数与 Store API 对齐，不直接操作文件。
* 每个工具的错误带 `code` 与可操作提示（如「先连接 Outlook」）。

**验收标准**

* 工具调用结果与界面看到的数据一致（同一查询）。
* 工具写操作触发界面刷新（订阅广播），不出现两份真相。
