# 08 · 和 DSH 一起：面板 ↔ 对话的联动入口

> 状态：**已评审并实施**（2026-11-14）。owner 决定：三层一起做、页头入口放 info 旁、日程 / 会话只留只读示例、预填用半句让用户接着写。
> 本文档记录交互与边界；实现落点见第 8 节。**定稿文案见 [`09-ui-copy.md`](09-ui-copy.md)（2026-11-14 定稿）。**

## 0. 一句话方案

不做「每页一个『让 DSH 记一条』按钮」，而是三层：

1. **空状态引导**：便签墙空状态给一个可点的「帮我记一条便签…」入口；任务待办空列只写两行纯文本引导（同便签页句式，**不加点击动作**）。
2. **页头统一入口**：品牌行常驻一个「✦ 和 DSH 说」按钮，按当前 tab 给 2–3 条提示，任何页面都能从同一位置进入对话。
3. **info 浮层升级**：把 slogan 扩成「两种用法 + 示例」，让说明本身承担教学。

三层一起实现；日程 / 会话只给只读示例、不给写入口。

## 1. 问题

- 五个 tab 的 AI 入口不对称：只有笔记有「让 AI 起草」和审阅闭环；便签 / 任务 / 日程 / 会话没有任何「可以对 DSH 说」的提示。
- 面板是 `main` 全局页，与对话区互斥：用户在面板里想「让 DSH 来做」时，没有任何从面板进入对话的路径，只能自己先记住要说什么。
- 首次打开落地的便签墙空态只教「双击 / 点 +」，没有示范对话式用法。

## 2. 原则

- **发现性优先**：入口出现在用户第一次会看的地方（空状态、页头），且全局只有一处常驻入口。
- **不重复**：同一动作不在页头和空状态各放一个大按钮；空状态入口在内容出现后自然消失。
- **不替用户做主**：只把提示词预填进草稿，**不自动发送**；也不自动应用任何 AI 结果。
- **菜单即短句（做好榜样）**：logo 菜单行是一句人话短句（≤10 汉字，通常不带「帮我」），像你会对助理说的一句话；点选后预填的是更完整的请求（范围 / 输出 / 边界放在隐藏的后半段）。菜单行不当动作标题（不写「理清便签」「安排今天」），隐藏预填不写「帮我整理一下」这类开放结果——用户会照着我们的句式说话，提示词本身就是教学。
- **不新增私有 seam**：复用「让 AI 起草」已经在用的官方公开服务 `uiWorkspace.startSession(workspaceId?, options)`。已确认安装版本 0.2.2-rc.3 支持 `whenDraftExists: 'replace' | 'append' | 'keep'`（`ui-conversation` 的 `DraftInitializationOptions`）。
- **不切走是做不到的**：面板与对话互斥，点击入口必然切到会话；这是预期行为，回来后 panel 仍记住上次 tab。

## 3. 交互

### 3.1 页头统一入口（常驻）

- 位置：`DeskHeader` 第一行品牌位。标题徽章（「✦」同桌）与入口**合并成一枚分段按钮**：左半是原来的反色徽章（不变），右半是墨色 0.5px 线框、无填充的「和我说」；整枚按钮打开菜单，不再占用 tab 动作区。
- 形态：左半徽章保持墨色底 + inverted 字 + 14px「✦」字形；右半线框/文字跟随主题反色（浅色主题墨线，深色主题亮线），hover 只给右半加浅底。窄面板不折叠文字（`nowrap`），由副标题让出宽度。
- 点击弹官方 `Menu`：菜单行是短句，点选后把对应的完整请求预填并切到会话（不发送）；悬停 / 聚焦菜单行时用官方 `Tooltip` 显示该行隐藏预填的全文，先看清再点：

| 当前 tab | 菜单行 ① / ② | 隐藏预填（完整请求） |
|---|---|---|
| 便签 | 合并重复的便签 / 把便签变成任务 | `帮我读一遍最近的便签，把重复或相近的说法合并成一条，保留最完整的内容；先给我看合并方案，不要直接改。` / `帮我把最近的便签看一遍，把其中需要跟进的事变成任务放进任务板；先看任务板避免重复，不要改动便签本身。` |
| 任务 | 把日程变成待办 / 把已完成任务存档 | `帮我看看今天的日程和任务板，把今天要做的事理出来，缺的补成任务；已经在任务板里的不要重复。` / `帮我把任务板「完成」列里已经做完的任务归档：先列出准备归档的清单让我确认，确认后再执行。` |
| 笔记 | 挑出本周的高价值内容 / 把好便签写成笔记 | `帮我读一下笔记库本周新增或更新的页，挑出值得反复看的高价值内容，说明理由并摘出可复用的要点；只给清单，不要改文件。` / `帮我从最近的便签里挑出值得长期保留的，整理成笔记库里的一篇新笔记：按笔记库既有格式写 title / date / tags，先给我看提纲和文件名，确认后再写。` |
| 日程 | 看看今天有没有冲突 / 看看这周哪天太满 | `帮我看看今天的日程，按时间列出每一件，标出时间冲突、连轴转和需要提前准备的事项；只给提醒，不要改动日程。` / `帮我梳理本周剩下的日程，按天列出关键事项和时间空档，指出排得太满的日子；建议哪些任务可以放进空档，不要改动日历。` |
| 会话 | 看看哪些会话能归档了 / 复盘这一周 | `帮我读一下最近两周的会话，找出已经结束或讲同一件事的会话，按主题分组列出；每组给出哪些可以归档的建议和理由，只给建议，先不要动。` / `帮我读一下最近一周的会话，按主题归纳我做了哪些事、各自进程到哪一步、还有哪些悬而未决；只输出小结，不要动会话。` |

- 无工作区时：官方 `startSession` 会走 `createFailed` 提示（`draft.workspaceRequired`），入口不隐藏；不额外弹自定义错误。
- 连点：起会话期间按钮 disabled（官方导航是异步）。

### 3.2 空状态引导（首次引导）

- **便签墙空态**（`NotesWall`）：主文案保留「双击空白处新建便签」，副文案改「或点击顶栏「+便签」，也可以直接对我说」；下方加次级按钮「「帮我记一条便签…」」。仅在空状态出现。
- **任务待办空列**（`TaskColumn`）：与便签墙同一句式写满两行纯文本——`双击空白处新建任务` / `或点击顶栏「+任务」，也可以直接对我说「帮我加一个任务…」`；**不加点击动作**（点击入口只保留在便签墙）。进行中 / 完成列的空列仍显示「暂无任务」。
- **笔记库未链接 / 空库**：不新增按钮（「让 AI 起草」已有）；未链接态文案补一句 AI 协作说明。
- **日程**：只读，不放写入口；页头的只读示例（「看看今天的安排」）已足够。空状态文案保持现状。
- **会话**：管理性页面，不放。

### 3.3 info 浮层（`DeskIntroInfo`）

从单段 slogan 改为结构：slogan + 「两种用法：自己点 / 和 DSH 说」+ 3 条示例句（中英双语，随界面语言）。示例只展示，不设点击（避免把说明变成第二个操作区）。

### 3.4 「…」菜单：许愿

- tab 行末尾的「…」菜单**最后一行永远是「许个愿」**（行首 Desk One 徽标字形「✦」，品牌蓝；当前没有溢出 tab，所以它就是唯一一行；以后有溢出 tab 时排在它们后面），行下有小字「去 GitHub 提 feature issue，我帮你整理」。
- 点选 = 把 `coauthor.prompt.wish` 预填进输入框（不发送）：句首「我想给同桌增加一个功能：」留给人写愿望，其后要求 agent 把它整理成 **GitHub feature issue 草稿**（仓库固定 `https://github.com/peiyucn/dsh-sparrow`）：**先给标题和正文草稿、不自动发布、不包含私人内容**。
- 不是「让用户自己定义插件」：这里只是需求收集入口；真正的插件生成 / 安装属于另一项能力，不在本条里承诺。
- 为什么不让 agent 直接发 issue：创建公开 issue 是**对外且不可逆**的动作，必须由人确认；agent 只负责起草和给出 `issues/new` 链接，或经人明确同意后再用 `gh` 提交。

## 4. 边界

- **草稿已有内容**：`whenDraftExists: 'append'`，提示词追加在现有草稿后并换行，不覆盖、不清空。
- **空白会话复用**：`startSession` 会复用当前 / 最近工作区里第一个可复用空白会话，不堆会话。
- **无工作区**：官方 toast，不改选择；按钮保持可点（隐藏会让人误以为功能不存在）。
- **不自动发送**：用户仍需自己按发送；这是与「让 AI 起草」「提交批注」一致的口径。
- **空状态按钮不常驻**：有内容后消失，老用户不受打扰。
- **不碰工具面**：19 个常驻工具保持不变（决策见 `01-object-model.md`）。

## 5. 不做（本期）

- 每个页面常驻的「让 DSH 记一条」大按钮（与「不重复」原则冲突）。
- 对象级操作：任务卡 / 便签卡上的「让 DSH 处理这个」——二期再议（需要会话选择与引用上下文，复杂度高）。
- 右栏 tab / 浮动面板（面板位置议题，另案）。
- 自动发送、自动应用、把 AI 结果写回面板。

## 6. 验收

- 新用户首次打开落在便签 tab，空态同时看到手动与对话两条路；点「让 DSH 记一条」→ 切到会话，草稿预填、未发送。
- 页头入口在五个 tab 都可用，菜单内容随 tab；窄面板不溢出（图标模式）。
- 已有草稿时追加不覆盖；无工作区时出现官方提示、面板不崩。
- 日程 / 会话没有写入口，只有只读示例。
- 中英文案齐全；`verify` 全绿；spec / README / CHANGELOG 同步。

## 7. owner 决定（2026-11-14）

1. 三层一起做（空状态 + 页头入口 + info 浮层）。
2. 页头入口放 info 旁。
3. 日程 / 会话真的不给写入口，只留页头只读示例。
4. 预填文案用半句（「帮我记一条便签：」），让用户接着写。
5. 文案评审（`09-ui-copy.md`，2026-11-14 定稿）后追加：标题徽章与入口合并成一枚分段按钮（左「✦」同桌、右「和我说」）；info 小标的位置等这枚按钮定型后再定。

**便签的预填怎么触发**：便签没有自己的「会话」，所以按钮并不写便签本身——它调用官方 `uiWorkspace.startSession(undefined, { prompt: '帮我记一条便签：', whenDraftExists: 'append' })`：打开（或复用）当前 / 最近工作区的空白会话，把半句指令追加进输入框草稿并聚焦，用户接着写内容、自己按发送；DSH 收到后通过 `desk_note_add` 落库。和「让 AI 起草」是同一条路，只是不带工作区参数、用 `append` 保护已有草稿。无工作区时由官方导航给出「需要工作区」提示。
