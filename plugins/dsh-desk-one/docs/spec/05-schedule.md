# 05 · 日程 Schedule — 聚合设计（S2，只读）

> **实现状态（2026-11-09）**：基础版已落地并 `verify` 全绿（126 个测试）；**真实服务未验证**——企微/iCloud/Outlook 均缺凭据探针，协议细节按 RFC 与公开观察实现，明早 owner 配置后联调。v1 范围与本文件一致：只读、无本地事件、无写回、无订阅。
>
> 模块中文名「日程」、英文 **Schedule**（不用 Calendar）：这里以后不只有日历，还会有日程列表与可排期的待办。
> 底层数据仍是 `event`（日程条目）+ `calendar`（远端日历源）两种 kind，见 [01-object-model.md](01-object-model.md)。

## 1. 目标与非目标

**目标**：把企业微信、iCloud、Outlook 个人三条线路的多个日历聚合成一个可读、可筛、可逐步扩展的「日程」页；只读外部数据，页面本身要有清晰分区，而不是「塞一个日历网格」。

**v1 非目标**：本地事件创建 / 编辑、写回外部、iCalendar 订阅/发布、跨源自动去重、会议室与参与人管理（写回与订阅见 00-overview 决策 7）。

## 2. 页面信息架构（必须有分区）

日程页不是一个单一日历控件，固定四个区域：

```text
┌ 日程 ────────────────────────────────────────────────────────────────────┐
│ 页头：状态（上次同步/失败源） · 刷新 · 今天 · 视图（列表 | 月 | 周） · 日历 │
├────────────────┬───────────────────────────────────────┬─────────────────┤
│ 近期日程        │ 主视图                                │ 日历源           │
│ （未来 7 天）    │ 列表（默认）：按天分组的完整日程列表     │ 企业微信（公司）  │
│ 今天            │   今天                                │  ● 公司日历 ✓   │
│  09:00 周会     │     09:00–09:30  周会   [公司日历]    │  ● 项目日历 ✓   │
│  14:00 评审     │     14:00–15:00  评审   [项目日历]    │ iCloud（个人）    │
│ 明天            │   明天                                │  ● 家庭     ✓   │
│  10:00 牙医     │     …                                 │  ● 旅行     ✓   │
│ …  [查看完整列表]│ 月：月网格（事件条/圆点，点击看详情）    │ Outlook（个人）   │
│                │ 周：周时间网格（重叠/冲突可见）          │  ● 已发布   ✓   │
└────────────────┴───────────────────────────────────────┴─────────────────┘
```

| 区域 | 职责 | 关键交互 |
| :--- | :--- | :--- |
| **近期日程**（常驻栏） | 未来 7 天（今天 + 6 天）按天分组的时间轴摘要；跨源合并、来源色可辨 | 点条目打开详情；「查看完整列表」把主视图切到列表并定位到今天；今天/明天分组标题固定 |
| **主视图** | 三种视图：**列表**（默认，完整日程列表，按天分组、可加载更多）/ **月** / **周** | 视图切换记住上次选择；点空白不新建（v1 只读）；点击事件打开详情 |
| **日历源**（常驻栏 / 窄屏抽屉） | 按「源 → 日历」两级组织：组头 = provider + 账号 + 同步状态；行 = 日历名 + 颜色 + 显隐 + 事件数 | 勾选显隐、点行聚焦「只看这个日历」、改颜色、组头显示失败原因/重试；状态持久化 |
| **事件详情** | 来源、所属日历、时间、地点、描述、链接（可选）、复制、跳转原始客户端 | 只读；打开不打断其它区域；Esc/点外部关闭 |

**响应式（按面板容器宽度，不按视口）**

- 宽（≥ 1180px）：三栏常驻（近期日程 240–280px · 主视图自适应 · 日历源 240–280px）。
- 中（900–1180px）：近期日程并入主视图上方（横向 7 天卡片）；日历源收成页头「日历」popover。
- 窄（< 900px）：单列堆叠；顶部「接下来」卡片（今天剩余 + 明天），主视图保留列表/月/周；日历源为抽屉。
- 任何档位都**不能只剩一个日历网格**：近期日程与列表入口始终可达。

## 3. 日历组织（多源 × 多日历）

1. **两级分组**：provider（企业微信 / iCloud / Outlook）→ calendar（一个源下 N 个日历）。源顺序固定为「工作（企业微信）→ 个人（iCloud / Outlook）」，组内按 `CalendarPayload.order`。
2. **颜色**：每个日历一个颜色，首次同步按固定 8 色板自动分配（避免相邻同色），用户可在日历源栏改；事件条目只用日历颜色，来源徽标/组头表达 provider。
3. **显隐**：每个日历可单独显隐；隐藏只影响视图，不删镜像数据。提供「全部显示 / 只看此源 / 只看此日历」快捷筛选；筛选状态是界面偏好（`localStorage`，不含用户内容）。
4. **数量与去重**：同源按 `(provider, calendarId, externalId)` 去重；跨源重复（同一会议被两个系统各同步一份）v1 **不自动合并**，并列展示并标注来源，避免误合并；后续可做「疑似重复」提示。
5. **失败隔离**：某个源失败时，该组头显示失败原因与重试；其它源、近期日程、列表照常；不把整页变成错误页。
6. **空态**：某天/某源无事件时给轻量提示；全部为空时给「连接日程源」引导。

## 4. 数据与查询

- 镜像数据：`event`（重复事件按窗口展开成实例）、`calendar`（每个远端日历一条，含颜色、显隐、顺序、同步状态、凭据引用名）。
- 查询：按时间区间 + 可选 `calendarIds` / `provider` 过滤，按 `start` 排序；列表按本地日分组；近期日程窗口 = 未来 7 天。
- 跨源合并只是查询投影，不落第二份数据；「总览」复用同一查询（最近日程 + 今日剩余）。

**host 路由（`/api/desk-one/schedule/`，全部过 desk-one 信任栅栏）**

| 方法 | 路径 | 作用 |
| :--- | :--- | :--- |
| GET | `events?from=&to=&calendarIds=&provider=` | 区间事件（只读） |
| GET | `calendars` | 源 → 日历两级清单 + 颜色/显隐/同步状态 |
| POST | `calendars/update` | 改日历 `color` / `enabled` / `order`（只改本地元数据） |
| GET | `status` | 各源同步状态与上次同步时间 |
| POST | `sync` | 手动同步（同源串行、重复点击合并） |
| GET | `connections` | 连接卡状态（不含凭据） |
| POST | `connections/save` | 保存连接（密码/链接进 `ctx.credentials`） |
| POST | `connections/test` | 测试连接（保存前必须先过） |
| POST | `connections/remove` | 断开连接 |

## 5. 三源适配器

| 源 | 通道 | 拉取 | 认证/失效 | 已知限制 |
| :--- | :--- | :--- | :--- | :--- |
| 企业微信（工作） | CalDAV `caldav.wecom.work` | 发现入口 `/.well-known/caldav`；日历家目录疑似裸 `/calendar/`（**未验证**）；按日历 ctag/ETag 增量 | 手机端同步密码；重新获取使旧密码失效 | 非 IANA TZID（靠内嵌 VTIMEZONE）；读限额未查到 |
| iCloud（个人） | CalDAV `caldav.icloud.com` | 发现可能跳 `pNN-caldav.icloud.com` 分片；REPORT 只请求裸 `<calendar-data/>`；窗口 ≤ 366 天 / 400 条 | Apple ID + App 专用密码（需双重认证；改主密码全部失效） | 60 读/分钟、单日历 5 万事件上限；共享/家庭日历可见性**未验证** |
| Outlook（个人） | 发布 ICS 链接（只读） | 条件 GET（ETag / Last-Modified）；按 `UID` upsert | 网页版「发布日历」复制链接；链接失效需重新发布 | 刷新通常 3–24 小时；公司账号可能被策略禁用（v1 只支持个人） |

统一适配器接口：`probe` / `listCalendars` / `pull(cursor, window)`；失败分类 `AUTH_EXPIRED`（不自动重试）与 `TRANSIENT`（退避重试）。

## 6. 同步策略

- 触发：打开面板拉一次；每 15 分钟一次；手动刷新。宿主没运行时不同步（无后台守护进程），页头明示上次同步时间。
- 窗口：`[-6, +3]` 个月；重复事件在该窗口内展开为实例（`payload.rrule` 保留主规则，窗口滚动时重展开并裁剪）。
- 并发：同源串行；跨源总并发 ≤ 2；iCloud 按 60 读/分钟限流。
- 写放大：`KvTable` 无批量 put，首同步分批写入并显示进度；`ETag` 未变跳过写。
- 失败：`AUTH_EXPIRED` 只提示不自动重试；`TRANSIENT` 指数退避（上限 30 分钟）；所有失败写 `calendar.payload.lastError` 并在页头/源组头可见。

## 7. 验收（S2）

- 日程页同时可见「近期日程」「主视图（列表 / 月 / 周）」「日历源」三块，不是单一日历网格；窄屏降级后近期日程与列表入口仍可达。
- 三个源、每个源多个日历时：源→日历两级组织清晰，颜色可辨，显隐/聚焦筛选生效，状态持久化。
- 近期日程与列表是同一查询的两种投影，筛选切换后数据一致，不出现两套真相。
- 同一源同一事件不重复；跨源重复并列展示并标注来源。
- 某源认证失效时只有该源降级，其它区域照常；错误提示可操作。
- 只读：没有新建/编辑外部事件的入口；v1 不出现本地事件创建。
- `npm run verify` 与根 `pnpm run check` 全绿；纯逻辑（RRULE 展开/时区/upsert/排序/分组/筛选）有单测。

## 8. 实现顺序与未验证项

1. **企业微信 CalDAV**（先做：公司日程信息量最大）→ 探针验证 `/.well-known/caldav`、家目录、VTIMEZONE、REPORT 形态。
2. **Outlook ICS**（网页端发布链接；条件 GET + UID upsert）。
3. **iCloud CalDAV**（凭据到位后：分片、REPORT、限流、共享日历可见性）。

未验证项（写代码前先探针钉死）：企微 `/calendar/` 家目录与标准发现链、非 IANA TZID 样本；iCloud 分片/REPORT/`sync-collection` 支持；共享日历是否出现在 CalDAV 集合；Outlook ICS 在 owner 个人账号上的发布入口与刷新延迟。

## 9. 实现备注（2026-11-09 基础版）

- **记录形态**：`event` / `calendar` / `schedule-source` 三种 kind 与便签/任务一样用**平铺字段**存进 `nodes`（`payload` 分层是设计目标，尚未迁移）；域版本不变，旧记录照常解码。
- **日历身份**：`DeskCalendar.remoteId` 存的是**日历集合 pathname**（不是绝对 URL），避免 iCloud 在 `pNN-caldav` 分片间切换时同一本日历生成新行；查询时用当前家目录 origin 拼回绝对 URL。
- **连接卡入口**：v1 放在日程页的「日历源 → 管理连接」浮层（单入口原则），宿主设置页后续再收编；保存前强制「测试连接」通过。
- **同步触发**：打开日程页时若上次同步超过 5 分钟自动同步；面板打开期间每 15 分钟同步；手动同步按钮；宿主关闭即停止。
- **Outlook 增量**：当前每次同步拉整份 ICS（未落 ETag/syncToken）；发布链接本身 3–24 小时才刷新，后续接 `If-None-Match`。
- **重复事件覆盖件拆文件风险**：若服务端把 RECURRENCE-ID 覆盖件拆成独立 `.ics` 资源，主文件展开与覆盖件会产出同一 `externalId`（不同时间），host 侧按「最后写入者胜」去重；需真机探针确认后再做合并策略。
- **未验证（禁止当已验证）**：企微 `/.well-known/caldav` 真实响应与 `/calendar/` 家目录、非 IANA TZID 样本；iCloud 分片跳转/REPORT 限制/共享日历可见性；Outlook 发布链接内容类型与被重定向到非白名单 CDN 的可能。
