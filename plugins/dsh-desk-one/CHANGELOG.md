# Changelog

English | [简体中文](CHANGELOG.zh-CN.md)

All notable changes to `dsh-desk-one` are documented here. The format follows Keep a Changelog and the version numbers mirror the official DSH release line.

## [0.2.2-rc.1] - 2026-11-06

* First release: one **Desk One** entry in the left sidebar hosting a tabbed panel; **Overview** is reserved as the future hub and stays intentionally blank in this release.
* Notes wall: add a note with **Capture** in the command bar or by double-clicking empty space — the new sticky lands where you clicked, on top of the pile, and takes focus; a two-tier header keeps DeskOne's own hierarchy: the first row is the title plus the primary tabs with the top-right reserved for future time-management/to-do widgets, and the second row holds the active view actions (notes: capture / smash / trash; board: new task / sort / archived tasks), both using official button specs; the empty wall keeps a faint two-line hint. Write directly on the sticky, drag it by its body anywhere inside the visible wall (no scrollbars), click or drag a sticky to bring it to the front, resize it from the bottom-right corner, switch colors or drop it into the trash with the trash icon on hover; the sticky is flat square paper with deeper Notion-toned colors and matching deep hue swatches (no gradients), and text, position, size, layer and trash state persist through the official DSH storage domain. The trash entry in the command bar restores or permanently deletes notes, and emptying it is an explicit two-step user action (never automatic).
* Task board: a fixed three-lane board (**To do / Doing / Done**) with colour-tagged cards whose title and description wrap automatically (a stacked swatch opens a five-colour palette), day-granular due dates shown as a calendar icon plus the date (icon only when unset) (overdue in red, due within a day with an amber outline), whole-card pointer dragging (click a field to edit it, press anywhere else to drag) with a straight pointer-following ghost that flies back on invalid drops, plus lane/group highlighting and an insertion line while dragging, double-click-to-add inside a lane, a collapsible Done lane, a two-tier header with new task / sort / archived tasks in its action row plus three view modes (manual / created / due), and an **Archived** view for finished tasks that can be restored or deleted permanently (only Done cards can be archived). Lane ordering is a single manual block sequence: ungrouped cards and group blocks can be interleaved in any order, and dragging a group between cards works like dragging a card. One-level groups are persisted records, not labels: they can be empty, renamed in place, collapsed, reordered by dragging their grip, deleted (their cards become ungrouped), and cards can be dragged into or out of them. Dragging a group moves the whole block like a card (the header and cards follow the pointer); dropping it on another lane moves its cards too, without a confirmation step. Groups in the Done lane can be archived as a unit: the archive view lists one row per group, restoring brings the group and its cards back, and deleting an archived group removes both. Cards can link one or more DSH sessions (and one session can serve several cards): chips carry their live state as colour — available sessions are green, archived/unavailable are neutral grey — and running ones get a slow orbiting green ring (static under reduced-motion); clicking a chip opens that session, and linking never overwrites the card's own text. The **@** entry sits on its own row under the linked chips; its picker is a page-level floating panel (no lane clipping) and lists the same session set as the composer's `@` menu, subagent sessions included. Narrow panels collapse the lanes into count-only columns instead of showing a horizontal scrollbar; an overflowing lane now shows a thin vertical scrollbar instead of squeezing its cards, and group headers use two rows (name + count) so they stay legible in narrow lanes. Lane titles are compact uppercase brand labels (bold with tracking); counts read as labels ("3 tasks") rather than bare numbers. Notes and the board share the same header and button style; object-level actions stay on their cards/lanes. The `desk_task_*` agent tools read and write the same tasks.
* Capacity and clean-up: the wall is capped at **100** notes and the trash at **200**; the trash view renders 10 rows at a time with a total and a **Load more** button, and the trash button no longer carries a count badge. **Smash!** is the red danger action in the command bar — always visible, two-step confirmation, and it sends the whole wall into the trash with a short fly-away animation; an armed Smash cancels when you click elsewhere or press **Esc**. The trash entry sits in the same command bar and its tooltip says **Open trash**; dropping a single sticky into the trash plays the same animation.
* Agent tools (`desk_note_*`) read and write the same notes, and the panel remembers the tab you were on when you come back.
