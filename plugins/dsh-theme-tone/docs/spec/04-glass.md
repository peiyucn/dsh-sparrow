# 04 · 玻璃效果 — dsh-theme-tone

> 本插件原定位是「色调」。玻璃拟态是**另一件事**（chrome 拟态，不是底色/染色），
> 只因复用同一个样式表注入点而暂时同住。**拆分入口已备好**：全部集中在 `src/glass.ts` 一个模块，
> 搬成独立插件时不用动 client half。见第 6 节。
>
> 覆盖面：**顶栏 + 输入框**。浮层（菜单 / 对话框）**不做玻璃** —— 那条路是「不透明 + 色调的光与颗粒」，
> 见第 5 节与 [05-surfaces.md](05-surfaces.md)。

## 1) 前提：只有压在滚动内容之上的元素才配做玻璃

玻璃的本质是**模糊它背后的东西**。背后若是纯色，模糊纯色 = 肉眼零变化。所以先查清楚了 DSH 里谁压着谁：

| 候选 | 是否压着滚动内容 | 依据 |
| :--- | :--- | :--- |
| **输入框底座** `.composerSeat` | ✅ 是 | `position: sticky; bottom: 0; z-index: 7`（`ConversationRoot.module.css:369-374`），sticky 在滚动体内部 |
| 对话顶栏 | ❌ 否 | 官方注释：`header is ordinary column chrome above the scrollport (not sticky)`（`:319`） |
| 左侧栏 logo 行 / tab strip | ❌ 否 | 全树无 `position: sticky` |
| 右侧栏面板 | ❌ 否 | 同上 |

所以：**输入框的玻璃是「真的」**（原生就成立）；**顶栏必须先改成浮层**才有东西可模糊。
浮层虽然也压在内容之上、玻璃在技术上成立，但浮层不做玻璃 —— 见第 5 节。

## 2) 顶栏：三处改动是一组，必须同时存在

```css
[data-phase='active'] { position: relative; }                                    /* ① 定位祖先 */
[data-phase='active'] [data-slot='conversation.session.header'] > * {            /* ② 浮起来 */
  position: absolute; top: 0; left: 0; right: 0;
  z-index: 82;                                                                   /* ABOVE_CONTENT_Z_INDEX */
  background: color-mix(in srgb, var(--dsw-alias-bg-base) 70%, transparent);
  backdrop-filter: blur(12px) saturate(1.15);                                    /* GLASS_BLUR */
}
[data-phase='active'] [data-conversation-scroll] { padding-top: 76px; }          /* ③ 滚区补高 */
```

> 上面的 `z-index` / `blur` 在源码里是模板插值（`ABOVE_CONTENT_Z_INDEX`、`GLASS_BLUR`）——
> **改这两项要去 `constants.ts` / `glass.ts` 改常量**，不要以为这里是一个字面量。

**为什么是 `[data-slot='…'] > *` 而不是槽位元素本身**：槽位产出物带 `data-slot` 锚点，
但它是 `display: contents`（`ui-renderer/src/client/scoped-slots.tsx:709-716` 的锚点契约：
「`display:contents` keeps it layout-neutral」）—— **它自己不生成盒子**，定位它没有任何效果；
真正生成盒子的是它的子元素。

**为什么 ③ 不能少**：① 让 `position: absolute` 认对祖先；② 让顶栏脱离流。脱离流后滚区会顶到 y=0，
正文第一行就被顶栏盖住。补 76px 后：

| | 顶栏 | 滚动内容起点 | 顶栏 border-bottom |
| :--- | :--- | :--- | :--- |
| 官方 | 占 76px 列空间 | y = 76 | y = 76 |
| 本插件 | 脱离流、浮在 y=0..76 | y = 0 + 76 = 76 | y = 76 |

→ **静止时布局等值**，顶栏的分隔线仍与左栏（tab strip 38px + 面板标题 38px = 76px）在列边缘接上
（`ConversationRoot.module.css:37-41` 那条契约）。差别只在「内容现在从它下面滚过」。

## 3) 输入框：玻璃**只做在卡片上**

输入框是**底座**（`.composerSeat`）套**卡片**（`[data-composer-card]`，卡片在 `InputBar.tsx:429`）。
官方两层都是**不透明**的，所以玻璃只做在**卡片**这一层：

| 层 | 官方 | 现在 | 理由 |
| :--- | :--- | :--- | :--- |
| 底座 | `bg-base` 到 36px 的**实色**渐隐带 | **不画**（`background: none`） | 在本插件的色调背景上它读成一条纯色带 |
| 卡片 | `--dsw-specific-input-major` **实色** | **58%** + `backdrop-filter` | **它才是**用户盯着的玻璃面，形状天然等于卡片 |
| 卡片下沿→座底 | 同上（实色渐隐带的下半段） | **不透明**、按背景底部的样子重画（`::after`，见 §3.1） | 挡住从卡片下方滚过去的正文 |

```css
[data-phase='active'] [data-composer-seat] {          /* 底座本体：不画 */
  background: none !important; backdrop-filter: none;   /* ⚠️ 绝不写 position —— 会顶掉官方 sticky */
}
[data-phase='active'] [data-composer-seat] [data-composer-card] {   /* 卡片：唯一的玻璃面 */
  background: color-mix(in srgb, var(--dsw-specific-input-major) 58%, transparent);
  backdrop-filter: blur(10px) saturate(1.45);
}
```

> ⛔ **「渐隐 + 玻璃」不许挂到底座上**（例如覆盖整座的 `::before { inset: 0 }`）：
> 底座是**全宽**的（卡片自己有 `max-width`，两侧留白），`inset: 0` 会把**两侧留白也糊上一层**，
> 读成两块竖直暗矩形，且因 `inset: 0` 跟着底座走、**输入框一变高它就跟着变高**。
> 玻璃归**卡片**（形状天然等于卡片、不外溢），底座**什么都不画**。
> 有回归测试钉住：底座不得再出现 `::before`、只许有 `::after` 一个伪元素、
> 且本体的 `background` 只能全是 `none`。

* **底座为什么必须 `!important`**：官方同位置规则 `.root[data-phase='active'] .composerSeat`（0,3,0），
  我们的 `[data-phase='active'] [data-composer-seat]` 是 0,2,0，压不过。
  **卡片不需要** —— `[data-composer-seat] [data-composer-card]` 是 (0,3,0) > 官方 `.card` (0,1,0)。
  只覆盖 `background` 一个属性；`backdrop-filter` 官方没设，无竞争。
* **为什么 `blur` 收在 12px**：大模糊会**抹掉背后内容的形状**，只剩一团平均色 ——
  读起来像「磨砂塑料」而不是玻璃；玻璃的「通透」恰恰来自**还能认出背后的东西在动**。
  12px 仍足以化开文字与图标、不至于干扰阅读，同时保留可辨的形状与流动感。

### 3.1 底座的 `::after`：为什么是「很矮 + 不透明 + 重画背景」

底座撤掉官方那条实色渐隐带后，**只有一件事**还留在底座上：**卡片下沿到座底那一小条**必须挡住
从卡片下方滚过去的正文（官方用「36px 以下刷实色」解决）。这段就是 `[data-composer-seat]::after`。

**几何**：`bottom: 0`、`height: SEAT_SOLID_PX + SEAT_SOLID_RAMP_PX = 46px`，
顶端 10px 是过渡（落在卡片背后，故不可见）、下面 36px 全实。
**只锚座底、不写 `top`** —— 从座顶往下量会顶掉卡片玻璃并留硬接缝。

**为什么不透明**：设该点页面色 `P = 底色 + L`，面以 α 画 `C`，合成 `α·C + (1−α)·P`。
要让它**恒等于周围**（看不出来）就必须 `C = P`：

| 取法 | 要做到 `C = P` 需要… | 结果 |
| :--- | :--- | :--- |
| **不透明**（α = 1）✅ | **原样画满 P**（底色 + 完整的光 + 颗粒） | 精确成立，没有可调错的比例 |
| 半透明（α < 1） | 画 `α·P` —— 底色与光**都**得乘 α | 漏乘光 = 光翻倍，肉眼读成「相当于两层光了」 |

—— 就是本文件 §3 判据的同一套数学，只是把「两层玻璃」换成了「背景重画」。

**为什么必须连光和颗粒一起画**：底座在背景层（`z-index: 80`）**之上**，
只刷一个 `bg-base` 会把那一片的色调光与颗粒一起盖掉 → 比周围暗一档的平板。
所以照背景底部的样子重画：`bg-base` + `BACKDROP_GRADIENTS` + 颗粒，
并用**单个** `background-attachment: fixed`
（本规则 4 层 `background-image`，per-layer 值少于层数时会**按顺序循环补齐**，
写 `scroll, fixed` 会让第 1、3 段渐变退回按元素自身盒子解析）。

### 3.2 缝挡板：栈内条目之间那条 6px（`buildSeamCss`）

**现象**。底座既然不画填充，栈内条目之间那条 `--dsh-composer-stack-gap`（6px）就是一条
**没有遮挡的窗口**：正文从卡片后面滚过时，卡片上是被玻璃化开的、在这 6px 里却是**原样清晰**的。
真机实测（白条探针按视口钉在缝里，避开流式内容的干扰）：缝内逐行峰值 **252**（完全透出），
官方同位置 **21**（被它那条「36px 以下实色」的背衬挡住）。**这不是"颜色不对"，是"漏正文"。**

**为什么是「挡住」而不是「接上」**：那 6px 间距是官方**有意的语义** ——
todo / goal 是提示信息，与输入框留一点间距是合理的；「接上」会把它收成 0，**不做**。

**做法**：在缝**下面那个条目**上挂一条 `::before`，向上铺满，配方复用座底那条
（`backingPaint()`：不透明底色 + 同源的光 + 颗粒 + `background-attachment: fixed`）。
不透明 ⇒ 逐像素等于背景 ⇒ **静态观感零变化**（实测缝区 mean **0.00** / max **0.0**，
差异只在卡片上沿 15px 内的 max 13.4 —— 那是卡片自己的 `backdrop-filter` 重采样了背后的挡板）。

挂「下面那个」而不是「上面那个」：待办卡根元素是 `overflow: hidden`（官方 `lXshSW_root`），
挂在它身上、向下伸出的伪元素会被**裁掉**。
（同理，**卡片自己**也补不了自己的圆角缺口 —— 伪元素同样被那个 `overflow` 裁掉。）

#### 圆角缺口

只盖那 6px 缝**不够**。卡片是 `border-radius: 12px` 的圆角矩形，而底座透明 ——
「圆角弧线以外、包围盒以内」那一小块三角（缺口）仍然露着背后的正文。
白条探针实测：缺口小窗（x 436–442、y 583–585）读数 **250+**（完全透出），
而紧邻的缝区已被挡到 ~35。官方那条底座背衬在不透明段顺手盖住了它，我们撤掉背衬就得自己盖。

**做法**：带子往上下各多伸 `SEAM_NOTCH_PX`（16 > 圆角半径 12，留 4px 余量）——
深处被卡片自己的不透明背景盖住，**只有缺口那点三角会显示成背景色**：

| 缝 | 高度 | 锚法 | 缺口 |
| :--- | :--- | :--- | :--- |
| 停靠卡 ↔ 停靠卡 | `calc(6px + 32px)` | `bottom: calc(100% - 16px)` | **两头都补**（两张都是不透明卡） |
| 最后一张 ↔ 输入框卡 | `calc(6px + 16px)` | `bottom: 100%` | **只往上补**上面那张 |

**为什么输入框卡那条只往上补**：下面那张是**玻璃**，往它顶里伸＝把背衬塞到玻璃背后，
那一片就不再透正文（实测卡片内部会从 113 掉到 ~41）。

**⚠️ 宿主必须是「卡的父元素」，不能是卡自己**：卡片带 `backdrop-filter` ⇒ **自成层叠上下文**
⇒ 伪元素（哪怕 `z-index: -1`）仍然画在**停靠卡之上**，于是补缺口的那 16px 把待办卡的底边
**涂成了背景色**（实测卡底 16px 从 ~52 掉到 ~25，肉眼就是被削掉一条）。
父元素是 `position: static` 的普通盒、不成层叠上下文 ⇒ 伪元素落回**座位**的层叠上下文，
与另外两条一样待在停靠卡背后。
门（有停靠卡 / 没有 queue）仍挂在**座位**上，宿主是**它里面的那个父元素** ——
两者之间必须有**后代组合符**：写成 `[data-composer-seat]:has(> [data-composer-card])`
会把宿主变成座位自己、伪元素挂回底座（实测缝反而漏），这条也进了守卫。

**哪些缝存在、各自的门**（官方次序 todo(0) / goal(10) / queue(20)，且 `QueueDock` 自带
`margin-bottom: calc(0px - stack-gap - 3px)` —— 实测**塞进输入框卡下、重叠 3px**）：

| 缝 | 挂在谁身上 | 门 |
| :--- | :--- | :--- |
| 待办 ↔ 目标 | 目标条 wrapper | 前面有 todo（兄弟选择器 `~`） |
| 目标 / 待办 ↔ 排队 | 排队卡 wrapper | 前面有 todo 或 goal |
| 最后一张 ↔ 输入框卡 | 输入框卡 | 有 todo 或 goal，**且没有 queue** |

**边界（最容易写错的地方）**：无停靠卡时输入框卡就是栈内第一项、上方**没有缝**；
排队卡在场时它与输入框卡**重叠**、那条缝**也不存在**。
这两种情形下无条件挂带子会把它画到**底座外**（盖住正文），所以门上必须带 `:has()` 判断。
两个 wrapper 官方是 `position: static`，`bottom: 100%` 需要它们当包含块，故补
`position: relative`（无偏移、不改布局；已核其子树里没有依赖「座位」当包含块的绝对定位后代）。

**为什么独立成一张表**：玻璃表有一条守卫「不许出现 `:has()`」（它只该锚在输入框 / 顶栏上），
surface 表有一条守卫「不许出现 `data-phase`」——而本表两条都要用。**三张表各守一条底线。**

**真机验证**（白条探针按视口钉住，A/B 只切挡板）：待办 ↔ 目标、目标 ↔ 排队两条 6px 缝
由 **255 漏** → **~40–41 挡住**；输入框卡内部（玻璃）**113 不变**；排队卡 ↔ 输入框卡实测
**-3px 重叠**、本就无缝，门正确关掉。补圆角缺口后：左下 / 右下圆角缺口由 **250+ 漏** →
**~20–26 挡住**，6px 缝 **~20–34 挡住**，待办卡卡身 **~52 不变**（没被涂掉）、
输入框卡玻璃 **124 不变**。

**回归守卫**：`test/seam.test.mjs` —— 三条缝都在、每条都带默认门 + 只 active、
挡板必须不透明 + 同源配方 + 单个 `background-attachment: fixed`、
压在条目背后 + 不吃事件、**高度 = 缝间距 + 圆角缺口**（停靠卡那两条两头都补、
输入框卡那条只往上补，且补贴必须大于官方 12px 圆角）、
三个宿主都补成包含块且不带偏移 / `z-index`、
**门与宿主必须分开**（宿主不得并进座位自身）、三种「没有缝」的情形必须被门挡住、
底座本体不得挂伪元素。

## 4) 耦合与风险（这套效果最脆的地方，测试逐条钉住）

| 耦合 | 值 / 锚点 | 官方变了怎么办 |
| :--- | :--- | :--- |
| 顶栏高度 | **76px**（= 左栏 38 + 38） | 官方改这个数字 → 顶栏分隔线与左栏错位。测试按 `38+38` 断言 |
| 顶栏槽位名 | `data-slot='conversation.session.header'` | 官方改名 → 顶栏不浮（不报错，静默失效） |
| 滚动体 | `[data-conversation-scroll]` | 同上 |
| 输入框底座 | `[data-composer-seat]` | 同上 |
| 输入框卡片 | `[data-composer-card]`（`InputBar.tsx:429`） | 同上 |
| 相位 | `data-phase='active'`（**卡片额外含 `hero`**） | 官方有**三档**：`settling` / `hero`（新建会话首页）/ `active`（`ConversationRoot.tsx:355`）。hero / settling 下顶栏是 `display: none`，补 76px 会把正文顶下去 —— 所以除**卡片那两条**外**所有规则都限定单 active**（有测试）。卡片走 `:is(active, hero)`，理由见 §5.4 |
| 渐隐带高度 | **36px**（官方 `:381-385` 的 px 停点） | 官方改这个数字 → 我们的 mask 曲线与几何渐隐带错位；**现在它同时是「几何」和「遮罩曲线」两个用途** |

**不依赖任何官方 hashed 类名**（有测试），所以官方改组件内部样式不会连累我们；但**锚点改名会静默失效**，
这也是为什么每一处都留了测试与注释。

**拖拽条（`.widthHandle`）必须压回 `top: 76px`**：官方把它「绝对定位在 `.body` 里，
让辉光落在顶栏下缘之下」，而顶栏浮层化之后 `.body` 从 y=0 开始 → 辉光会延伸到顶栏区域，
且**画在玻璃顶栏之上**。

几何链（`ConversationRoot.tsx:372-392`）：`.root > [顶栏槽位] + .body > (.scrollBody + .widthHandle)`，
官方的 `.widthHandle` 是 `.body` 里的 `absolute; top: 0; bottom: 0` ——
**官方顶栏在流内占 76px，所以 `.body` 从 76 起，辉光天然进不了顶栏**。

**修法：把拖拽条本体压回 `top: 76px`（= `HEADER_HEIGHT_PX`），即恢复官方几何。**
只锚 `[data-width-handle]`（ConversationRoot 那条、带 `::after` 光带）；
AppFrame 的 `[data-side]` 手柄长在 frame 里且**没有光带**，不动它。
只改 `top`，不动 `bottom` / 宽度 —— 可拖高度少掉顶栏那 76px，与官方一致（官方在顶栏区本来就拖不到）。
守卫见 `test/glass.test.mjs`。

## 5) 浮层**不做玻璃**；液态玻璃做在**输入框**上

浮层（菜单 / 对话框 / listbox）走**实色 + 色调的光与颗粒**那条路（05 / `src/surface.ts`），
玻璃只留给**控制层**。判据（可推广）：**玻璃只给控制层**（浮在内容之上的控件），内容面一律实色。

**Apple HIG 是这条分工的依据**：

> **Don't put glass on lists, cards, or media content.**
> **Liquid Glass is exclusively for the navigation/control layer floating above content.**
> **Use the regular variant wherever background content could hurt legibility or the component carries a lot of text.**

设置 / 云端文件 / 归档都是**内容面**（列表 / 卡片 / 表格），做玻璃既违反规范、又让内容变透明。

**分工**：

| | 玻璃（本文 / `src/glass.ts`） | 抬升面质感（05 / `src/surface.ts`） |
| :--- | :--- | :--- |
| 做在谁身上 | 对话顶栏、**输入框（液态玻璃）** | 菜单、listbox 弹层、**模态弹窗**、血缘树、任务列表、提示条 |
| 手段 | 半透明 + `backdrop-filter` + **一圈镜面高光** | 不透明填充 + 径向渐变 + 颗粒 |
| 失败长什么样 | 退化成半透明（仍可用） | 退化成官方实色（仍可用） |

### 5.1 输入框卡片的三件套

| 件 | 值 | 为什么 |
| :--- | :--- | :--- |
| 半透明填充 | `--dsw-specific-input-major` @ **`.58`** | 玻璃只做卡片这一层，**它这一层就是最终不透明度** |
| **一圈镜面高光** | 上 `30%` / 左 `20%` / 右 `12%` / 下 `8%` | 见 §5.2 |
| **悬浮投影** | `0 7px 20px rgba(0,0,0,.21)` + `0 2px 5px rgba(0,0,0,.17)` | 叠在官方 `--dsw-elevation-soft` **之后**（并列，不替换）—— 官方那条只有 **3% 黑**，读不出抬升 |
| 真模糊 | `blur(10px) saturate(1.45)` | 与顶栏（`blur(12px) saturate(1.15)`）**允许不同档**，理由见下 |

#### 通透度与悬浮投影：为什么是这些值

**① 通透度**：实测阶梯（条纹探针铺在卡片背后，取卡片内部条纹可见度，越大越通透）：
`12px / 62%` 76 → **`10px / 58%`（本值）80** → `8px / 52%` 87 → `6px / 46%` 103。
模糊与填充**两个都在压通透**，同向调会叠加。选 `10px` 而非更低：变化看得见，
又不会让背后文字化不开 —— 玻璃的通透恰来自**还能认出背后有东西**。

> **⚠️ 一条不成立的旧约束**：「卡片与顶栏模糊必须同档」（理由是「同一块玻璃的两个部件，
> 不一致会在交界处露断层」）**不成立** —— 顶栏在**顶部**、输入框在**底部**，
> 两者**永不相邻**，没有交界可言。真正相邻的是底座不透带与卡片（同一个视觉组，另行守住）。
> 故现在只要求「卡片不重于顶栏」，顶栏保持不动。

**② 悬浮投影**：官方 `--dsw-elevation-soft` 实测 ≈ `0 4px 16px #00000008`（**3% 黑**）。
四档候选下**卡片下缘**亮度（越低越实）：官方（不叠）35.2 / soft 24.8 / strong 18.6 / float 16.6。

> **⚠️ 已排除的风险：自投影不会透出来压暗卡片。** 卡片是半透明的，影子若落在自己包围盒内
> 会被 `backdrop-filter` 采进背景、反而把自己压暗。**实测不存在** —— 偏移是 `0 4px`（向下），
> 影子落在卡外：四档下卡片**内部**亮度**恒为 80.1 不变**，只有卡下缘变暗。

**往回收时三项一起收**（不透明度 / 模糊半径 / y 偏移）：只降 alpha 会让影子
「淡但仍在远处糊一片」；只减 blur 又会「小而硬」；三项同收，影子才是整体**变小变淡**。
真机阶梯实测（卡片正下方影子带亮度，**越高 = 影子越淡**）：

| 档 | 影子带亮度 |
| :--- | ---: |
| `.30 / 28px / y10` | 216.8 |
| `.24 / 22px / y8` | 228.4 |
| **本值 `.21 / 20px / y7`** | **233.0** |
| `.18 / 18px / y6` | 236.2 |
| `.12 / 14px / y4` | 243.1 |
| `.06 / 10px / y3`（几乎无） | 246.6 |

**回归守卫**：`test/glass.test.mjs` 把**上限**钉住（主投影 alpha ≤ 0.26、blur ≤ 24px），
同时钉**下限**（≥ 0.15）—— 这个旋钮已经来回走过两次，避免第三个人再推上去或收没了。

> ⚠️ **这一档已接近「收没了」的边界**。若还要再收，应当先确认是否真的还需要悬浮感 ——
> 悬浮感是明确要求过的，一路收到 0 就退回官方那种**读不出抬升**的状态；
> 那时该做的是**去掉这条投影**并明确记录，而不是把 alpha 磨到 0.1 以下。

⚠️ **调这条只许动 `GLASS_CARD_LIFT` 这一个常量**：`GLASS_SPECULAR_RING` 那几条 `inset`
是**边光**（玻璃厚度），与悬浮投影是两件事，别混着调。

### 5.2 边光：**按光路做** —— 上/左是光、右是阴影、下是焦散

本应用的主光是**左上方**。一块**有厚度**的玻璃被光照亮时，四条边的物理角色**完全不同**：
**背光侧壁处在自己的阴影里**、比背景**更暗**，这一条同时给出两个信息 ——
**① 光的方向（左亮右暗）；② 玻璃的厚度**。

```
       光源 ↖
  ┌──────────────┐  ← 上缘：正对光源 → 高光（最强）
  │╲            ╱│
  │ ╲          ╱ │  ← 左缘：斜射 → 高光（次强，不是满光）
  │  ╲        ╱  │  ← 右缘：背对光源 → 阴影（不是光！）
  └──────────────┘  ← 下缘：穿过玻璃体 → 焦散（弱光）
```

所以右缘必须是**暗色** inset（不是亮色）；左缘弱于上缘（斜射 vs 正对），且带一点柔（不是镜面正反射）。
四边都给光的话，**光源方向就丢了** —— 那正是「看着假」的根源。

> ⚠️ **iPhone 那张参考图不能照抄**：它的光是**正上方**打下来的，左右**对称**；
> 本应用是**左上方**，必须**左亮右暗**的不对称（有守卫钉住）。照抄对称反而错。

#### 光**沿边衰减**，不是均匀光条

`inset box-shadow` 的**每条边天生均匀** —— 它只能做「一圈等亮的壁」，
既做不出**沿边衰减**，也做不出**向内的柔化**，强度不随位置变化，读起来就是**一圈薄描边**。
修法：**锚在光源角落的细长椭圆**（写进 `background-image`）：

```
   ◉ 光源（左上角）
   ┌────────────────────┐  ← 上缘：靠左最亮，向右渐暗（横向衰减）
   │                    │
   │                    │  ← 左缘：靠上最亮，向下渐暗（纵向衰减）
   └────────────────────┘
```

| 图层 | 椭圆 | 作用 |
| :--- | :--- | :--- |
| 上缘 | 横向铺满、纵向极扁（锚 `at 0% 0%`） | 沿上边向右衰减 + 往内柔化 |
| 左缘 | 纵向铺满、横向很窄（锚 `at 0% 0%`） | 沿左边向下衰减 + 往内柔化 |

两条都锚在**同一个角**，所以**左上角最亮**（两层叠加），向右、向下各自衰减
—— 这就是「光从左上方来」。**一个工具同时解决三个问题**（均匀 / 薄 / 锐利）。

> **为什么不用 `background-size` 切横条**：那样切出来的条在**垂直方向仍是硬边界**
> （只是把「均匀的竖条」换成「均匀的横条」），「薄 / 锐利」解决不了。
> 细长椭圆的衰减是**两个方向都连续**的。

**与 `inset` 环的分工（两者都在）**：

| 层 | 负责 | 参数 |
| :--- | :--- | :--- |
| `background-image` 椭圆 | **主光**：沿边衰减 + 向内柔化（上缘 + **左缘**） | 见下表 |
| `inset` 环 | **底光**：一圈连续、绕得过圆角的兜底（**只管上 / 下**） | 见下表 |

#### 最终取值

| 边 | 相对光源 | 角色 | `inset` 底光 | 渐变主光 |
| :--- | :--- | :--- | :--- | :--- |
| 上缘 | 正对 | **高光**（最强） | `0 1px 2px 0` @ `14%` | **`28%`**（`ry 3%`） |
| 左缘 | 斜射 | **高光**（窄而暗） | —（只走渐变层） | **`12%`**（`rx 1.6%`） |
| **右缘** | **背对** | **阴影**（暗色 `bluish-1000`） | `-1px 0 2px 0` @ `10%`(light) / `6%`(dark) | — |
| 下缘 | 穿过玻璃体 | **焦散**（最柔） | `0 -1px 2.2px 0` @ `9%` | — |

阴影浓度按轴分（`SHADE_ALPHA`）：浅色轴 `10%`（近白底需要它立形）、深色轴 `6%`（暗底重了发脏）。
**阴影侧两轴都有** —— 它属于**光路**，不是浅色轴的补丁。

**左缘为什么必须窄而暗**：物理上侧壁的光只是「**透过玻璃看到厚度**」，应当是**窄而暗的一条**
（`rx 1.6%` ≈ 21px、可见约 12px；α `12%` 不到上缘的一半），不是一大片亮区。
**左缘不得同时出现在 `inset` 环里**：底光环与渐变层同一位置会**叠加**（13% + 13% ≈ 24%），
把收窄的左缘又拉宽回去 —— 现在**左边只由渐变层负责**。
判据（有守卫）：左缘 α 必须 < 上缘的六成、横向半径 ≤ 3%、**不得同时出现在 `inset` 环里**、
左上角叠加亮度（`1−(1−a)(1−b)`）≤ 45%。

**「厚度感」由两处一起表达**：上缘**柔化带 `ry`**（主要来源）与 `inset` 底光的 **blur**；
调一个要想到另一个。本机无头复现逐像素量过**上缘亮度剖面**（`ry` → 可见厚度）：

| `ry` | 第0px | 第1px | 第2px | 第3px | 可见厚度 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `0.040` | 93.3 | 77.0 | 61.0 | **48.3** | 4px |
| `0.034` | 91.3 | 74.3 | 56.0 | **41.0** | 4px（仍看不出） |
| **`0.030`（本值）** | 91.5 | 73.1 | 51.2 | **36.0** | **3px** |
| `0.020`（越界对照） | 90.5 | 60.9 | 37.0 | 36.0 | 2px（像描边） |

**根因（值得记住，别再凭感觉小步挪）**：小步挪 `ry` 会**先改亮度、后改厚度** ——
`0.040 → 0.034`（−15%）只改了第 3 个像素的亮度（48.3 → 41.0），**可见厚度仍是 4px**，
等于没做；`0.040 → 0.030`（−25%）才把可见厚度压到 **3px**，是可以被眼睛确认的一档。
要让眼睛确认「变薄了」，得**跨过那个像素台阶**。

> **判据是双侧的，不是单边下限**：`0.030` 是**量出来的描边阈值**，别再往下
> （`0.020` 那档可见带只剩 2px，已贴到「过于锐利」的观感）；
> 上界是 `ry ≤ 0.05`（再大就过厚）。守卫写成 **`2px ≤ blur ≤ 3px`** 且
> **`0.03 ≤ ry ≤ 0.05`** —— **别只朝一个方向推**。

**α 与阴影浓度不参与厚度调整**：说的是「**薄**」（宽度），不是「**淡**」（亮度）。
压 alpha / 阴影浓度会让**光源方向**丢掉（左亮右暗的不对称是「光从左上来」的全部证据），
所以那两项在历次厚度调整里**一次都没动过**。要再收厚度，先动 `ry` 与底光 blur。

#### 为什么 `inset` 仍不可少

官方卡片圆角 **`border-radius: 22px`**（`InputBar.module.css:55`）。`linear-gradient` 是**直线带**，
到圆角处被裁断 —— **光绕不过圆角**。`inset` 阴影沿元素**自身圆角轮廓**描边，天然绕圈
（右下角那一带靠它，椭圆到不了）。避开 `box-shadow` 的理由**不成立**：
官方那条 `--dsw-elevation-soft` 是**外**投影，与内阴影**可并存**（逗号并列），
故写成 `box-shadow: var(--dsw-elevation-soft), <inset…>`（有守卫）。

**守卫钉住**：① 光必须写在 `background-image` 且**两条都锚在左上角**；
② 椭圆纵向/横向半径**不得为 0**（否则退回硬边）；③ 玻璃不得「薄」—— `inset` blur 全部 ≥ 2px；
④ 生成的 CSS 不得含**浮点噪声**（`1.1 * 100` 会漏出 `110.00000000000001%`）；
⑤ 右缘不得出现在高光里、必须在阴影里；⑥ 左缘弱于上缘、强于下缘；⑦ 左右必须**不对称**。

### 5.3 两轴的差别**只在阴影浓度**（光路是同一套）

阴影侧（右缘）**两轴都有** —— 它属于**光路**（背光侧壁必然比背景暗），不是浅色轴的补丁。

| | 阴影浓度 | 为什么 |
| :--- | :--- | :--- |
| 浅色轴 | `10%` | 近白底上需要它来立形（白高光在近白面上读不出来） |
| 深色轴 | `6%` | 暗底上重了会**发脏** |

> **未做的部分**：苹果还有 **refraction**（边缘把背后内容轻微折射 / 放大）。
> CSS 只能靠 `backdrop-filter: url(#feDisplacementMap)` 近似，Chromium 支持但代价高、易糊，
> 当前**未做** —— 观感上「光 + 阴影 + 焦散 + 模糊 + 提饱和」已经能读出玻璃。

### 5.4 新建会话首页（`hero`）：卡片也要玻璃

**根因**：官方 `data-phase` 有**三档**（`ConversationRoot.tsx:355`）：

```
const phase = settling ? 'settling' : hero ? 'hero' : 'active'
```

首页（还没有会话）走的是 **`hero`**，而本模块原先每条规则都写死 `[data-phase='active']` ——
于是首页**一条都不命中**，卡片留着官方的 `background: var(--dsw-specific-input-major)`
（**不透明实色**，`InputBar.module.css:56`）= 一张灰板。

**修法**：把**卡片那两条**（深 / 浅轴）的相位门放宽成 `GLASS_CARD_PHASES = ['active', 'hero']`，
经 `phaseGate()` 拼成 `:is([data-phase='active'], [data-phase='hero'])`。

⚠️ **用 `:is()` 而不是并列选择器，是为了不改变特异度** —— `:is()` 取参数中最高者，
两个参数都是 `(0,1,0)` 的属性选择器，所以整条规则的特异度与原先完全一致。
（底座那条注释记着特异度算错的代价：曾把官方 `sticky` 压成 `relative`，输入框跟着内容滚走。）

#### ⛔ 只许放宽卡片，别顺手带上别的

| 规则 | 为什么**必须**留在单 `active` |
| :--- | :--- |
| 底座 `::after`（不透带） | 它是 `position: absolute; bottom: 0`，**包含块来自底座自己**；而官方只在 `.root[data-phase='active'] .composerSeat` 里写 `position: sticky`（`ConversationRoot.module.css:369-371`），`.composerSeat` 基规则**不含** position ——**hero 下底座不是定位元素**，带子会改锚最近的定位祖先（hero 下是 `.root`；若该 tab 有 composer overlay 则是 `.scrollBody`，见 `:421-422`）——两者都**不等于**「卡片下沿到座底那一小条」，于是带子会跑到别处去画 |
| 顶栏浮层 + 滚区补 76px | hero 下顶栏本就 `display: none`，补 76px 会把正文顶下去 |
| 拖拽条 | hero 没有拖拽条（`ConversationRoot.tsx:382` 只在 `phase === 'active'` 渲染） |

`settling` **不在列内**：官方把底座设成 `visibility: hidden`
（`ConversationRoot.module.css:474`），卡片随之不可见，画不画都一样。

守卫（`test/glass.test.mjs`）逐条钉住：卡片两条都必须同时含两个相位；
其余每条规则必须是**单** active 且不得出现 `:is(`；底座不透带那条不得含 `hero`。

> **首页上「模糊」这一项天然弱（物理事实，不是缺陷）**：第 1 节那条前提 ——
> 「玻璃的本质是模糊背后的东西」—— 在首页上**打折**：hero 的卡片背后是**干净的背景层**
> （没有正文从它后面滚过），所以 `backdrop-filter` 那 `12px` 模糊几乎**无事可做**，
> 此时卡片读起来更像「半透明填充 + 边光」而不是「磨砂玻璃」。
> 半透明与边光都照常生效（那是主要观感来源）。真机上若觉得首页卡片偏「薄」，
> 该调的是**填充 α 或边光**，而不是加模糊（加模糊在无内容背景上照样看不出来）。

### 5.6 「未选工作区」待启动态：**把边界让回官方那条虚线框**

首页在「还没选工作区」时，官方给输入框卡片画一圈**虚线圆角框**，并**同时**把
`--dsw-elevation-stroke-color` 设成 `transparent` —— 即它刻意让那条虚线成为**唯一**的边界。

本插件的玻璃给卡片**无条件**加了悬浮投影 + 内嵌边光，于是两套边缘语言叠在一起
（owner 2026-09-20：「点击选择工作区的页面，改成玻璃输入框后，它这个描边就有点不和谐了」）。
**定案：撤我们的、留官方的。**

| 撤掉 | 保留 |
| :--- | :--- |
| 悬浮投影 `GLASS_CARD_LIFT`（虚线框已承担「立形」） | 官方自己的 `--dsw-elevation-soft`（官方抬升语义，不归我们管） |
| `inset` 边光 `rimFor()`（与虚线并存就是两条边） | 玻璃**填充**与 `backdrop-filter`（卡片本体仍是玻璃，只是边缘交给官方） |

#### 为什么判定必须靠**行为探针**，而不是 CSS 选择器

官方那个状态只体现为一个 **CSS-module 哈希类名**（形如 `uV2eYG_cardWorkspaceTrigger`，每次构建都变）
—— 仓库红线禁止写哈希类名。而它同时写入的**语义属性全部不可用**，实测普通态下三个候选
**都误命中**：

| 候选选择器 | 普通态 | 被谁污染 |
| :--- | :--- | :--- |
| `:has([aria-haspopup='menu'])` | **true** | 本插件的 `ccb-model-trigger`（模型选择器） |
| `:has([aria-haspopup])` | **true** | 附件按钮（`listbox`）/ 权限按钮（`dialog`） |
| `:has([contenteditable])` | **true** | 输入框本身 |

唯一可靠的判据是**那条虚线伪元素自己的签名**：官方用「实色块 + 虚线遮罩」画那圈框，
所以页面上**查不到任何 `border-style: dashed`**（`border` 全是 `none`）。签名是两条同时成立：

1. `::after` 的 `content` 不是 `none` / `normal` / 空串（**是**在渲染）；
2. 它的 `mask-image`（或 `-webkit-mask-image`）里含 `stroke-dasharray`
   （官方那段内联 SVG 圆角矩形的 `stroke-dasharray='4 4'`）。

判定做成纯函数 `src/workstart.ts`（`isWorkstartProbe`），client 侧用 `MutationObserver`
观察 `class` 变动、同帧合并后读一次 `getComputedStyle(card, '::after')` 并打 / 摘
`WORKSTART_ATTR`；卸载时一并摘掉。真机实测三段闭环：普通态无属性 → 虚线出现即打上
（投影与 inset 都撤掉、模糊保留）→ 虚线消失即复原。

守卫在 `test/workstart.test.mjs`（判定纯函数）与 `test/glass.test.mjs`
（CSS 形状：那条规则只能剩 `var(--dsw-elevation-soft)`、不得含 `inset`、且必须排在卡片玻璃规则**之后** ——
同特异性靠后者胜出）。

### 5.5 右边栏：**被抬到 82 之后，得自己画一遍**光与颗粒

**根因是抬升的代价**（与顶栏「金光没了」同一类，见 [03-palette](03-palette.md) 的不变式）：

| | z-index | 结果 |
| :--- | :--- | :--- |
| 背景层（光 + 颗粒） | `80` | —— |
| **右边栏**（为不被内容盖住而抬） | **`82`** | **跑到背景层上面 → 吃不到光与颗粒** |

它官方是 `background: var(--dsw-alias-bg-base)`（**不透明实色**，`SidebarRight.module.css:34`），
所以**底色已经被 token 染对了**，缺的只是质感。

**修法**：让它自己叠一遍背景层那套 —— 与顶栏同一思路，区别是**顶栏半透明（要先铺 fill 再画光）、
它是不透明实色底（直接在底色上叠图层）**：

```css
body:not([PLAIN]) [data-sidebar-right-panel] {
  background-image: var(--…-grain-tile, none), <BACKDROP_GRADIENTS>;  /* 与背景层同源 */
  background-attachment: scroll;
  background-size: auto, 100vw 100vh, 100vw 100vh, 100vw 100vh;
  background-position: calc(100% - 100vw) top, right top, right top, right top;
  background-repeat: repeat, no-repeat, no-repeat, no-repeat;
}
```

* **用 `background-image` 而不是 `background` 简写** —— 简写会连 `background-color` 一起重置，
  把官方那层 `bg-base` 底色抹掉。
* **不写 `background-color`** —— 官方底色本来就是对的，不该动。
* 与背景层**同源**（共用 `BACKDROP_GRADIENTS` 常量，不复制粘贴数值）。

#### ⛔ `background-attachment: fixed` 在这里是**错的**

**症状**：右边栏**在弹出/收回过程中，上下亮度骤增**，静止时没事。

**根因**：`background-attachment: fixed` 的定位区**不是恒定的** —— 只要元素（或任一祖先）
带**非 `none` 的 `transform`**，它就从「视口」**静默改判为元素自己的盒子**，百分比随之
按元素盒解析。而官方 `.panel` 的开关动画恰好就是 `transform`
（`SidebarRight.module.css:36-47`：`translateX(100%)` ←→ `none`，`0.3s`）：

| 相位 | 定位区 | `at 50%` 落在 |
| :--- | :--- | :--- |
| 静止（`transform: none`） | 视口（宽 1280） | **640** ✓ |
| 滑动中（任意非 `none` transform） | 面板盒（宽 380） | **190** ✗ |

`at 50%` 的 x 锚点从视口中心跳到面板盒中心 → 顶光/底光**灌进面板**；动画一结束 regime
又翻回来 → 就是「**骤增**」。静止态没事，所以**截不到图**。

⚠️ **`transform: translateX(0px)` 这种看起来是空操作的值同样触发改判** ——
不能靠「值等于 0」绕过去。

**实测证据**（本机无头复现；面板几何完全相同，逐像素与「无面板」参照比对）：

* 静止 + `fixed` + `at 50%` → mad **0.2**（正确）
* 动画 + `fixed` + `at 50%` → mad **26.4** / max 90（错，且在 y=2 与 y=717 最重 —— 正是「上下」）

**白线探针**直接读出定位区宽度：900px 宽的面板里 `at 50%` 落在 **x = 830**（= 380 + 450，
即元素盒的 50%），而不是视口中心 640。

**修法：完全不用 `fixed`**，改成「**显式视口尺寸的背景盒 + 右对齐**」。
`.panel` 是 `position: absolute; right: 0`，承载它的 frame 又是全窗宽
（`AppFrame.module.css:84-88`：`rightbarCol` 是 `overflow: visible`，不裁切）——
所以**面板右缘恒等于视口右缘**。于是：

* **渐变层**：把图片盒**显式**写成 `100vw × 100vh`（不能用 `auto`，否则盒宽会在两种
  regime 下分别是视口宽 / 元素宽），再 `right top` —— 图片右缘贴元素右缘、宽度又是视口宽
  ⇒ 盒子恰好覆盖视口，`at 50%` 落在视口中心。**两种 regime 同解**，压根没有可切换的东西。
* **颗粒层**：贴图是自铺瓦片，`right` 会给它一个图幅大小的相位偏移；写成
  `calc(100% - 100vw)` 后瓦片相位与背景层**逐像素一致**。
* 附着用 `scroll`（初值）**自始至终不变** ⇒ 动画中面板外观是**刚性平移**，连续、无跳变。

实测：静止态与未改前逐像素 **0.0/0**（不回退）；静止帧与动画首帧 **0.0/0**（交班处无缝）。

⚠️ `background-size` / `-position` / `-repeat` 都是 **4 层**，**必须给足 4 个值** ——
值少于层数时会**按顺序循环补齐**（本插件栽过：写「`scroll, fixed`」等于两者交替，
第 1、3 段渐变退回按元素盒解析）。**不许再退回任何一个 per-layer 属性只给一两个值。**

> **判据（可推广）**：凡被抬到背景层**之上**、且**不透明**的面，都会丢质感；
> **半透明的**（顶栏）要自己画 fill + 光，**不透明的**（右边栏）只需叠光与颗粒。
> 有守卫钉住右边栏这条（不得用 `background` 简写、不得写 `background-color`、必须同源、
> **不得用 `background-attachment: fixed`**、三个 per-layer 属性各 4 个值）。

> **教训（可推广到任何 `fixed` 背景）**：`background-attachment: fixed` 与 `transform`
> **不能共存** —— 元素或**任一祖先**一旦有 `transform`（**任意深度**，实测到第 6 层仍成立），
> `fixed` 的定位区就变成元素盒。**静态与动态 `transform` 都会触发**（`translateX(0px)` 也算）。
>
> **本项目其余两处 `fixed`（顶栏、底座 `::after`）判定为安全，理由是行为侧的**：
> 若祖先链上有**静态** `transform`，那两处的渐变会**长期**错位 —— 而它们的静止外观已经过目视确认，
> 故静止时祖先链上必无 `transform`；若动画期间**新增**了 `transform`，会看到与右边栏同款的
> 「骤增」，也没有发生过。两者合起来 ⇒ 目前无 `transform`。
> （`ConversationRoot.module.css:436-439` 也明写 `composerHero` 刻意不用 `transform`，
> 正是为了不改变 `position: fixed` 后代的包含块。）
>
> ⚠️ **但这是「当前事实」而非「结构保证」**：官方哪天给这两处任一祖先加个滑入动画，
> 它们会**静默**坏掉（和这次右边栏一模一样）。改动顶栏 / 底座那两处附近时先回来读这段。

### 7.1 **动态** bug 可以本地复现

「静止时没事、只在动画中出现」的 bug 截不到图，办法是：

**做法**：在 `_poc/TEMP/` 下生成**并排的静态对照页**，让每个变体只差**一条**被考察的 CSS，
其余几何完全相同（面板位置 / 宽度 / 层级 / 是否有背景层），再用 `playwright-cli` 逐页截图，
与**「该元素完全不存在」的参照页**逐像素比对。

**关键纪律（踩过坑）**：

1. **同一位置对比，不要横排后跨 x 比** —— 渐变的 `at 50%` 随 x 变，横排比对会把
   「位置差」混进「样式差」。
2. **必须有参照页**（元素 `display: none`），否则读不出「元素到底有没有画错」。
3. **`transform` 只要非 `none` 就会触发** `fixed` 改判 —— 所以对照里要显式放一个
   `transform: translateX(0px)` 变体，别以为它是空操作。
4. **祖先的 `transform` 同样触发，且不限深度** —— 实测到**第 6 层祖先**仍然改判。
   所以「元素自己没写 transform」**不构成安全理由**，必须往上看完整条祖先链。
5. **白线探针**读坐标系最直接：把待考察的锚点写成一条 1px 亮线
   （`linear-gradient(90deg, transparent calc(X - 1px), #fff …, transparent …)`），
   截图后读亮线落在哪个像素，就知道定位区到底是视口还是元素盒。
