## 3) 统一实现（一次到位）

### 3.1 数据模型：一份「面配方」

新增 `src/recipe.ts`（或在 `constants.ts` 内），把三档几何与强度收成**可查询的表**：

```ts
type Scale = 'viewport' | 'panel' | 'strip'
type Surface = { scale: Scale; light: number; grain: boolean }

const SHAPES: Record<Scale, { top: string; bottom: string; left: string; stop: string }>
const STRENGTH: Record<Scale, number>      // 1.0 视口 / 0.7 面板 / 0.7 矮条
```

**唯一出口**：`surfaceLayers(scale)` → 4 层字符串。删掉 `menuSurfaceLayers()`（它只有 2 层，
是「不统一」的直接来源）。

### 3.2 载体规则（MUST）

| 情形 | 载体 |
| :--- | :--- |
| 官方**未占用** `::after` | `::after`（默认，与 07 §3.1 一致） |
| 官方**已占用** `::after`（如 QueueDock 的 0.5px 描边） | 补官方自己的 `::before`（`OFFICIAL_BEFORE_LAYER_ANCHORS`） |
| 其余 | —— |

**一律删除元素级的 `background-image`**（那正是双层的一半）。

### 3.3 分组菜单与分组标题

* 分组菜单（`[role='menu']:has([role='group'])`）：**并入面板档**，4 层，
  与普通菜单同一几何 —— 不再有专用 2 层配方。
* 粘性分组标题（`groupTitleLayers`）：它是「把卡片那一摞原样重画」的派生层，
  **必须跟着卡片的最终配方同步**（卡片改成 4 层后，标题也要重画 4 层）。
  ⚠️ 这块历史上被修坏过 3 次（owner 四轮反馈），改动后必须真机复核「滚动时不出现横带」。

### 3.4 颗粒：收敛到单一管线

删掉 `grainTileUri(alpha)` 预乘那条路，浮层改用与地面**同一个** `::after` 配方：

```css
opacity: var(--dsh-theme-tone-grain-alpha)
mix-blend-mode: 与该轴地面一致（深色 screen / 浅色 multiply）
background-image: <不带 alpha 的同一张贴图>
```

⇒ 此后「一个变量」名副其实（G4）。

## 4) 恢复弹窗遮罩模糊（G6）

### 4.1 事实（先定性，避免误判）

**不是我们改坏的**：官方 `dsh-v0.1.7-rc.2` 提交 `fdd14a0989`（"unify UI materials"）
把 `--dsw-mask-blur` 从 `blur(2px)` 改成 `none`，注释同步改写为
"Blocking masks dim the page; menu backgrounds retain their blur"，
并有 e2e 断言 `expect(mask).toEqual({ …, blur: 'none' })` 钉住。
逐版取值：`0.1.5-rc.3` / `0.1.6-alpha.2` / `0.1.7-alpha.1` / `0.1.7-rc.1` 均为 `blur(2px)`，
**只 rc.2 变成 none**。完整证据链见 [`docs/upstream/0.1.7-rc.2-mask-blur.md`](../../../../docs/upstream/0.1.7-rc.2-mask-blur.md)。

⇒ 恢复它 = **刻意改官方默认**，属仓库现有「破例」记账范畴（先例：`HOVER_CARD_ANCHOR`）。

### 4.2 影响面（4 个消费点，**必须区别对待**）

| # | 消费点 | 用法 | 恢复后 |
| :--- | :--- | :--- | :--- |
| 1 | `ui-primitives/Modal` `.mask` | `backdrop-filter: var(--dsw-mask-blur)` | ✅ 模态遮罩背后变模糊 |
| 2 | `ui-settings-general/SettingsRoot` `.mask` | 同上 | ✅ 设置面板背后变模糊 |
| 3 | `ui-primitives/ImageLightbox` `.mask` | 同上 | ⚠️ 看大图时背景变模糊（见 Q6） |
| 4 | `ui-settings-account/DesktopOnboarding` `.blurred` | **`filter:`** 而非 backdrop | ❌ **必须排除** —— 它滤的是**自身内容**，恢复会把引导页整页糊掉 |

第 4 点是关键：**不能全局改 `--dsw-mask-blur`**（会连带把 `filter` 那处也变得模糊）。

### 4.3 做法（不碰官方变量本体）

> **Q6a / Q6b 已定**（owner 2026-09-27）：**大图查看一并恢复**；**两个档位都恢复**
> （不只插件档）。⇒ 下面的规则**不带 `PLAIN_ATTR` 门**，且一次覆盖全部 3 个消费点。

在**遮罩元素自身**上重设该变量 —— 官方规则 `backdrop-filter: var(--…)` 会自动取到新值，
而 `.blurred` 是**另一个元素**（`.page`），仍继承 body 的 `none`：

```css
/* 恢复 0.1.5 的「遮罩滤背后」观感；官方全局变量保持 none 不动，避免波及 filter 那处。
   不带 PLAIN_ATTR 门 ⇒ 官方默认档也生效（owner 决定，属刻意破例，须记账）。 */
[class*='_mask'] {
  --dsw-mask-blur: blur(2px);
}
```

优点：
* 不改官方全局变量 ⇒ **不波及** `filter` 那处；
* 不硬编码 `backdrop-filter` ⇒ 沿用官方自己的规则，官方若改回也自动跟随；
* 一处规则覆盖全部 3 个消费点（Modal / SettingsRoot / ImageLightbox）。

#### 4.3.1 已真机验证（两个档位各测一遍，按 Q6a/Q6b 的最终口径）

在真实页面上注入上面那条**不带门**的规则，逐项对比：

| 读取项 | 注入前 | 注入后（插件档） | 注入后（**官方默认档**） |
| :--- | :--- | :--- | :--- |
| 遮罩 `backdropFilter` | `none` | **`blur(2px)`** ✅ | **`blur(2px)`** ✅ |
| 遮罩自身 `--dsw-mask-blur` | `none` | `blur(2px)` | `blur(2px)` |
| **`body` 上的全局变量** | `none` | **`none`（未变）** ✅ | **`none`（未变）** ✅ |
| `[class*='_mask']` 命中数 | 1（`VOzbGW_mask`） | 1 | 1 |
| 本插件自有层 `--dsw-mask-blur` | `none` | **`none`（未被误伤）** ✅ | `none` ✅ |
| 全页 `backdrop-filter ≠ none` 元素数 | 0 | 1 | 1 |

⇒ 三点确认：
1. **只覆盖遮罩元素、不动全局变量**成立 ⇒ `filter` 消费点（引导页）不受影响；
2. **两个档位都恢复**成立（Q6b 的要求），且默认档不因缺门而漏掉；
3. **本插件自有元素不被误伤** —— 实测 `.dsh-theme-tone` 的该变量仍为 `none`
   （源码侧也已核对：插件所有 `src` 里 `_mask` 零命中）。

⚠️ **脆弱依赖（须记账）**：`[class*='_mask']` 是**哈希类名的稳定后缀匹配**。
`docs/private-seams.md` 现已登记**两处**同类例外（悬停卡字色 `_hoverTitle` 等、扫光带
`[class*='_row']::after`），本条将是**第 3 处** —— 须同处登记，并把该文件那句
「例外是**两处**」同步改为三处（否则文档与实际不符，正是本仓库反复出问题的那类事故）。

守卫三条（M8 的验收）：①遮罩取到 `blur(2px)`；②`body` 上的变量仍为 `none`；
③引导页 `.blurred` 的 `filter` 不受影响。

### 4.4 与「官方默认档」的关系（Q6b）

默认档（`PLAIN_ATTR`）**是否也恢复**？两个选择：

* **只插件档**（带门）：官方默认保持 rc.2 原样，符合「官方默认不动」硬规矩；
* **两档都恢复**：贴近 owner「我想要 0.1.5 那个观感」的本意，
  但破例范围扩大（与 `HOVER_CARD_ANCHOR` 同类记账）。

⇒ 交 owner 定（§7 Q6b）。

## 5) 顶栏 / 输入卡 / 右栏（例外，不并入）

它们是**玻璃**（有 `backdrop-filter`），光的强度必须与各自的填充 alpha 解耦，
不能简单套 §3 的表。**保持现状**，仅做两件收口：

1. 去掉 `background-attachment: fixed`（07 §4.3 禁止项）—— 改用盒子内几何 + 显式
   `100vw/100vh` 盒对齐（右栏已有此写法，复用）；
2. 复核它们的几何常量与 §3.1 的视口档**同源**，不再各写一份。

### 9.1 M6 的两个结论（都推翻了我自己先前的记录）

1. **颗粒系数 0.7 的两个前提都变了**：层数 2→1、且旧表**不在同一屏幕位置**取样。
   同位置重测 ⇒ **1.23**（7 点扫描独立复核 1.264）。**且「浮层必须更弱」是错的** ——
   screen 混合在深色轴把噪声提亮，浮层（普通合成）反而需要更强才同档。
2. **光强 0.7 恰好落位**：光与颗粒不同，它是**同一条管线**（共用同一个变量、只多乘系数），
   而解析定标解的就是「同位置 alpha 相等」⇒ 正确前提是**单层**，M2 恰好把它变成单层。

> ⚠️ **期间修掉一个取样污染**（值得记，因为同类错误本仓库犯过多次）：
> 只隐藏对话框时，同位置元素是 `VOzbGW_mask`（遮罩），2024/2024 点**全落在它上面** ——
> 量到的是遮罩而不是地面。必须**同时隐藏对话框与遮罩**才能露出地面。
