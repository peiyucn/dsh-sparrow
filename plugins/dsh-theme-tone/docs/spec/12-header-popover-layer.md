# 12 · 顶栏后台任务弹框：为什么纯 CSS 修不了（含一次完整回退）

> 触发：owner 真机报障「后台任务弹框被右边栏挡住」（2026-10-08）。
> 本文记**一次从修到回退的完整过程**与**两条受控实验**，结论是「纯 CSS 无解」——
> 目的是让下一个人**不必再走一遍**。相关：`docs/private-seams.md` §C 第一条。

## 1. 现象与两个成因

官方 `JobListAction` 的弹框（`ul.menu`，`position: absolute; left: 0; width: 500px`）长在**顶栏子树里**，
**不是** portal 出去的浮层。右栏打开时它同时挨两刀：

| # | 缺陷 | 机制 |
| :--- | :--- | :--- |
| ① | **被裁** | `.root[data-phase='active'] { overflow: hidden }`（`ConversationRoot.module.css:363-365`）是顶栏的**祖先**；弹框向右伸出列，伸出部分整块被裁，**裁切右边界逐像素等于右栏面板左缘** |
| ② | **被盖** | 弹框是**顶栏后代** ⇒ 层叠上限就是顶栏那一档（本插件抬到 82）；右栏面板同为 82 且 DOM 更后 ⇒ 面板恒赢 |

## 2. 受控实验 A：层序（真实 Edge，`elementFromPoint`）

复刻真实层级（backdrop 80 / 滚动体 81 / 顶栏 82 与面板 82 为**兄弟**）：

| 变体 | 重叠区命中的元素 |
| :--- | :--- |
| 现状（顶栏 82 / **弹框自己** z-index 999 / 面板 82） | panel |
| **顶栏** 83 / 面板 82 | **menu** |
| 顶栏 83 / 面板 90（官方更高档） | panel |

⇒ 抬**弹框自己**的 z-index **无效**（出不了顶栏那层层叠上下文）；抬**顶栏**确实能盖过面板。
⚠️ 建模必须按真实结构：`CONTENT_Z_INDEX` 打在**滚动体**上、顶栏是它的**兄弟**
（第一版实验把顶栏错放进 81 那层，得出「抬顶栏也没用」—— 是错的，教训记此）。

## 3. 受控实验 B：位置（换包含块之后 `left` 取什么值）

| `left` 取值 | 弹框 − 触发器 |
| :--- | ---: |
| `0`（官方样式表与内联的常见值） | **−300px**（贴到列左缘） |
| **`auto`** | **0**（完美贴回触发器） |
| 官方 `fit()` 的负数收边值 | −420（坐标系错位） |

⇒ `left/right` 都是 `auto` 时绝对定位元素回到**静态位置**；换包含块后它恰好等于
「触发器容器在新包含块里的左缘」= 官方那套锚定想表达的位置。

## 4. 曾经的做法（已回退）与它为什么既难看又没用

2026-10-02 的 `0f39393` 用「把装了弹框的 wrapper 改成 `position: static`（换包含块）+
`left: 0 !important`」来修 ①，并声称修好了。**2026-10-08 真机复看：弹框变成贴列左缘、
横跨整个对话区的一条**，比原缺陷更难看。

回退后查明两件事：

1. **换包含块根本没解决裁切**。`ConversationRoot.module.css:71` 给 `.titleRow` 挂了
   `container-type: inline-size`，它**隐含 `contain: layout`** ⇒ 该元素成为 abspos / **fixed**
   后代的**包含块**。而弹出层就在 `.titleRow` 的子树里 —— 于是换谁当包含块都还在 `.titleRow` 内，
   `.root` 的 `overflow: hidden` 又是它的祖先 ⇒ **恒被裁**。`position: fixed` 同样救不了
   （包含块仍被 containment 钉住）。
2. **抬顶栏能过层序那一关、却过不了裁切那一关**，而且与官方次序冲突：
   官方全屏面板（`--dsh-dockkit-dock-layer: 40`）本就高于顶栏（9），dockkit 浮窗又是 60 ——
   抬顶栏会让它在全屏时浮到面板之上（`d133f2c` 实测过：整块像素 mean 2.47 / 17.3% 变化）。

## 5. 结论与**最终采用的改法**

**「逃出列的裁切」确实无解**（`containment` 把包含块钉在 `.titleRow` 内，`fixed` 也一样）；
但**不需要逃** —— 只要让弹框**别伸到裁切边界外面**就行。

### 采用的改法（owner 提议）：**只把对齐方向改成右对齐**

官方的 `left: 0` 是「**左缘**贴触发器」⇒ 弹框**向右**伸 500px，伸出列的部分被裁。
改成「**右缘**贴触发器」（`right: 0` + `left: auto !important`）⇒ 弹框**向左**伸，整块落在列内。

```css
body[data-tone-anchor~="right-panel-open"] [data-slot='conversation.session.header.actions'] ul {
  left: auto !important;   /* 压掉官方样式表与内联两处的 left */
  right: 0;                /* 右缘贴触发器右缘 */
}
```

* 包含块不变（官方 `.root { position: relative }`）、`width` 与 `max-width` 仍是官方的、`z-index` 不动、
  `overflow` 不动 —— **一条规则两条声明**，是本问题能有的最小改动。
* 门只挂「右栏面板已打开」：面板关着时列本来够宽、官方左对齐不出问题，**不动它**。
* **残余**（如实记）：列比「触发器右缘到列左缘的距离 + 500px」还窄时，会改成从**左边**溢出被裁 ——
  面板打开时列宽通常 ≥540px，实测未触发；真要兜住得知道列宽（官方只发布了内容宽，不是列宽），暂不做。

### 已排除的做法（都试过，各有受控实验，别再走一遍）

| 已排除 | 为什么不行 |
| :--- | :--- |
| 换包含块（wrapper → `static`） | containment 把包含块钉在 `.titleRow`，仍逃不出 `.root` 的裁切 |
| `position: fixed` | 同上（containment 也是 fixed 的包含块） |
| 抬弹框自己的 `z-index` | 出不了顶栏的层叠上下文（实验 A） |
| 抬顶栏 | 能过层序，但改不了裁切，且违反官方全屏面板次序 |
| 动中列 `overflow` | 那是列自身的裁切契约 |

⚠️ 另一条**对位置的**坑记在这里：官方把锚定值写成**相对触发器**的内联 `left`，一旦换了包含块就落在
错误的坐标系里（实验 B 实测偏 −300px）。**不换包含块就不会踩它。**
