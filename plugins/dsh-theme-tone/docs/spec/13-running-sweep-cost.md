# 13 · 运行期合成开销：把「每帧按视口栅格化」的 `fixed` 清掉

> **状态**：已实现。**范围**：`sweep.ts`（4 条扫光带）+ `glass.ts`（吸顶遮罩行、轨迹视图）。
> **起因**：owner 2026-10-21「多个会话同时工作的时候，会话的转圈动画都会卡，会话切换也非常卡，
> 整个对话页面滚动也比官方性能差很多」。

## 1) 先修量具：这台机器上什么测不出来

前几轮归因反复给出**互相矛盾**的结论（同一臂在 40 / 80 / 201 / 5304 之间跳），
根因全在量具，不在代码：

| 坑 | 现象 | 结论 |
| :--- | :--- | :--- |
| 后台标签页 rAF 节流 | 帧间隔恒为 ~1000ms（≈1fps） | 任何「帧率 / 帧间隔」读数都是假的；必须 `Emulation.setFocusEmulationEnabled` + `Page.bringToFront` |
| 两次独立 trace 对比 | 基线在 40~5304 间漂 | `Tracing.start/stop` 本身重置渲染器状态 ⇒ **只能在同一次 trace 内交替** |
| trace `ts` 与页面时钟不同基准 | 按时间戳切段得到全 `0` | `ts` 是**相对进程启动**的单调时钟（可达数天），需减去一个常量偏移 |
| `--remote-debugging-port=0` | 启动器进程立刻退出、拿不到端口 | 用**固定端口** + 轮询 `/json/version`（启动器退出是 Chromium 正常行为） |
| 每轮新建 profile | Edge 进程堆积 60+ 个 | 复用**固定 profile 目录** |
| 拿 `querySelectorAll` 数伪元素 | 带 `::before` 的选择器恒为 0 | 伪元素查不到，必须换成「剥掉伪元素后的宿主」再查 |

**最终可用的判据（本专项沿用的）**：

* **`Page.captureScreenshot` 逐像素比对** —— 确定性、可重复、与调度无关。用来证明「无观感回退」。
* **`long-animation-frame`（LoAF）** —— 浏览器官方的主线程阻塞度量，页内采集、无往返。
* **DOM 侧结构计数**（规则命中数、层相关属性命中数）—— 确定性，用来证明「改到了什么」。

> ⚠️ 不再用「帧间隔 / 帧率」报告收益：本机噪声底比真实效应大（spec 10 §6 已记过一次）。

## 2) 归因结论：真正的热源是 `background-attachment: fixed`

产出物里 `background-attachment: fixed` 共 **13 条**。逐条查宿主命中：

| 规则 | 宿主命中 | 说明 |
| :--- | :--- | :--- |
| 顶栏 `> header::before` | 1 | 始终存在 |
| 座底不透带 `[data-composer-seat]::after` | 1 | 始终存在（已有相位档） |
| 卡片缺口 | 1 | 始终存在（已有相位档） |
| **扫光带 ×4**（`[data-state='running']…::after`） | **多会话并行时每个 running 行各 1** | **本专项的主热源** |
| 吸顶遮罩行 `[data-disclosure-row]` | 展开 Think 行时命中 | 流式内容里 |
| 轨迹视图 ×8 选择器 | 打开轨迹视图时命中 | 大面积不透明面 |

机制（spec 10 已实测）：`fixed` 让**定位区 = 视口** ⇒ 每帧按视口重新解析/栅格化，
**成本与声明尺寸无关**（把盒子缩到 1/225 也不省）。

⇒ 「多个会话同时工作就卡」的直接解释：**每个 running 行**都挂着一层按视口栅格化的背景，
行数越多、每帧的视口栅格化次数越多。

## 3) 改法：显式几何 + `scroll`（逐像素等价）

`fixed` 的语义是「图片盒与视口重合」。用 `scroll` 复现该相位有两种写法：

| 载体 | 写法 | 需要运行期测量？ |
| :--- | :--- | :--- |
| 座底带 / 卡片缺口 | 运行期实测相位变量（`PHASE_*_VARIABLE`） | **要**（定位区随左右栏变） |
| **扫光带 / 吸顶行 / 轨迹视图** | `100vw 100vh` + `background-position: 0 0` + `no-repeat` | **不要**（这几个载体的背景本来就按视口尺寸铺） |

本专项三处都用第二种：

```css
background-attachment: scroll;
background-size: auto, 100vw 100vh, 100vw 100vh, 100vw 100vh;   /* 逐层！第 1 层颗粒是 auto */
background-repeat: repeat, no-repeat, no-repeat, no-repeat;
background-position: 0px 0px, 0px 0px, 0px 0px, 0px 0px;
```

⚠️ **`background-size` 必须逐层给**：值少于层数会按序循环补齐，把颗粒拉成粗块、
让三层渐变退回「按元素自身盒子解析」（行只有 20–30px 时压成硬边带）。

## 4) 验收：逐像素等价（真机）

同一场景、同一次会话，只切换目标规则的 `fixed`/`scroll`，全屏截图逐像素比对
（判据：通道差 > 2 记为改变）：

| 改动 | 改变像素 / 全屏 160 万 | 比例 | 最大通道差 |
| :--- | ---: | ---: | ---: |
| 扫光带 ×4（12 个 running 行） | **91** | **0.006%** | 119 |
| 吸顶行 + 轨迹视图 ×2 | **85** | **0.005%** | 113 |
| （反例）**不加相位**直接换 `scroll` | 51 649 | 3.23% | 91 |

⇒ 前两项肉眼不可见；反例证明**不能裸换**（必须给显式几何）。

> 为什么扫光带能容忍竖直相位偏移：它的可见范围由横向 mask
> （`transparent 0% → 60% 55% → transparent 100%`）决定，行高只有 20–30px，
> 竖直方向上光层在其掩膜内的变化看不出来。

## 5) 为什么不一次全改完

剩下的 6 条 `fixed` 属于**另一类**，不能套本节的写法：

| 位置 | 为什么保留 |
| :--- | :--- |
| 顶栏 `::before` | 它自己就是 `absolute` 浮层，且需要「76px 盒子不被重采样成硬边带」 |
| 座底带 / 卡片缺口 | 已有**运行期相位**档（spec 10），已是 `scroll`；规则里的 `fixed` 是**慢档兜底**（相位测不到时用） |
| 菜单分组行 | 盒子极扁，且只在菜单打开时存在 |

## 6) 本机量具的限制（必读，否则会得出错误结论）

这台开发机的**渲染帧率被限制在约 2Hz**（`requestAnimationFrame` 间隔恒定 ~535ms，
`visibilityState: 'visible'`、`hasFocus: true`、GPU 为 Intel Arc + D3D11 硬件加速均正常）。
⇒ **任何「帧间隔 / 帧率 / 掉帧数」类指标在本机都不可用**，两臂测出来会「完全持平」，
那不是「没有差异」，是量具没有分辨率。

本专项因此只用两类判据：

| 判据 | 为什么可信 |
| :--- | :--- |
| **逐像素截图比对** | 确定性、与调度无关；用来证明「无观感回退」 |
| **产物静态结构计数**（去注释后数 `fixed` / `scroll` / 规则数 / 命中宿主数） | 确定性、可重复；用来证明「改到了什么」 |

**不要**在本机报告「省了多少 ms / 帧率从 X 回到 Y」—— 已在 spec 10 §6 记过一次同类教训。

## 7) 最终状态

去注释后的产物统计（`glass` + `sweep` + `backdrop`）：

| 项 | 改动前 | 改动后 |
| :--- | ---: | ---: |
| `background-attachment: fixed` | **13** | **2** |
| `background-attachment: scroll` | 6 | 10 |

剩下的 2 条是**有意保留**：

1. **顶栏 `> header::before`**：它带 `backdrop-filter`，且必须让「76px 盒子不被重采样成硬边带」——
   实测换成显式几何会有 **7.4% 像素差**（header 起于 x=280，而 `fixed` 让图片盒锚定视口），
   故必须配运行期相位，暂不动。
2. **座底不透带 `[data-composer-seat]::after`**：这是 `fixed` 的**慢档兜底**
   —— 运行期相位门（`data-dsh-theme-tone-phase-band`）测到值时由 spec 10 那条 `scroll` 规则覆盖，
   测不到才落回这一条（慢但一定正确）。
3. **缝挡板 ×4**（`[data-testid='todo-panel'] ~ [data-goal-bar]::before`、
   `:is(...) ~ [data-queue-dock]::before`、`[data-tone-anchor~='seat-docked'] … composer-host::before`、
   `[data-tone-anchor~='composer-host']::after`）：
   **实测不能裸换** —— 显式几何会带来 **1.1% 像素差 / 最大通道差 232**（比扫光带高两个数量级）。
   原因是这几个载体的**位置各不相同**（叠在输入框卡上方不同高度），
   `fixed` 让它们共享同一份视口相位；换成 `background-position: 0 0` 后相位随各自盒子漂移。
   ⇒ 要改必须像座底带那样**逐载体实测运行期相位**，属于另一件工作，本轮不做。

> 实测三条「不能裸换」的证据（都记在上面）：顶栏 7.4%、缝挡板 1.1%、
> 而扫光带/吸顶行/轨迹视图 0.005~0.006%。判别标准很清晰：
> **载体自身位置固定且盒高很小 ⇒ 显式几何等价；载体位置会动或盒高较大 ⇒ 必须运行期相位。**
