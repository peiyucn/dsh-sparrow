# 11 · `:has()` 与流式期间的样式重算（「think 时滚动卡」的真正主因）

> 结论先行：owner 报的「模型 think 的时候滚动依然很卡」，主因**不是**绘制，
> 而是插件主表里 **19 条 `:has()` 规则**引发的**样式重算**。
> 流式时 DOM 每帧在变 ⇒ 每帧都要把这 19 条重匹配一遍 ⇒ 实测 **+3.1 秒 / 100 帧**。
> 把它们的**选择器形状**换成等价的属性选择器，可拿回 **100%** 的收益（PoC 已验证）。

## 1) 为什么上一轮（spec 10）没解决

spec 10 修的是 `background-attachment: fixed` 的按视口栅格化 —— 那是**绘制**成本，
在**静止页面**上滚动时确实能测到。但：

* 静止滚动下，插件与官方默认的差只有 **~1.8ms/帧**（受控实测，80% 符号一致）；
* 流式时 DOM 每帧在变，主因换成了**样式重算**，与绘制无关。

spec 10 测得「相位档省 56% 绘制次数」是真的，但那笔钱在**总量里只占小头**：

| 场景 | 插件 Paint | 官方 Paint | 插件 UpdateLayoutTree | 官方 UpdateLayoutTree |
| :--- | ---: | ---: | ---: | ---: |
| 静止滚动 | — | — | — | — |
| **流式 + 滚动** | 632 ms | 116 ms | **5291 ms** | ~1460 ms |

⇒ 流式场景下，「样式重算」比「绘制」贵一个数量级。

## 2) 量具：为什么前面几轮结论反复

本轮**先建量具纪律、再下结论**，前后作废过三次结论：

| 曾经的结论 | 为什么不成立 |
| :--- | :--- |
| 「移除 `mix-blend-mode` ⇒ 长帧 80 → 23」 | 换一次运行基线自己从 80 变 5；**逐轮散布 ±5ms 大于臂间差异** |
| 「提升背景层为合成层 ⇒ p50 16.0 → 12.9」 | 同上；受控复测后 Δp50 = **−0.10ms**、符号一致性 53%（掷硬币） |
| 「`background-image` 是大头」 | 单属性归因在**静止**场景做的；流式下排序完全不同 |

**现在的做法**（`TEMP/perf-ab2.mjs` / `perf-plugin-vs-official.mjs`）：

1. **交错采样**：每轮把所有臂各测一次，轮间反向顺序 ⇒ 漂移平摊；
2. **成对差值**：只统计「同一轮内 A−B」，消掉轮次漂移；
3. **符号一致性**：报「差值为负的轮数 / 总轮数」，60% 以下一律视为噪声；
4. **噪声底臂**：同一配置测两次，它的差值就是**该量具的分辨率**；
5. **断言每臂真生效**：报告 computed 值，不一致直接报错。
   （曾有一版臂注入静默失败，四个臂的 computed 全都一样 —— 等于在同一状态上测了 60 次。）

> ⚠️ 另有一条**场景纪律**：判据必须取自**用户抱怨的那个场景**。
> 静止滚动测不出的东西，在流式下差 6 倍。

## 3) 归因链（全部受控、带符号一致性）

场景：流式模拟（每帧改一次 DOM）+ 滚动，100~120 帧/次，交错多轮。

### 3.1 是「效果」还是「规则在场」？

| 臂 | Paint | UpdateLayoutTree |
| :--- | ---: | ---: |
| 插件现状 | 632.1 | **5290.7** |
| 效果关掉、**规则仍在**（`PLAIN_ATTR`） | 115.9 | **4892.1** |
| **插件各表 `disabled`** | 109.1 | **1462.0** |

* 「效果关掉但规则在」⇒ Paint 掉 516ms（9/9 一致），**样式重算几乎不动**；
* 「规则整个摘掉」⇒ 再掉 ~3800ms。

⇒ **Paint 那 516ms 是「效果被画出来」的成本；另有 ~3830ms 是「规则在场」的成本**，
两者互相独立。

### 3.2 是哪张表？

| 臂 | UpdateLayoutTree | Δ | 一致性 |
| :--- | ---: | ---: | ---: |
| 基线 | 5256.3 | — | — |
| 噪声底 | 5415.7 | +115（噪声） | 2/7 |
| **摘掉全部 `:has()`（19 条）** | **1756.7** | **−3547.7** | **7/7** |
| 整表 disabled | 1579.9 | −3746.0 | 7/7 |
| 禁用 `style[21]`（ccb 表，30 条） | 5295.8 | −28.7 | 4/7（噪声） |
| **禁用 `style[25]`（主题主表，109 条）** | **1574.1** | **−3670.3** | **7/7** |
| 禁用 `style[50]`（21 条） | 5402.9 | +37.2 | 3/7（噪声） |
| 禁用 `style[51]`（32 条） | 5289.5 | +10.0 | 3/7（噪声） |

⇒ 成本**全部**在主题主表；且**几乎全部**在那 19 条 `:has()` 上（占主表收益的 95%）。
另外三张插件表贡献 ≈ 0。

### 3.3 是 `:has()` 本身，还是「复杂选择器」？

**关键 PoC**（`perf-has-poc.mjs`）—— 把 19 条 `:has()` 的**选择器**换成
「命中同一批元素的属性选择器」：先用原选择器查出真正命中的元素，
给它们打 `data-has-sim="K"`，再把选择器换成 `[data-has-sim="K"]`（保留伪元素后缀）。
于是**规则条数、命中元素集合、画出来的效果全都不变**，只有选择器形状变了。

| 臂 | UpdateLayoutTree | 帧均值 |
| :--- | ---: | ---: |
| 基线（19 条 `:has()`） | 4622.8 | 65.20 |
| 噪声底 | 4563.1 | 64.82 |
| 删掉全部 19 条 | 1559.4 | 32.95 |
| **换成属性选择器（19 条）** | **1513.8** | **32.38** |

**换选择器拿回了 3109ms / 3063ms ≈ 100% 的收益**（与「全删」只差 45.6ms，在噪声内），
而效果一个字没少。

⇒ 成本来自 **`:has()` 这个伪类的匹配求值**，与「命中后画什么」无关。

## 4) 修法方向（待实现）

**把 19 条 `:has()` 换成属性选择器**，属性由 client half 在运行期维护 ——
与 spec 10 已建立的机制**同型**（`publishPhase` 那套：rAF 合并 + 收敛重测 + `ctx.effect` 清理）。

草案：

1. client half 用 `MutationObserver` + rAF 维护若干锚点属性，例如
   `data-tone-anchor='seat' | 'composer-host' | 'scroll-wrap' | 'turn-nav' |
   'overlay-tree' | 'overlay-listbox' | 'dialog' | 'grouped-menu' | 'panel-actions'`；
2. 主表里对应的 19 条选择器改成 `[data-tone-anchor='…']`（保留原有门与伪元素）；
3. 维护逻辑**必须便宜**：只在「锚点集合的指纹」变化时才写属性，避免自己成为热路径
   （实测：`getComputedStyle` 每帧调用次数在插件态与官方态同为 2.5/帧，不是问题）。

⚠️ **尚未实现**。本节只是把方向与判据固定下来；落地前须按 `08` 的 spec-before-code 走一遍评审。

## 5) 复现方式

```powershell
# 需要 GUI 令牌与有头浏览器（headless 不做真实合成，量不到这些）

node TEMP/perf-recalc-attribution.mjs   # 逐表归因
node TEMP/perf-has-poc.mjs              # `:has()` → 属性选择器的等价性 PoC（决定性）
node TEMP/perf-streaming.mjs            # 流式场景本身的对照
```

> 本轮的结论在 headless 下量不到（这也解释了更早几轮为何都在绘制指标上打转）。
