# 01 · 自适应 API 拦截（11128 有界降级）

> 2026-10-29 立项。owner 已确认形态：失败触发的有界阶梯，不做二分探测，不主动打探测流量。
> 现状背景见 `00-overview.md`《上游渠道校验（11128）》与 2026-10-29 定位记录。

## 1. 要解决的问题

上游渠道校验（HTTP 400 / code 11128）的失效面有两个维度：

| 维度 | 变化时机 | 现有静态表能否覆盖 |
| :--- | :--- | :--- |
| 归一化扩容（当前中和符被上游洗掉） | 随时，服务端行为 | ❌ 现方案整层失效，只能等发版 |
| 指纹内容新增（DSH 提示词改版出现新命中句） | 随 DSH 版本，版本由我们 pin | 部分（前缀规则覆盖整类句子） |

本 spec 只给第一个维度做**自适应 API 拦截**；第二个维度继续走「升级 DSH 时离线比对提示词 + 发版」的既有流程。

## 2. 非目标

- **不做二分探测**：不拿真实账号发送连续的探测请求去定位命中段。定位成本（每次 5–10 个 400 请求，
  全部进企业用量日志）高于收益；内容维度的变化可以离线发现。
- 不做语义/LLM 级改写。若上游改为语义检测，本层与静态层一起失效，报明确错误。
- 不引入持久化：适配结果只存进程内存（重启重付一次阶梯成本，可接受）。

## 3. 阶梯（rung）

按顺序尝试，命中 11128 才进下一级；**非 11128 的错误不重试**（结构层错误重试无意义）。

| # | rung id | 变换 | 2026-10-29 实测（完整被拦请求） |
| :--- | :--- | :--- | :--- |
| 1 | `cgj` | 插 U+034F（CGJ，Mn） | 200 ✅ 当前默认 |
| 2 | `marker-180B` | 插 U+180B（蒙古文自由变体选择器，Mn） | 200 ✅（两轮） |
| 3 | `marker-180D` | 插 U+180D（同上，Mn） | 200 ✅（两轮） |
| 4 | `strip` | 删已知指纹段 + 品牌词替换 | 200 ✅（不依赖插入符） |

候选选择结论：上游当前清洗的是 **Cf 类格式字符**（U+200B/200C/200D/2060/FEFF/00AD/180E/2061–2064）
并压缩双空格；**Mn 类组合记号**未清洗，故候选全部选 Mn、且必须无可见字形：

- 落选并禁止再用：U+2061 / U+2062（Cf，实测 11128）、U+FE00 / U+FE0F（Mn 但被清洗，11128）、
  U+E0100（Mn，首测 200、复测三次 11128 → 网关节点差异，判定不可靠）；
- 落选的 U+1D165（音乐符号组合符，实测 200）有可见风险（支持音乐字形的字体会画出符干），不入池。

`NEUTRALIZER_MARKERS` 单一来源在 `src/fingerprints.ts`。候选池被全部洗掉后，
`strip` 仍能救「已知内容 + 归一化全灭」；`strip` 也失败即判定需发版。

## 4. 触发与状态机

- 位置：`src/adapter.ts` 的 `request()`。11128 在 SSE 开流前返回，重试是干净的（无半个流）。
- 判定：`status === 400 && body.code === 11128`（读 `response.clone()`，不消耗原响应体）。
- 状态：适配器实例私有 `rungIndex`（进程内）。失败即前进一格；成功即记住该格，后续请求直接从它开始。
- 阶梯长度上限 4 → 单次请求最坏多发 3 次 400（初始 + 3 次重试），行为有界。
- 并发：DSH 会话内请求基本串行；并发流各走各的阶梯，最坏重复一格，可接受（不做锁）。
- 设置开关 `autoAdapt`（默认开）：关闭时只走 rung 1、不前进、原样报错，即回到 2026-10-29 之前的行为。
- 用尽后错误文案：保留服务端 detail，追加「已尝试自动降级，仍被拒，需升级插件」，让用户一眼可读。

| 面 | 改动 |

## 6. 测试矩阵

| 用例 | 断言 |
| :--- | :--- |
| 阶梯变换单测 | 池内每个 marker 都能中和三类指纹且可见文本不变；`strip` 删除身份句 / `@` 段 / 品牌词，代码块保留；`strip` 不依赖插入符（对 ZWSP 归一化后的原文同样生效） |
| 适配器重试 | 第一次 400/11128、第二次 200 → 两次请求，两次 body 的 system 插入符不同，且流正常输出 |
| 记住成功 rung | 适配成功后第二个流只发 1 次请求，body 直接用成功 rung 的插入符 |
| 非 11128 不重试 | 400/10081 → 只 1 次请求，错误原样透传 |
| 阶梯用尽 | 全部 11128 → 4 次请求后抛错，文案含「自动降级」提示 |
| 开关关闭 | 只发 1 次请求，失败原样透传 |
| `strip` 降级 | 第 2、3 格仍 11128、第 4 格 200 → 请求体 system 不含身份句与 `@` 段 |
| 路由 | `/status.autoAdapt`、`POST /auto-adapt` 参数校验与写入 |

## 7. 已知限制

- 只覆盖「已知内容类别」：内容维度出现**全新类别**的命中句（不含品牌词、不匹配既有句子）时，阶梯
  全部无效 → 报错等发版。这是有意取舍（不做二分探测）。
- 候选字符已实测但仍可能被收掉：2026-10-29 实测 U+180B / U+180D 放行；上游下一轮若把 Mn 组合记号
  一并清洗，第 2、3 格会各多付一次 400，然后由 `strip` 兜底。
- `strip` 有行为漂移：删掉身份句与 `@` 路径说明段，模型对环境与 `@` 语法的认知变弱；只在最后兜底启用。
- 适配状态不持久化：进程重启后重新从 rung 1 试起（最多多付 3 次 400）。
- 每次适配都会在上游用量日志留下被拒请求；阶梯上限 4 是刻意的噪声上限。
