# 05 — 转动环层级：必须落在遮罩之下

> 状态：已实现（2026-09-08）。owner 实测反馈：其它弹窗打开时，联想转动环没有随背景一起虚化。

## 现象

归档面板 / 官方弹窗打开时，背景整体被虚化（遮罩 `backdrop-filter`），但输入框上沿那圈
联想转动环仍然清晰、浮在弹窗之上。

## 根因

环是 `position: fixed` + `z-index: 2000`，由 `createPortal` 挂到 `document.body`
（根层叠上下文），而官方与插件自己的遮罩层都在它**下面**：

| 层 | z-index | 来源 |
| :--- | ---: | :--- |
| 菜单 / 悬浮卡 / Tooltip | 100–101 | 官方 `Menu`/`HoverCard`/`Tooltip` |
| **转动环** | **2000** | 本插件（改前） |
| 弹窗遮罩（官方 Modal / Settings） | 1000 | 官方 `Modal.module.css:5` |
| 归档面板遮罩 | 1000 | 本插件 |
| 归档确认框遮罩 | 1100 | 本插件 |

`backdrop-filter` 只模糊**它下面**绘制的内容。环在 2000，比所有遮罩都高，因此
既不被模糊、也不被遮罩压暗，直接盖在弹窗上。

## 设计

把环降到 **900**——位于菜单层（101）之上、一切遮罩（1000/1100）之下：

```
0–20  页面内容
100   官方菜单 / 悬浮卡 / Tooltip
900   转动环（本插件）
1000  官方弹窗遮罩 / 归档面板遮罩
1100  归档确认框 / 官方 Toast / Onboarding
```

取值依据：官方客户端 CSS 的 z-index 取值实测只有
`0–10 / 20 / 100 / 101 / 1000 / 1100`，900 与任何一层都不冲突。

效果：弹窗一出，环随背景一起被 `--dsw-mask-blur`（blur(2px)）模糊并压暗；
弹窗关闭后恢复正常。环是 `pointer-events: none` 的装饰层，不参与交互，降到遮罩下无副作用。

## 为什么不隐藏环

也可以用 MutationObserver 检测弹窗（`[aria-modal="true"]`）出现即隐藏环，但：
遮罩本身已经负责虚化背景，让环「一起被虚化」才是与官方视觉一致的做法；
隐藏会让关闭弹窗时环突然闪现，反而多一个闪烁源。

## 涉及文件

- `src/client/ChatFimDock.tsx`：`.dsh-chat-fim-ring` 的 `z-index` 2000 → 900（附层叠契约注释）。

## 验证

- `npm run verify` 全绿（181 tests）；客户端产物重新打包。
- 行为：弹窗打开时环与背景一同虚化；无弹窗时观感不变。

## 风险

- 层级依赖官方遮罩的 z-index 约定（1000）。官方若改动该值，环需同步——
  已在 CSS 注释与本文件记录判据，便于跟随官方升级时复查。
- 灵敏度弹层（`z-index: 2100`）**未**改动：它是可交互的临时菜单，
  点开弹窗即因「外部点击」关闭，不构成同类问题；保持在上层以免弹窗期间被遮罩吃掉点击。
