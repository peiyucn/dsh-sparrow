# 00 · 插件概览 — dsh-vision-access

> dsh-sparrow 合集成员。详细设计见 01-design.md（seam 选择以 dsh 源码查证为准），路线图见 02-roadmap.md。

## 定位

让**纯文本主模型**（如 `deepseek-v4-pro` / 普通 Flash）会话能直接贴图：图片交给官方视觉模型（`deepseek-v4-flash-vision-exp`）**直连读取**（经 `ctx.llm`，不起子代理），主模型保持对话大脑。

## 痛点与动机

* dsh 0.1.1 起原生支持官方视觉模型直接收图，但准入门禁按会话模型的 `inputModalities` 判定：Pro 会话贴图会被拒绝（`MODEL_DOES_NOT_SUPPORT_IMAGES`），用户必须手动把会话模型切成 vision 模型再切回来；
* 已核实的社区现状（2026-08，均来自 GitHub 实测）：
  * 整轮切换（dsh-periscope）：路由判定扫描**全部历史消息**，贴一张图后后续纯文本轮次也会被路由到 vision——「Pro 大脑」被悄悄接管，与目标相反；
  * 第三方 VLM 转译（dsh-vision-proxy 等）：图片发给第三方端点转成文字再喂主模型——隐私、信息有损、额外 key；
  * 占位 + 子代理委托（dsh-image-subagent）：思路与本插件一致，但实现有短板（见 01 竞品短板清单）。

## 方案一句话

**「占位投影 + 直连视觉模型」架构，并把 dsh-image-subagent 的每一条短板做成硬约束修复**：委托是机制不是 prompt 软约束、附件走官方 seam 不硬编码布局、结构化报告 + 哈希缓存 + 面板可见、完整降级链、测试与版本适配矩阵。

## 需求范围（做 / 不做）

**做**：

* 贴图放行（门禁适配）与「attachmentId 占位投影」，主模型上下文里始终有图片的内容描述；
* 视觉读取走官方 `deepseek-v4-flash-vision-exp`（同一 provider/key，图片不出 DeepSeek 体系）；
* 触发机制程序化（主模型通过注入的 `vision_read` 工具触发，不靠自觉）；
* 结构化报告（OCR 逐字 / 表格 / 版式分区）、按图片哈希缓存、面板可见；
* 主模型非 DeepSeek 系列时按 agent 屏蔽 `vision_read`（工具/UI 都像没有）；vision 不可用时的明确降级。

**不做**：

* 不整轮切换会话模型（主模型永远保持大脑）；
* 不默认把图片发给第三方 VLM（第三方只作为用户显式配置的可选降级，并明示隐私）；
* 不硬编码 `~/.dsh/attachments/...` 内部布局；不 monkey-patch 核心。

## 验收标准

### M1 · host half

* Pro 会话贴图不再被门禁拒绝；带图轮次由官方视觉模型直连产出结构化报告，主模型基于报告作答；
* 附件解析走官方 seam（无内部路径硬编码）；同一图片跨会话/跨轮次命中缓存，不重复读；
* 视觉模型缺失/上游失败时以工具错误返回（含具体原因，正文缺失时明确报「只输出了思考/无文本」），不悬挂、不把思考当报告；`npm run verify` 全绿，投影/门禁逻辑有单测；
* 所包装 seam 的可逆性与所适配 dsh 版本在 README/spec 中记录。

### M2 · 体验

* 视觉报告在面板可见；连续多图合并为一次读取；失败可一键重试；
* 纯文本轮次零开销（不触发任何 vision 调用）。

## 退役条件

官方在纯文本模型路由上原生支持「自动视觉路由/读图」后，本插件从合集中退役。
